# Лабораторная работа № 2 — анализ асимптотики

## Задача 1A. Минимальная очередь с приоритетом

`PriorityQueueCustom<T>` использует двоичную кучу в массиве. Для узла с индексом `i`
индексы потомков равны `2 * i + 1`, `2 * i + 2`, индекс родителя — `(i - 1) / 2`.
Высота кучи из `n` элементов составляет `O(log n)`.

| Операция | Время | Дополнительная память | Обоснование |
|---|---|---|---|
| `add` | `O(log n)` амортизированно | `O(1)` без расширения | Просеивание вверх по высоте кучи |
| `poll` | `O(log n)` | `O(1)` | Просеивание вниз после замены корня |
| `peek` | `O(1)` | `O(1)` | Обращение к корню массива |
| `size` | `O(1)` | `O(1)` | Чтение поля размера |
| `isEmpty` | `O(1)` | `O(1)` | Проверка поля размера |

При расширении массива одна операция `add` может потребовать `O(n)` времени
и `O(n)` временной дополнительной памяти для копирования.
За последовательность вставок удвоение ёмкости даёт амортизированную
стоимость вставки `O(log n)`. Постоянно выделенная память очереди — `O(n)`.

Пустая очередь: `peek` возвращает `null`, `poll` выбрасывает
`NoSuchElementException`. Вставка `null` не допускается.

## Задача 1B. Компаратор

`Comparator<T>` меняет только порядок сравнения элементов.
Асимптотика `add` и `poll` не меняется: `O(log n)` амортизированно
для `add` и `O(log n)` для `poll`; `peek` — `O(1)`.

## Задача 1C. Удаление по значению

`remove(T item)` проверяет до `n` элементов при линейном поиске: `O(n)`.
Замена найденного элемента последним занимает `O(1)`, восстановление
свойства кучи через `siftUp` или `siftDown` — `O(log n)`.
Итоговое время — `O(n)`, дополнительная память — `O(1)`.

## Задача 1D. Построение кучи из массива

Сначала массив из `n` элементов копируется за `O(n)`, затем выполняется
построение кучи методом Флойда: `siftDown` запускается от индекса
`n / 2 - 1` до корня. На высоте `h` имеется `O(n / 2^(h + 1))` узлов,
а стоимость просеивания одного узла — `O(h)`.
Суммарная стоимость равна `O(n * Σ(h / 2^h)) = O(n)`.
Дополнительная память для копии исходного массива — `O(n)`.

При последовательной вставке `n` элементов верхняя оценка времени — `O(n log n)`.

## Задача 2A. Хеш-таблица с линейным пробированием

В `HashMapCustom<K, V>` ожидаемое время `put`, `get`, `containsKey`, `remove` — `O(1)`
при равномерном распределении хешей и ограниченной загрузке таблицы.
При множестве коллизий худшее время каждой из этих операций — `O(n)`.

При увеличении ёмкости перехеширование всех элементов занимает `O(n)`.
Вставка с учётом редких расширений имеет амортизированное ожидаемое время `O(1)`
при указанных предположениях о хешировании. `size` и `capacity` — `O(1)`.
Общая память таблицы — `O(capacity)`.

Для отрицательного хеш-кода используется абсолютное значение перед
вычислением индекса; значение `Integer.MIN_VALUE` обрабатывается
без переполнения с помощью типа `long`.
