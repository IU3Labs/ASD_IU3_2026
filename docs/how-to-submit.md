# Инструкция по сдаче лабораторной работы

Эта инструкция описывает пошаговый процесс сдачи лабораторной работы через GitHub.

---

## Шаг 1. Fork основного репозитория

1. Откройте основной репозиторий курса (`ASD_IU3_2026`).
2. Нажмите кнопку **Fork** в правом верхнем углу.
3. В появившемся окне выберите свой аккаунт. Теперь у вас есть собственная копия репозитория.

---

## Шаг 2. Клонирование на компьютер

```bash
git clone <<ссылка на репозиторий>>
cd ASD_IU3_2026
```

---

## Шаг 3. Создание ветки

Создайте ветку по шаблону `labN-Фамилия-Группа`:

```bash
git checkout -b lab01-Ivanov-XX
```

Замените `01` на номер лабораторной, `Ivanov` — на вашу фамилию, `xx` — на группу.

---

## Шаг 4. Реализация решения

1. Перейдите в репозиторий.
2. Создайте свой модуль с наименованием `XX-Ivanov` (см пример)
3. Добавьте package для решения задачи ( ru.bmstu.lab1 )
4. Реализуйте решение в созданной папке.
5. Добавьте тесты в папку `test`.
6. Убедитесь, что код соответствует `style-guide.md`.

---

## Шаг 5. Коммиты

Делайте коммиты по мере готовности логических частей:

```bash
git add .
git commit -m "feat: implement array-based queue insert and remove"
```

---

## Шаг 6. Отправка изменений

```bash
git push origin lab01-Ivanov-31
```

---

## Шаг 7. Создание Pull Request (PR)

1. Зайдите в свой форк на GitHub.
2. Нажмите **Compare & pull request**.
3. Убедитесь, что:
   - **Base repository:** `ASD_IU3_2026` (основной репозиторий курса), ветка `main`.
   - **Head repository:** ваш форк, ваша ветка.
4. Заполните описание PR:

   ```
   ФИО: Иван Иванов
   Группа: XX
   Лабораторная: №1 — Массивы и списки

   Краткое описание:
   Реализован динамический массив на основе встроенного массива.
   Асимптотика: insert — O(1) амортизированно, removeAt — O(n).

   Добавленные тесты:
   - testInsertBeyondCapacity — проверка роста массива
   - testRemoveFromEmpty — граничный случай
   - testBulkInsertAndRemove — стресс-тест на 100 000 элементов
   ```

5. Нажмите **Create Pull Request**.

---

## Шаг 8. Ожидание проверки

Преподаватель проверит работу и оставит комментарии. Если потребуются правки — внесите их и обновите PR.

---

## Шаг 9. Завершение

Когда работа принята, преподаватель сделает merge в основной репозиторий. Статус PR изменится на **Merged**.
