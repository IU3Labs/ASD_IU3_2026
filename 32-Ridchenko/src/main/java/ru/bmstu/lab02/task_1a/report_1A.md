# Отчет

## Задача 1A. Базовая реализация PriorityQueueCustom

Реализовать очередь с приоритетом (min-heap) на динамическом массиве с операциями `add`, `poll`, `peek`, `size`, `isEmpty`.

### Идея решения

Куча хранится в массиве. Для узла с индексом `i`:
- левый ребенок: `2*i + 1`
- правый ребенок: `2*i + 2`
- родитель: `(i - 1) / 2`

При добавлении элемент кладется в конец массива и "всплывает" вверх (`siftUp`), пока не встанет на место.
При извлечении минимума корень заменяется последним элементом, после чего новый корень "проседает" вниз (`siftDown`).
Массив автоматически расширяется вдвое при заполнении.

### Асимптотика

- `add`: `O(log n)` — высота кучи.
- `poll`: `O(log n)` — высота кучи.
- `peek`: `O(1)` — корень всегда в `heap[0]`.
- `size`, `isEmpty`: `O(1)`.
- Доп. память: `O(n)` — сам массив.

### Проверки

- `add 5, add 3, add 8, poll` → `3`: минимум извлекается первым.
- `add 10, add 2, peek` → `2`: минимум без удаления.
- `poll` на пустой очереди → `NoSuchElementException`.
- `add` 100 элементов при начальной ёмкости 10 → массив расширяется, все элементы извлекаются в порядке возрастания.
- `add null` → `NullPointerException`.
