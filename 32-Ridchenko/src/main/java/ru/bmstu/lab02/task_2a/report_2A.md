# Отчет

## Задача 2A. HashMapCustom с линейным пробированием

Реализовать хеш-таблицу с линейным пробированием.

### Идея решения

Таблица хранится в массиве. Индекс вычисляется как `Math.abs(key.hashCode()) % capacity`.
Если ячейка занята другим ключом, мы идем вперед по массиву (`index + 1`, `index + 2` и т.д.) до первой свободной.
При удалении мы не можем просто оставить `null`, иначе цепочка поиска прервется, и элементы "за" удаленным потеряются. Поэтому используется маркер `DELETED`.
При достижении коэффициента загрузки 0.75 (отношение занятых ячеек к общему размеру) таблица расширяется вдвое, и все элементы перехешируются.

### Асимптотика

- `put`, `get`, `remove`, `containsKey`: в среднем **`O(1)`**, в худшем (при коллизиях) — `O(n)`.
- `size`, `capacity`: `O(1)`.
- Доп. память: `O(capacity)`.

### Проверки

- Вставка и поиск: `put("a", 1), get("a")` → `1`.
- Перезапись: `put("a", 1), put("a", 2)` → размер 1, значение `2`.
- Удаление: `remove("a")` → `true`, `get("a")` → `null`.
- Ресайз: вставка 100 элементов вызывает расширение массива.
- Маркер `DELETED`: после удаления ключа из середины цепочки поиск других ключей не ломается.
