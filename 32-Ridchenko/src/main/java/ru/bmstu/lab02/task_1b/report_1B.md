# Отчет

## Задача 1B. Min-heap и max-heap через компаратор

Реализовать очередь с приоритетом, которая может работать как min-heap и max-heap. Конструктор принимает `Comparator<T>`.

### Идея решения

Вместо жесткого вызова `compareTo` (как в 1A), мы используем `comparator.compare(a, b)`.
Если компаратор не передан — берем `Comparator.naturalOrder()` (работает как min-heap).
Если передан `Comparator.reverseOrder()` — куча становится max-heap.
Благодаря этому один и тот же код работает в обоих режимах. Для кастомных объектов можно передать свой компаратор.

### Асимптотика

Все операции аналогичны 1A:
- `add`: `O(log n)`
- `poll`: `O(log n)`
- `peek`: `O(1)`
- `size`, `isEmpty`: `O(1)`

Вызов компаратора добавляет лишь константное время `O(1)` на каждое сравнение, что не меняет общую асимптотику.

### Проверки

- Min-heap с `add 5, 1, 3` → извлекается `1, 3, 5`.
- Max-heap с `add 5, 1, 3` → извлекается `5, 3, 1`.
- Кастомный компаратор (сначала четные) → `add 3, 2, 1, 4` → извлекается `2, 4, 1, 3`.
- Добавление `null` → `NullPointerException`.
