# Бенчмарки ЛР2

Среднее арифметическое по 12 измерениям после 8 прогревочных запусков каждого сценария.
Среда — Linux x86-64, Intel Xeon Platinum 8573C, OpenJDK 25.0.1 (Zulu), JVM с флагами
`-Xms512m -Xmx512m`. Для каждого размера использовался один и тот же массив уникальных случайных
`Integer` для всех сравниваемых реализаций (`Random(33)`). Время генерации входа и проверки
контрольной суммы исключено. Каждый запуск создаёт новую структуру, а порядок запуска сценариев
циклически меняется между повторами.

## Сравнение со стандартными коллекциями

Для очереди выполняются N вставок, затем N извлечений. Для хеш-таблицы выполняются N вставок,
N успешных поисков и N удалений, отдельными последовательными проходами. В таблице указано время
полного сценария, включая создание структуры и расширения массивов.

| Структура | Операции | N элементов | Среднее время (мс) |
|---|---|---:|---:|
| `PriorityQueueCustom` | `add + poll` | 10 000 | 1,752 |
| `java.util.PriorityQueue` | `add + poll` | 10 000 | 1,773 |
| `HashMapCustom` | `put + get + remove` | 10 000 | 1,338 |
| `java.util.HashMap` | `put + get + remove` | 10 000 | 0,747 |
| `PriorityQueueCustom` | `add + poll` | 50 000 | 14,766 |
| `java.util.PriorityQueue` | `add + poll` | 50 000 | 12,805 |
| `HashMapCustom` | `put + get + remove` | 50 000 | 10,180 |
| `java.util.HashMap` | `put + get + remove` | 50 000 | 6,502 |
| `PriorityQueueCustom` | `add + poll` | 100 000 | 32,572 |
| `java.util.PriorityQueue` | `add + poll` | 100 000 | 33,001 |
| `HashMapCustom` | `put + get + remove` | 100 000 | 24,845 |
| `java.util.HashMap` | `put + get + remove` | 100 000 | 25,818 |

## Построение кучи из 100 000 элементов (1D)

Замеряется только создание кучи из подготовленных данных. При последовательной вставке в замер
входят расширения массива, а при построении снизу вверх — однократное копирование массива.

| Способ | Худшее время по асимптотике | Среднее время (мс) |
|---|---|---:|
| Последовательные `add()` | O(n log n) | 8,893 |
| Конструктор с просеиванием снизу вверх | O(n) | 2,302 |

Запуск из корня проекта после `mvn -pl 33-Shevtsov test` (в Windows разделитель путей в classpath — `;`):

```bash
java -Xms512m -Xmx512m -cp "33-Shevtsov/target/classes:33-Shevtsov/target/test-classes" ru.bmstu.lab02.Lab02Benchmark
```

## Вывод

Построение кучи снизу вверх в этом замере заняло в 3,9 раза меньше времени благодаря коротким просеиваниям
у большинства узлов и однократному выделению массива нужной ёмкости.
В циклах `add + poll` время обеих очередей сопоставимо, а хеш-таблица курса показала результат, близкий
к `HashMap` на 100 000 ключах, при этом на двух меньших наборах `HashMap` завершил цикл быстрее.
На время хеш-таблицы влияют длины цепочек пробирования и перехеширование при росте.
Обе очереди хранят ссылки в массиве и различаются правилами роста, а обе хеш-таблицы выделяют объекты записей,
при этом линейное пробирование хранит цепочки в самом массиве и сохраняет маркеры удаления в ячейках.
