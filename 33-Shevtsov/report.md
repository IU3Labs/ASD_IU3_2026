## Очередь с приоритетом (1A и 1D)

Очередь хранит двоичную min-кучу в динамическом массиве. Для каждого узла значение родителя не больше
значений детей, поэтому минимум лежит по индексу 0. Дети узла с индексом `i` находятся по индексам
`2*i + 1` и `2*i + 2`, родитель — по индексу `(i - 1) / 2`.

При вставке элемент помещается в конец массива и просеивается вверх. При извлечении минимум заменяется
последним элементом, который просеивается вниз через меньшего из детей. Освободившаяся ячейка очищается.
Из пустой очереди `poll()` бросает `NoSuchElementException`, а `peek()` возвращает `null`.
При вставке `null` бросается `NullPointerException`.

Конструктор копирует входной массив и обходит внутренние узлы от `n / 2 - 1` до 0. Когда начинается
просеивание узла, поддеревья его детей уже удовлетворяют свойству кучи. Каждый лист сразу является кучей
из одного элемента.

| Операция | Время | Пояснение |
|---|---|---|
| `add(item)` | Амортизированное O(log n), O(n) при расширении | Просеивание проходит до корня. Стоимость копирований при удвоении суммарно линейна по числу вставок |
| `poll()` | O(log n) | Просеивание проходит вниз по одной ветви |
| `peek()`, `size()`, `isEmpty()` | O(1) | Чтение корня или счётчика |
| Конструктор из массива | O(n) | Копирование и просеивание внутренних узлов снизу вверх |

В дереве из `n` элементов число узлов, которые могут опуститься хотя бы на `h` уровней, не превосходит
`floor(n / 2^h)`. Сумма таких оценок по всем `h ≥ 1` меньше `n`, значит суммарная стоимость просеиваний
равна O(n). Последовательная вставка имеет верхнюю оценку O(n log n), которая достигается на убывающих
входных данных. Очередь занимает O(C) памяти, где `C` — ёмкость массива. При извлечении ёмкость сохраняется,
поэтому она зависит от максимального размера очереди за время её работы.

## Хеш-таблица (2A)

Ключ получает стартовую позицию по формуле `abs(hashCode) % capacity`. Преобразование к `long` до взятия
модуля учитывает `Integer.MIN_VALUE`. При коллизии проверяются последовательные ячейки с переходом в начало
массива после последней позиции. Ключи сравниваются через `equals()`.

Удалённая ячейка помечается `DELETED`. Поиск идёт дальше маркера, потому что искомый ключ мог попасть в ту же
цепочку. Вставка запоминает первый маркер, но завершает поиск до пустой ячейки или совпадения ключей. Это
позволяет обновить существующий ключ без дублирования. Когда новая вставка превысит загрузку 0,75, таблица
удваивается и все живые пары перехешируются. Если живых пар не более 75%, но 7/8 ячеек заняты парами или
маркерами, вставка в пустую ячейку запускает перехеширование на прежней ёмкости. Есть хотя бы одна пустая
ячейка, завершающая поиск отсутствующего ключа. Ключ `null` отклоняется, значение `null` допустимо.

| Операция | Время при хорошем распределении хешей | Худший случай |
|---|---|---|
| `get(key)`, `containsKey(key)`, `remove(key)` | В среднем O(1) | O(C), обход длинной цепочки |
| `put(key, value)` | Амортизированное ожидаемое O(1) | O(C) без перехеширования, O(C + n²) с ним при одинаковых хешах |
| `size()`, `capacity()` | O(1) | O(1) |

Здесь `n` — число живых пар, `C` — ёмкость. Перехеширование перебирает старый массив за O(C) и повторно
размещает каждую пару. При хорошем распределении хешей это занимает O(C) в среднем. После очистки маркеров
занято не более 3/4 ячеек, поэтому перед следующей очисткой требуется занять ещё как минимум C/8 ячеек.
Память — O(C). При перехешировании временно существуют два массива ссылок, а сами записи переиспользуются.

## Примеры ручной проверки

| Вход или операции | Ожидаемый результат | Что проверяется |
|---|---|---|
| Добавить в очередь 7, 3, 3, −1. Четырежды вызвать `poll()` | −1, 3, 3, 7 | Порядок извлечения и дубликаты |
| Построить кучу из массива [9, 2, 5, 1], изменить исходный массив и опустошить очередь | 1, 2, 5, 9 | Построение снизу вверх и независимость копии |
| Вставить ключи 15, 31, 47 в таблицу ёмкости 16, удалить 15 | Ключи 31 и 47 находятся | Коллизия, переход через границу и поиск через `DELETED` |
| Вставить 12 разных ключей, обновить один из них и добавить 13-й ключ | После обновления ёмкость 16, после вставки 32. Все значения доступны | Порог загрузки и сохранность данных при росте |

Автоматические тесты проверяют также пустые структуры, одиночный элемент, повторную вставку и серии
операций в сравнении со стандартными коллекциями. Все 26 тестов прошли. JaCoCo показал 100% покрытия
строк и ветвей в обеих структурах. Методика и результаты измерений приведены
в [benchmarks.md](benchmarks.md).
