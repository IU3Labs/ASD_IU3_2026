# Лабораторная работа №2. Структуры данных

Александр Симонов, ИУ3-33Б (`IU3-33B`). Задачи 1A, 1B и 2A, всего 7 баллов.

## Очередь с приоритетом

Куча хранится в массиве. Для узла `i` дочерние элементы находятся по индексам `2*i + 1` и `2*i + 2`,
а родитель — по индексу `(i - 1) / 2`. Новый элемент добавляется в конец и просеивается вверх.
При извлечении последний элемент встаёт на место корня и просеивается вниз.
Без компаратора используется естественный порядок, обратный компаратор превращает очередь в max-heap.

| Операция | Время |
|---|---|
| `add` | O(log n) амортизированно, O(n) при расширении массива |
| `poll` | O(log n) |
| `peek`, `size`, `isEmpty` | O(1) |

Массив удваивается при заполнении. Память пропорциональна ёмкости массива, которая зависит от
максимального размера очереди. Для пустой очереди `poll` бросает `NoSuchElementException`,
а `peek` возвращает `null`. Элементы `null` не допускаются.

Ручная проверка: добавить `4, 1, 4, -2`. При естественном порядке извлекаются `-2, 1, 4, 4`,
при обратном — `4, 4, 1, -2`. Дубликат проверяет, что одинаковые приоритеты не приводят к потере элементов.

## Хеш-таблица

Хранятся два массива одинаковой длины, для ключей и для значений. При коллизии поиск идёт
к следующей ячейке, а с конца массива возвращается к началу. `DELETED` сохраняет цепочку поиска.
Вставка запоминает первую удалённую ячейку, но продолжает искать такой же ключ до свободной ячейки.
Так обновление существующего ключа не создаёт дубликат.

Ёмкость удваивается, когда новая запись превысила бы загрузку 75%. Если метки удаления довели
число занятых и удалённых ячеек до 7/8 ёмкости, перед записью в свободную ячейку таблица очищает
метки перехешированием без увеличения ёмкости. Для вычисления модуля хеш сначала расширяется
до `long`, чтобы корректно обработать `Integer.MIN_VALUE`. Поддерживаются ключ и значения `null`.
В отличие от `get`, `containsKey` отличает отсутствующий ключ от ключа со значением `null`.

| Операция | Время |
|---|---|
| `get`, `containsKey`, `remove` | O(1) в среднем при хорошем распределении хешей, O(C) в худшем случае |
| `put` | O(1) в среднем амортизированно при хорошем распределении хешей, O(C) без перехеширования в худшем случае |
| `size`, `capacity` | O(1) |

Здесь C — ёмкость таблицы, n — число записей. При перехешировании ожидается O(C) времени.
Если все ключи попадают в одну цепочку, перехеширование может потребовать O(C + n²).
Таблица занимает O(C) памяти.

Ручная проверка: при ёмкости 16 вставить ключи `15` и `31`, затем удалить `15`.
Ключ `31` должен остаться доступным. Эта последовательность проверяет проход через конец массива
и через удалённую ячейку.
