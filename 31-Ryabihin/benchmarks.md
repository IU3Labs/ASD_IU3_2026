# Бенчмарки хеш-таблиц

Замеры выполнены на Intel Core i5-12600K под Windows 11 с Eclipse Temurin 25.0.4.1. Для каждого случая было три прогревочных запуска и пять измерительных. Таблицы показывают среднее время на всю указанную серию операций. Данные и запросы созданы заранее с фиксированным зерном генератора. Время вставки включает выделение записей и рост таблицы.

Запуск из корня репозитория в PowerShell

```powershell
mvn -f 31-Ryabihin/pom.xml test-compile
$classes = '31-Ryabihin/target/test-classes;31-Ryabihin/target/classes'
java -Xms256m -Xmx512m -cp $classes ru.bmstu.lab2.task_2.HashMapBenchmark
```

## Одинаковые хеши (2C)

Линейный вариант с порогом 0.75 сравнивался на одном наборе из 10 000 строк. Во второй серии те же строки обёрнуты в `CollisionKey`. После вставки каждая серия ищет все сохранённые ключи.

## Порог загрузки (2D)

Для линейного варианта выполнено по 100 000 вставок и 50 000 поисков. Ёмкость — число ячеек массива после вставок.

| Порог | Ёмкость | Время вставок, мс | Время поисков, мс | На вставку, нс | На поиск, нс |
|---|---:|---:|---:|---:|---:|
| 0,50 | 262 144 | 6,740 | 2,151 | 67,40 | 43,02 |
| 0,75 | 262 144 | 9,349 | 1,748 | 93,49 | 34,96 |
| 0,90 | 131 072 | 8,099 | 3,204 | 80,99 | 64,08 |

При пороге 0,90 потребовалось вдвое меньше ячеек, а поиск занял больше времени, чем при 0,50. Одинаковые хеши увеличили время обеих операций из-за длинной общей цепочки пробирования. Квадратичное пробирование сократило среднее число проверок на 5 %, а на этих наборах `java.util.HashMap` быстрее выполнила поиск при всех трёх размерах.
