# Расчёт асимптотической сложности

Сложность показывает, как растёт число действий при увеличении входных данных.
O(1) — постоянное число действий, O(n) — число действий растёт пропорционально размеру входа,
O(n²) — примерно пропорционально квадрату размера входа.
O(log n) означает медленный рост: при удвоении размера кучи её высота увеличивается примерно на один уровень.

Обозначения: n — число элементов, m — ёмкость хеш-таблицы, u — число уникальных элементов.
Для Top-K используется q = min(k, n): нельзя выбрать больше элементов, чем есть во входе.

Сравнение элементов, equals и hashCode считаем операциями O(1).
Для длинной строки отдельное сравнение или первое вычисление хеша может требовать O(L), где L — длина строки.

## 1A, 1B — очередь с приоритетом

Элементы лежат в массиве, который представляет двоичную кучу.
При добавлении элемент поднимается к корню, при извлечении вершины — просеивается вниз.
Оба пути проходят не больше O(log n) уровней.

| Операция | Время | Объяснение |
|---|---|---|
| `add` без расширения | O(log n) | Подъём по одной ветви к корню |
| `add` с расширением | O(n) | Сначала копируется массив, затем выполняется подъём |
| `add` амортизированно | O(log n) | Копирование требуется редко, потому что массив удваивается |
| `poll` | O(log n) | Последний элемент переносится в корень и просеивается вниз |
| `peek`, `size`, `isEmpty` | O(1) | Читается вершина или поле размера |

«Амортизированно» означает оценку одной операции с учётом затрат на длинную последовательность операций.
При росте массива суммарно копируется 16 + 32 + ... элементов — меньше 2n.
Поэтому редкие копирования добавляют O(1) на вставку в среднем по последовательности,
а вместе с просеиванием получается O(log n). Именно в этом смысле выполнено требование к add.

Память — O(n). В min-heap первым извлекается минимум, в max-heap — максимум.
Меняется порядок сравнения, но число уровней и оценка сложности остаются прежними.

## 2A, 2C — хеш-таблица

Хеш определяет начальную ячейку. Если она занята другим ключом, проверяются следующие ячейки по кругу.
Такое последовательное движение называется линейным пробированием.

При хорошем распределении хешей и коротких цепочках поиск обычно проверяет мало ячеек:
get, containsKey и remove имеют ожидаемую сложность O(1).
Вставка put также занимает O(1) ожидаемо и амортизированно: расширения происходят редко.
При обычном распределении перенос записей в увеличенную вдвое таблицу требует O(m).

| Операция | Худшее время | Объяснение |
|---|---|---|
| `get`, `containsKey`, `remove` | O(m) | Может потребоваться проверка всех m ячеек |
| `put` без расширения | O(m) | Поиск ключа и свободной или удалённой ячейки |
| `put` с расширением при коллизиях | O(m²) | Каждая переносимая запись снова проходит длинную цепочку |
| `size`, `capacity` | O(1) | Чтение сохранённых полей |

Память — O(m). Во время расширения одновременно существуют старые и новые массивы,
но их суммарный размер остаётся пропорциональным m.
После удаления записей таблица не уменьшается, поэтому ёмкость может быть намного больше числа живых записей.
Маркеры DELETED сохраняют путь поиска. Если таких маркеров много, поиск может замедлиться даже при малой загрузке;
поэтому ожидаемое O(1) не обещается для любой истории вставок и удалений.

У всех CollisionKey одинаковый хеш. При вставке очередного ключа приходится проходить всё более длинную цепочку.
Сумма проверок 1 + 2 + ... + n даёт O(n²) для вставки всех n ключей, включая расширения.
Поиск и удаление всех таких ключей также занимают O(n²), отдельный поиск — до O(n).

## 3A — Top-K

Храним в min-heap не более q наибольших элементов, найденных к текущему моменту.
Для каждого нового значения сравниваем его с минимумом кучи и при необходимости заменяем этот минимум.
Одна такая замена занимает O(log(q + 1)), просмотр всех n значений — O(n log(q + 1)).
В конце извлекаем q результатов по возрастанию за O(q log(q + 1)).

Итого: **O(n log(q + 1)) времени и O(q) дополнительной памяти**, включая результат.
При 2 <= k <= n это требуемое O(n log k); при k = 1 время O(n), при k = 0 — O(1).
При k > n возвращаются все n значений, массив длины k не создаётся.

## 3C — уникальные элементы

Проходим вход один раз. Через containsKey проверяем, встречался ли элемент раньше.
Новый элемент добавляем в таблицу и в конец списка результатов.

При обычном распределении хешей время — **O(n) ожидаемо**, память — **O(u)**.
При одинаковых хешах длинные цепочки могут увеличить общее время до O(n²), включая расширения.
Так как мы добавляем элементы в результат при первом появлении, исходный порядок сохраняется.

## Вспомогательный ArrayListCustom

`get`, `size` и `isEmpty` — O(1). Добавление в конец — O(1) амортизированно,
но O(n) в отдельный момент расширения массива. Память — O(n).
Итератор и представление диапазона subList создаются за O(1); шаг итератора занимает O(1).
Поиск, сравнение списков, вычисление хеша и копирование в массив — O(n).
Проверка containsAll для c элементов требует O(n * c).
Изменение по индексу, удаление и пакетные изменения не поддерживаются: интерфейс List допускает такой выбор.
