# Бенчмарки ЛР2

Дата: 2026-11-22.

Среда: OpenJDK 64-Bit Server VM 25.0.4.1; Windows 11 amd64; CPU: Intel64 Family 6 Model 151 Stepping 2, GenuineIntel.

Первые 3 запуска нужны для прогрева: Java успевает подготовить код, а их время не учитывается. Затем выполняются 5 запусков и вычисляется среднее время всего пакета операций. Для времени используется System.nanoTime().

Обе реализации получают одинаковые входные данные. Начальное значение генератора случайных чисел (seed = 2026) фиксировано, чтобы повторять тот же набор. Подготовка входа и проверка ответов не входят в замер; создание исследуемых структур входит. Результаты сохраняются, чтобы Java не исключила вычисления как ненужные.

Условия запуска: один процесс, без JaCoCo, -Xms512m -Xmx512m (начальный и максимальный размер памяти Java — 512 МиБ). Время может меняться из-за оптимизации кода Java, освобождения памяти и других работающих программ.

## 1B — min-heap и max-heap

Один и тот же набор и явный компаратор в обоих режимах.

| Структура | Операция | N элементов | Среднее время (мс) | Примечание |
|---|---|---:|---:|---|
| PriorityQueueCustom | add + poll | 100000 | 52.167 | min: naturalOrder; выделено 1048790 байт |
| PriorityQueueCustom | add + poll | 100000 | 55.464 | max: reverseOrder; выделено 1048784 байт |

В одном режиме первым извлекается минимум, в другом — максимум. В обоих случаях выполняются просеивания по куче, поэтому сложность одинакова. Число сравнений и обменов может различаться; на время также влияют оптимизация кода Java и освобождение памяти.

## 3C — уникальные элементы: время и память

В столбце «выделено» указано, сколько байтов программа выделила за один запуск, в среднем по пяти запускам. Счётчик ThreadMXBean учитывает выделения текущего потока, включая временную таблицу и новые массивы при расширении. Подготовленный заранее вход не учитывается. Это расход памяти за запуск, а не объём, занятый результатом после удаления временных объектов. u — число уникальных элементов; n/a означает недоступность счётчика. LinkedHashSet показан отдельно и вместе с преобразованием в List, чтобы сравнить также получение результата того же типа.

| LinkedHashSet | new LinkedHashSet<>(items) | 10000 | 0.439 | u = 4298; выделено 237584 байт |

## Выводы

Min-heap и max-heap имеют одинаковую сложность O(n log n), а разница во времени зависит от сравнений элементов и работы Java. В этих замерах собственная хеш-таблица медленнее стандартной из-за длинных цепочек проверок; при одинаковом хеше обработка всех n ключей требует O(n²) действий. Свои структуры в этих замерах выделили меньше памяти, чем стандартные аналоги, хотя часть памяти массивов занимают свободные ячейки и копии при расширении. Измеренная память включает все выделения за один запуск, в том числе временные объекты, поэтому это не размер готового результата.
