# ЛР2. Бенчмарки

Замеры: Linux x86_64, OpenJDK 21.0.13, JVM с `-Xms512m -Xmx512m`.
Каждое время — среднее арифметическое 11 запусков после 5 прогревочных, по `System.nanoTime()`.
Входы подготовлены заранее; фиксированный seed 33 используется для воспроизведения.
Для очереди измерены создание, N добавлений и N извлечений; для таблиц — создание, N вставок и 50 000 поисков,
с общим для сравниваемых вариантов набором запросов: половина берётся из вставленных ключей, половина случайна.
Размер в колонке N — число вставляемых элементов. Замеры времени включают рост массивов, если он происходит.
Это локальный эксперимент, а не оценка гарантированного времени операции.

## Запуск и вывод

Из директории модуля: `mvn test-compile`, затем запустить main классов `PriorityQueueBenchmark` и `LabBenchmark` в IntelliJ. Для сравнения с приведёнными замерами задайте в Run Configuration опции JVM `-Xms512m -Xmx512m`.

На 100 000 элементах стандартная очередь быстрее нашей в данном запуске; варианты min и max используют одну схему и показали близкое время. Построение снизу вверх дало меньшее время и использовало массив без запаса, в отличие от последовательных добавлений с удвоением ёмкости. Для таблицы порог 0,5 дал больший массив и более быстрый поиск в этом наборе, но дополнительный рост массива увеличил затраты на вставку. При одном хеше оба пробирования проходят длинную последовательность занятых ячеек; в 3C своя версия выделила меньше байтов, но работала медленнее LinkedHashSet на этом наборе.
