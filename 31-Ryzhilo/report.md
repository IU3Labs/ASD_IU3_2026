## Бинарная куча

Массив хранит полное бинарное дерево без отдельных объектов для узлов. Компаратор
задаёт порядок, поэтому один алгоритм поддерживает min-heap и max-heap. При удалении
освободившуюся позицию занимает последний элемент. Сравнение с родителем определяет
направление просеивания.

| Операция | Время | Дополнительная память |
|---|---|---|
| `add` | `O(log n)` амортизированно, `O(n)` при расширении | `O(1)`, при расширении `O(n)` |
| `poll` | `O(log n)` | `O(1)` |
| `peek`, `size`, `isEmpty` | `O(1)` | `O(1)` |
| `remove` | `O(n)` на поиск и до `O(log n)` на восстановление | `O(1)` |
| Конструктор из массива | `O(n)` | `O(n)` на копию |

При построении снизу вверх листья уже удовлетворяют свойству кучи. Число узлов
высоты не менее `h` ограничено `n / 2^h`, поэтому сумма высот внутренних узлов
линейна. Куча хранит память пропорционально максимальному достигнутому размеру.

## Хеш-таблица

Ключи и значения лежат в двух массивах. Линейный режим добавляет к исходному индексу
`i`, квадратичный — `i + 2i²`. Ёмкость равна степени двойки. Разность смещений
для шагов `i` и `j` равна `(i − j)(1 + 2(i + j))`. Второй множитель нечётный,
поэтому совпадение смещений по модулю ёмкости возможно только для одного и того же
шага в пределах полного обхода.

Маркер `DELETED` сохраняет цепочку поиска. Вставка запоминает первый маркер и
продолжает поиск, чтобы обновление существующего ключа не создало дубликат.
При превышении порога по живым записям таблица удваивается. Если занятые слоты
вместе с маркерами превышают порог `(1 + loadThreshold) / 2`, таблица очищает
маркеры перехешированием при прежней ёмкости. Зазор между порогами позволяет
накопить удалённые позиции перед очисткой.

При ёмкости `c`, `get`, `containsKey` и `remove` занимают ожидаемое `O(1)`
при равномерных хешах и `O(c)` в худшем случае. `put` занимает ожидаемое
амортизированное `O(1)`. Перехеширование стоит ожидаемое `O(c)`, в худшем
случае `O(c²)` из-за накопленных коллизий. `size` и `capacity` занимают
`O(1)`. Таблица хранит `O(c)` ссылок и использует `O(c)` дополнительной памяти
при перехешировании.

## Прикладные задачи

| Алгоритм | Идея | Время и память |
|---|---|---|
| Top-K | Min-heap удерживает только лучшие элементы. | `O(n log(k + 1))` по времени, `O(k)` по памяти. Здесь `k` ограничен размером входа. |
| Частоты слов | Текст приводится к нижнему регистру, слова выделяются по категориям Unicode и подсчитываются в своей таблице. | Ожидаемое `O(L)` по времени для `L` символов, `O(L)` памяти с учётом строки и ключей. |
| Уникальные элементы | Своя таблица запоминает встреченные значения, массив сохраняет порядок появления. | Ожидаемое `O(n)` по времени, `O(n)` по памяти. |
| Скользящий минимум | Куча хранит индексы, вышедшие из окна индексы удаляются при достижении корня. | `O(n log(n + 1))` по времени, `O(n)` по памяти в худшем случае. |

Представления результатов реализуют интерфейсы `List` и `Map`. Данные хранятся
в массивах или собственной таблице. Абстрактные классы JDK предоставляют только
реализации стандартных методов интерфейсов.

## Ручные проверки

- Удаление `8` из кучи, заполненной в порядке `1, 5, 2, 8, 6, 3, 4`, даёт последовательность
  извлечения `1, 2, 3, 4, 5, 6`. Этот пример проверяет просеивание вверх после произвольного удаления.
- При начальной ёмкости 16 ключи `0` и `16` имеют один начальный индекс. После удаления
  `0` поиск `16` должен находить значение за маркером.
- Для `[2, 1, 2]` при `k = 2` результат Top-K равен `[2, 2]`. Равные значения учитываются
  независимо.
- Текст `«Мир, мир!»` даёт `{мир=2}`. Пример проверяет регистр и пунктуацию.
- Для `[8, null, 1, 8, null]` результат `distinct` равен `[8, null, 1]`. Порядок первого
  появления сохраняется, повторный `null` пропускается.
- Для `[4, 2, 2, 5, 1, 3]` и окна 3 минимумы равны `[2, 2, 1, 1]`. Равные минимумы
  имеют разные индексы и истекают в разных окнах.
