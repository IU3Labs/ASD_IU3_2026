# Лабораторная работа № 2. Структуры данных

ФИО: Рыжило К.А.
Группа: ИУ3-31
Лабораторная: №2 — структуры данных

## Краткое описание

В работе реализованы базовые структуры данных без использования соответствующих
классов стандартной библиотеки. Собственные реализации проверены тестами JUnit 5,
сравнены с реализациями Java и дополнены замерами времени и выделенной памяти.

## Реализованные задачи

| Задача | Решение | Основные операции и асимптотика |
|---|---|---|
| 1A | `task01a/PriorityQueueCustom` | `add` — `O(log n)`, `poll` — `O(log n)`, `peek`, `size`, `isEmpty` — `O(1)` |
| 1B | `task01b/ComparatorPriorityQueue` | min-heap и max-heap через `Comparator` |
| 1C | `task01c/RemovablePriorityQueue` | удаление по значению — `O(n)` на поиск и до `O(log n)` на восстановление |
| 1D | `task01d/BulkPriorityQueue` | построение кучи из массива — `O(n)` |
| 2A | `task02a/HashMapCustom` | линейное пробирование, ожидаемые `O(1)` для `put`, `get`, `containsKey`, `remove` |
| 2B | `task02b/QuadraticHashMap` | квадратичное пробирование и подсчёт числа проб |
| 2C | `task02c/CollisionKey` | постоянный хеш для эксперимента с 10 000 коллизий |
| 2D | `task02d/LoadThresholdHashMap` | настраиваемый порог загрузки и автоматическое расширение |
| 3A | `task03a/Task03A` | `topK` за `O(n log k)` и `O(k)` памяти |
| 3B | `task03b/Task03B` | подсчёт частот слов ожидаемо за `O(L)` для текста длины `L` |
| 3C | `task03c/Task03C` | уникальные элементы в исходном порядке, ожидаемо `O(n)` |
| 3D | `task03d/Task03D` | скользящий минимум за `O(n log n)` и `O(n)` памяти |

Каждая задача находится в отдельной папке `src/main/java/ru/bmstu/lab02/taskXX`.
Одноимённый тест находится в соответствующей папке `src/test/java/ru/bmstu/lab02`.

## Искусственные коллизии

`CollisionKey` возвращает одинаковый `hashCode` для всех экземпляров, но сравнивает
ключи по исходной строке. Поэтому при одинаковом начальном индексе таблица вынуждена
проверять следующие позиции. При `n` разных ключах число проверок может вырасти до
`O(n²)`. Маркер `DELETED` позволяет продолжать поиск через удалённые ячейки и не
разрывать цепочку пробирования.

## Тестирование и бенчмарки

Из корня репозитория с JDK 21 или новее и Maven:

```bash
mvn clean test
```

Выполняются 44 теста JUnit 5. Отчёт покрытия JaCoCo сохраняется в
`31-Ryzhilo/target/site/jacoco/index.html`. Checkstyle запускается на фазе
`validate` и проверяет форматирование, длину строк, импорты и документацию.

Для повторного запуска бенчмарка:

```bash
mvn -pl 31-Ryzhilo test-compile
java -Xms512m -Xmx512m -Dstdout.encoding=UTF-8 \
  -cp "31-Ryzhilo/target/classes;31-Ryzhilo/target/test-classes" \
  ru.bmstu.lab02.Lab02Benchmark
```

Подробные результаты замеров находятся в [benchmarks.md](benchmarks.md), расчёт
асимптотики и ручные проверки — в [report.md](report.md).
