# Лабораторная работа № 2. Структуры данных

Ryzhilo, группа 31. Выполнены задачи 1A–1D, 2A–2D и 3A–3D из условия ЛР2.

- 1A–1D: бинарная куча на динамическом массиве, прямой и обратный порядок, удаление по значению и линейное построение.
- 2A–2D: хеш-таблица с открытой адресацией, два вида пробирования, эксперимент с коллизиями и сравнение порогов загрузки.
- 3A–3D: Top-K, частоты слов, уникальные элементы в исходном порядке и скользящий минимум.

## Структура проекта

Папка `31-Ryzhilo` следует шаблону `XX-Ivanov` из инструкции архива.
Число 31 в начале имени обозначает группу. Корневой Maven-проект подключает
этот модуль. Пакет `ru.bmstu.lab02` находится в стандартной структуре Maven.

```text
31-Ryzhilo/
├── pom.xml
└── src/
    ├── main/java/ru/bmstu/lab02/
    └── test/java/ru/bmstu/lab02/
```

## Сборка и проверка

Из корня репозитория с JDK 25 и Maven:

```text
mvn clean test
```

JUnit 5 запускает тесты, JaCoCo сохраняет отчёт в `31-Ryzhilo/target/site/jacoco/index.html`.

## Искусственные коллизии

У всех экземпляров `CollisionKey` одинаковый хеш, хотя равенство определяется исходной строкой.
Поэтому ключи при вставке и поиске начинают с одного индекса и идут по одной последовательности проб.
Вставка `i`-го уникального ключа проверяет уже занятые позиции, а поиск и удаление
продолжаются через маркеры удалённых ячеек. При `n` таких ключах серия операций требует
`Θ(n²)` проб. Квадратичное пробирование разрежает последовательность позиций,
но не разделяет ключи, у которых совпал начальный индекс.

Тест прогоняет вставку, поиск и удаление 10 000 ключей в обоих режимах.
В [benchmarks.md](benchmarks.md) приведён замер для тех же строк с обычным и постоянным хешем.
Асимптотика и примеры ручной проверки приведены в [report.md](report.md).
