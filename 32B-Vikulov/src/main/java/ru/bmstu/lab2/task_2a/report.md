# Задача 2A. Хеш-таблица с линейным пробированием

**Студент:** Викулов Петр, ИУ3-32Б · **ЛР 2** · **Баллы:** 3 ·
**Решение:** [`HashMapCustom.java`](HashMapCustom.java) ·
**Тесты:** [`HashMapCustomTest.java`](../../../../../../test/java/ru/bmstu/lab2/task_2a/HashMapCustomTest.java)

## Условие

Реализовать `HashMapCustom<K, V>` с линейным пробированием: `put`, `get`, `containsKey`, `remove`, `size`,
`capacity`. Хеш-функция `Math.abs(key.hashCode()) % capacity`. Коэффициент загрузки не более 0.75, при
превышении — удвоение ёмкости с перехешированием. Для удалённых ячеек — маркер `DELETED`.

## Устройство

Открытая адресация: все пары лежат прямо в массивах, без списков и узлов.

```
keys:   [ null | "b" | DELETED | "a" | "c" | null | ... ]
values: [ null |  2  |  null   |  1  |  3  | null | ... ]
```

- `keys[i]` и `values[i]` — параллельные массивы: ключ и его значение лежат под одним индексом.
- Ячейка ключа бывает **пустой** (`null`, в неё никогда ничего не клали), **удалённой** (`DELETED`) или
  **занятой**.
- **Поиск ключа** ([`findIndex`](HashMapCustom.java#L176-L190)): начинаем с домашней ячейки
  `|hashCode % capacity|` и идём вправо по кругу (`index + 1`), пока не найдём ключ или не упрёмся
  в пустую ячейку. Пустая ячейка означает «ключа нет»: при вставке он лёг бы не дальше неё.
- **Вставка** ([`put`](HashMapCustom.java#L71-L80)): если ключ есть — обновляем значение; если нет — кладём
  в первую пустую **или удалённую** ячейку цепочки ([`insertAbsent`](HashMapCustom.java#L193-L204)).
- **Удаление** ([`remove`](HashMapCustom.java#L112-L122)) ставит маркер `DELETED`, а не `null`.

### Зачем маркер `DELETED`

Ключи `a`, `b`, `c` с одинаковой домашней ячейкой 3 лежат цепочкой в ячейках 3, 4, 5. Если при удалении `b`
записать в ячейку 4 `null`, поиск `c` начнётся с 3, дойдёт до пустой 4 и остановится — `c` «потеряется».
`DELETED` говорит поиску «здесь было занято, иди дальше», а вставке — «сюда можно положить новый ключ».
Это проверяет тест `shouldFindKeyAfterRemovingEarlierKeyInSameProbeChain`.

### Загрузка и ресайз

Поле `size` хранит число живых элементов, `occupied` — число живых элементов и маркеров `DELETED`.
Перед вставкой нового ключа [проверяются два порога](HashMapCustom.java#L210-L216).

- При `size + 1 > 0.75 · capacity` ёмкость удваивается.
- При `occupied + 1 > 0.875 · capacity` таблица перестраивается в той же ёмкости, если для живых элементов
  места достаточно. При перестройке маркеры исчезают.

Маркеры удлиняют цепочки пробирования. Отдельный порог оставляет пустые ячейки для завершения поиска
и позволяет обработать серию замен ключей без полной перестройки на каждой вставке.
Тест `shouldNotGrowForeverUnderInsertRemoveChurn` проверяет стабильность ёмкости после 100 000 вставок и удалений.

### Хеш-функция и `Integer.MIN_VALUE`

[`indexFor`](HashMapCustom.java#L171-L173) считает `Math.abs(key.hashCode() % capacity)` — модуль берётся
**после** остатка, а не до, как в формуле из условия. Причина: `Math.abs(Integer.MIN_VALUE)` в Java равен
`Integer.MIN_VALUE` (модуль `2³¹` не помещается в `int`), и индекс получился бы отрицательным. Остаток же по
модулю всегда меньше ёмкости, так что его модуль безопасен. Для всех остальных хешей результат совпадает с
формулой из условия. Проверяет тест `shouldHandleNegativeAndMinValueHashCodes`.

### Прочие решения

- **`null`-ключ запрещён** (`NullPointerException`): у `null` нет `hashCode()`, а `null` в массиве ключей уже
  означает «пустая ячейка».
- **`null`-значение разрешено**; отличить его от отсутствующего ключа можно через `containsKey`.
- `forEach` обходит пары в порядке ячеек — он нужен для просмотра частот в задаче 3B.

## Асимптотика

`n` — число живых элементов, `m` — ёмкость.

| Операция | Среднее время | Худший случай |
|---|---|---|
| `get`, `containsKey`, `remove` | O(1) | O(m) |
| `put` | O(1) амортизированно | O(m + n²) при перестройке |
| `size`, `isEmpty`, `capacity` | O(1) | O(1) |
| `forEach` | O(m) | O(m) |
| `rehash` | O(m) | O(m + n²) |

При равномерном хешировании число проб в среднем ограничено константой при фиксированной доле занятых
ячеек. При большом числе коллизий поиск проходит кластер целиком. Перестройка сканирует старый массив
и заново вставляет живые ключи. Если все ключи имеют одинаковый хеш, повторные вставки требуют
в сумме O(n²) проб.

После удвоения загрузка близка к 0,375. Порог 0,75 достигается после порядка m новых вставок.
При очистке маркеров остаётся не более 0,75m занятых ячеек, до следующей очистки потребуется порядка m
новых занятых ячеек. Это даёт O(1) средней амортизированной стоимости вставки.
Два массива занимают O(m) памяти. При удалениях ёмкость сохраняется.

## Тесты

| Тест | Что проверяет |
|------|---------------|
| `shouldReturnNullAndZeroSizeWhenMapIsEmpty` | пустая таблица: `get` → `null`, размер 0, ёмкость по умолчанию |
| `shouldStoreAndReturnValues` | базовые `put` / `get` / `containsKey` |
| `shouldUpdateValueWithoutChangingSizeWhenKeyExists` | повторный `put` обновляет значение, а не добавляет второй ключ |
| `shouldRemoveExistingKeyAndReportMissingKey` | `remove` возвращает `true`, повторный — `false` |
| `shouldFindKeyAfterRemovingEarlierKeyInSameProbeChain` | **маркер `DELETED`**: ключ за удалённым в цепочке находится |
| `shouldReuseDeletedCellOnInsert` | вставка переиспользует ячейку `DELETED` |
| `shouldDoubleCapacityWhenLoadFactorExceeded` | удвоение ёмкости ровно на пороге 0.75, данные не теряются |
| `shouldKeepLoadFactorBelowLimitForManyKeys` | 10 000 вставок с ёмкости 1: загрузка всегда ≤ 0.75 |
| `shouldHandleNegativeAndMinValueHashCodes` | отрицательный хеш и `Integer.MIN_VALUE` |
| `shouldNotGrowForeverUnderInsertRemoveChurn` | 100 000 пар вставка/удаление: маркеры вычищаются, ёмкость не растёт |
| `shouldStoreNullValueAndDistinguishItFromMissingKey` | `null`-значение отличается от отсутствующего ключа |
| `shouldVisitEveryLiveEntryInForEach` | `forEach` обходит живые пары и пропускает удалённые |
| `shouldRejectNullKeyAndNonPositiveCapacity` | `null`-ключ и ёмкость 0 отклоняются |
| `shouldMatchJavaHashMapOnRandomOperations` | 50 000 случайных `put` / `get` / `remove` — сверка с `java.util.HashMap` |
