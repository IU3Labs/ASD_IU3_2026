## Условие

Реализовать `List<T> distinct(List<T> items)` — уникальные элементы в порядке первого вхождения, используя
собственную хеш-таблицу. Сравнить по времени и памяти с `new LinkedHashSet<>(items)`.

## Идея

```java
28:        HashMapCustom<T, Boolean> seen = new HashMapCustom<>();
...
32:        for (T item : items) {
...
38:            } else if (!seen.containsKey(item)) {
39:                seen.put(item, Boolean.TRUE);
40:                result.add(item);
41:            }
```

Таблица [`HashMapCustom`](../task_2a/HashMapCustom.java) из задачи 2A используется как **множество**
«уже встречались»: ключ — элемент, значение — просто `Boolean.TRUE` (один общий объект, лишней памяти не
занимает). Элемент попадает в результат только при первой встрече.

**Порядок первого вхождения** обеспечивает список `result`, а не таблица: порядок обхода ячеек хеш-таблицы
произвольный. `LinkedHashSet` решает ту же задачу иначе — связывает свои узлы в двусвязный список.

**`null` в списке.** Наша таблица не принимает `null`-ключи (см. отчёт 2A), а в списке `null` встречаться
может. Поэтому факт встречи `null` хранится в отдельном флаге `seenNull` (строки 30, 33–37): первый `null`
попадает в результат, остальные — нет. Это поведение совпадает с `LinkedHashSet`.

Исходный список не меняется, результат — новый `ArrayList`.

## Асимптотика

| Строки | Стоимость | Раз | Вклад |
|--------|-----------|-----|-------|
| [32](Distinct.java#L32) — цикл | O(1) | n | O(n) |
| [38](Distinct.java#L38) — `containsKey` | O(1) в среднем | n | O(n) |
| [39–40](Distinct.java#L39-L40) — `put` и `add` | O(1) амортизированно в среднем | u | O(u) |

**Время:** O(n) в среднем, где n — длина списка, u ≤ n — число уникальных элементов. В худшем случае (все
хеши совпадают) каждая проверка в таблице — O(u), итого O(n·u).

**Память:** таблица на u ключей (ёмкость < u / 0.375) и список из u ссылок — O(u).

## Сравнение с `LinkedHashSet`

Полная таблица и методика — в [`benchmarks.md`](../../../../../../../lab2/benchmarks.md). Кратко:

- **Память: `Distinct` примерно в 2–5 раз экономнее.** У `LinkedHashSet` на каждый уникальный элемент
  создаётся объект-узел (`LinkedHashMap.Entry`: ссылки на ключ, значение, следующий узел цепочки,
  предыдущий и следующий в порядке вставки, хеш) — около 40 байт. У нас на элемент приходится две ячейки
  массивов таблицы и одна ячейка списка — по 4 байта на ссылку.
- **Время: `Distinct` медленнее в 1.3–2 раза при N от 50 000, а при N = 10 000 — примерно в 12 раз**
  (причина этого выброса — кластеризация, см. ниже). На каждый элемент делается два поиска в таблице
  (`containsKey`, затем `put`), а `LinkedHashSet` обходится одним. Кроме того, индекс у нас вычисляется
  делением (`%`), а в `HashMap` — побитовым `&` при ёмкости-степени двойки, и `HashMap` перемешивает биты
  хеша. На тестовых данных (плотные небольшие числа) это особенно заметно: у `Integer` хеш равен самому
  числу, и при линейном пробировании образуются длинные кластеры — подробно в `benchmarks.md`.

## Тесты

| Тест | Что проверяет |

| `shouldKeepFirstOccurrenceOrder` | порядок первого вхождения при повторах |
