# Лабораторная работа № 2. Структуры данных

## Задание 1A. Очередь с приоритетом на основе бинарной кучи

### 1. Цель работы

Реализовать собственную обобщённую очередь с приоритетом `PriorityQueueCustom<T>` на языке Java без использования стандартных коллекций для хранения элементов.

Изучить принцип работы бинарной минимальной кучи, операции добавления и извлечения элементов, а также оценить временную и пространственную сложность алгоритмов.

### 2. Описание реализации

**Файл реализации:** `src/main/java/ru/bmstu/lab2/PriorityQueueCustom.java`

**Файл тестов:** `src/test/java/ru/bmstu/lab2/PriorityQueueCustomTest.java`

Очередь с приоритетом реализована на основе бинарной минимальной кучи, которая хранится в динамически расширяемом массиве `Object[] heap`.

В минимальной куче значение каждого родительского узла не превышает значения его дочерних узлов. Поэтому минимальный элемент всегда находится в корне кучи, то есть по индексу 0.

Для узла с индексом `i` используются формулы:

- Левый потомок: `2 * i + 1`.
- Правый потомок: `2 * i + 2`.
- Родитель: `(i - 1) / 2`.

Сравнение элементов выполняется с помощью интерфейса `Comparable`.

Начальная вместимость массива составляет 16 элементов. При заполнении массива его вместимость удваивается.

### 3. Основные операции

**Добавление элемента — `add(T item)`**

Новый элемент помещается в конец массива. Затем выполняется операция `siftUp`, которая последовательно сравнивает элемент с родителем и при необходимости меняет их местами.

Процесс продолжается до восстановления свойства минимальной кучи.

Добавление `null` запрещено и вызывает `NullPointerException`.

**Извлечение минимума — `poll()`**

Минимальный элемент извлекается из корня кучи. На его место переносится последний элемент массива, после чего выполняется операция `siftDown`.

При `siftDown` элемент сравнивается с дочерними узлами и при необходимости меняется местами с меньшим из них.

Если очередь пуста, выбрасывается `NoSuchElementException`.

**Просмотр минимума — `peek()`**

Возвращает элемент с индексом 0 без удаления. Если очередь пуста, выбрасывается `NoSuchElementException`.

**Определение размера — `size()`**

Возвращает текущее количество элементов, хранящееся в поле `size`.

**Проверка пустоты — `isEmpty()`**

Проверяет равенство `size == 0`.

### 4. Анализ сложности

| Операция | Временная сложность | Обоснование |
|---|---|---|
| `add(T item)` | O(log n) амортизированно | Подъём элемента по высоте кучи |
| `poll()` | O(log n) | Спуск элемента по высоте кучи |
| `peek()` | O(1) | Обращение к первому элементу массива |
| `size()` | O(1) | Чтение поля `size` |
| `isEmpty()` | O(1) | Сравнение размера с нулём |
| `siftUp()` | O(log n) | Перемещение к родителю |
| `siftDown()` | O(log n) | Перемещение к дочернему узлу |

Высота бинарной кучи составляет O(log n), поскольку она представляет собой полное бинарное дерево.

**Пространственная сложность:** O(n), где n — количество элементов очереди.

При расширении массива дополнительно выделяется память под новый массив. Поэтому отдельная операция `add()` в момент расширения может потребовать O(n) времени, хотя амортизированная сложность добавления остаётся O(log n).

### 5. Пример работы

Добавим элементы в следующем порядке:

`8, 3, 6, 1`

После выполнения операций `add()` минимальный элемент будет находиться в корне кучи.

Вызов `peek()` вернёт `1`, не изменяя размер очереди.

Последовательные вызовы `poll()` вернут:

`1, 3, 6, 8`

Таким образом, элементы извлекаются в порядке возрастания.

### 6. Модульное тестирование

Для проверки реализации написано 12 независимых тестов с использованием JUnit.

| № | Тест | Что проверяется |
|---|---|---|
| 1 | `newQueueIsEmpty` | Новая очередь пуста |
| 2 | `addingOneElementChangesSize` | Изменение размера после добавления |
| 3 | `peekReturnsMinimum` | Получение минимального элемента |
| 4 | `peekDoesNotRemoveElement` | Сохранение размера после `peek()` |
| 5 | `pollReturnsElementsInAscendingOrder` | Правильный порядок извлечения |
| 6 | `pollDecreasesSize` | Уменьшение размера после извлечения |
| 7 | `pollLastElementMakesQueueEmpty` | Опустошение очереди |
| 8 | `duplicateElementsArePreserved` | Обработка повторяющихся значений |
| 9 | `negativeNumbersAreOrderedCorrectly` | Обработка отрицательных чисел |
| 10 | `arrayExpandsAutomatically` | Автоматическое расширение массива |
| 11 | `pollOnEmptyQueueThrowsException` | Исключение при извлечении из пустой очереди |
| 12 | `peekOnEmptyQueueThrowsException` | Исключение при просмотре пустой очереди |

Тесты охватывают обычные и граничные случаи, в том числе пустую очередь, дубликаты, отрицательные значения и превышение первоначальной вместимости массива.
