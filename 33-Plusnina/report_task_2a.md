# Лабораторная работа № 2. Структуры данных

## Задание 2А. Хеш-таблица с линейным пробированием

### 1. Цель работы

Реализовать собственную хеш-таблицу `HashMapCustom<K, V>` на языке Java с использованием метода открытой адресации и линейного пробирования.

Изучить принципы вычисления хеш-индексов, разрешения коллизий, удаления элементов и автоматического расширения таблицы.

### 2. Описание задания

Необходимо реализовать обобщённую структуру данных `HashMapCustom<K, V>` без использования стандартных коллекций Java для хранения элементов.

Структура должна поддерживать следующие операции:

- `put(K key, V value)` — добавление новой пары ключ–значение или обновление существующей.
- `get(K key)` — получение значения по ключу.
- `containsKey(K key)` — проверка наличия ключа.
- `remove(K key)` — удаление элемента по ключу.
- `size()` — получение количества элементов.
- `capacity()` — получение вместимости внутренней таблицы.

Для разрешения коллизий используется линейное пробирование. При достижении установленного порога заполнения таблица расширяется с повторным хешированием элементов.

### 3. Выбор структуры данных

Для хранения данных используются три параллельных массива:

- `Object[] keys` — ключи.
- `Object[] values` — соответствующие значения.
- `byte[] states` — состояния ячеек.

Состояние каждой ячейки определяется одной из трёх констант:

- `EMPTY` — ячейка никогда не использовалась.
- `OCCUPIED` — ячейка содержит действующую пару ключ–значение.
- `DELETED` — элемент удалён, но ячейка остаётся доступной для дальнейшего пробирования.

Использование массива состояний позволяет корректно выполнять поиск после удаления элементов.

### 4. Описание алгоритмов

#### 4.1. Вычисление хеш-индекса

Начальный индекс определяется на основании хеш-кода ключа:

\[
h(k) = (k.hashCode() \mathbin{\&} 0x7fffffff) \bmod m,
\]

где \(m\) — текущая вместимость таблицы.

Побитовая операция `& 0x7fffffff` убирает знаковый бит, обеспечивая неотрицательное значение перед вычислением остатка.

#### 4.2. Разрешение коллизий

Если рассчитанная ячейка занята другим ключом, выполняется последовательная проверка следующих ячеек.

Индекс на шаге \(i\) вычисляется по формуле:

\[
h_i(k) = (h(k) + i) \bmod m.
\]

Пробирование продолжается до обнаружения подходящей ячейки или завершения полного обхода таблицы.

#### 4.3. Добавление элементов

Метод `put()` сначала проверяет наличие ключа в таблице.

Если ключ уже существует, его значение обновляется. Если ключ отсутствует, определяется позиция для вставки.

Перед добавлением нового элемента проверяется коэффициент заполнения:

\[
\alpha = \frac{n}{m},
\]

где \(n\) — количество элементов, \(m\) — вместимость таблицы.

Если добавление приведёт к превышению порога `0.75`, выполняется расширение таблицы.

#### 4.4. Поиск элементов

Поиск начинается с вычисления хеш-индекса.

При совпадении ключа возвращается соответствующее значение. Если встречается ячейка `DELETED`, поиск продолжается.

При обнаружении `EMPTY` поиск завершается, поскольку искомый ключ отсутствует в последовательности пробирования.

#### 4.5. Удаление элементов

При удалении ключ сначала находится с помощью линейного пробирования.

После удаления состояние соответствующей ячейки изменяется на `DELETED`.

Это необходимо, чтобы не нарушить цепочку пробирования для других ключей, попавших в ту же область таблицы.

#### 4.6. Автоматическое расширение

При превышении допустимого коэффициента заполнения вызывается метод `resize()`.

В ходе расширения:

1. Сохраняются ссылки на старые массивы.
2. Создаются новые массивы удвоенной вместимости.
3. Количество элементов временно обнуляется.
4. Все действующие пары повторно размещаются с учётом новой вместимости.

Удалённые элементы при повторном хешировании не переносятся.

### 5. Оценка сложности алгоритмов

| Операция | Средняя сложность | Худшая сложность |
|---|---|---|
| `put()` | O(1), амортизированно | O(n) |
| `get()` | O(1) | O(n) |
| `containsKey()` | O(1) | O(n) |
| `remove()` | O(1) | O(n) |
| `size()` | O(1) | O(1) |
| `capacity()` | O(1) | O(1) |
| `resize()` | O(n) | O(n) |

Здесь \(n\) — количество элементов, а при оценке полного пробирования учитывается вместимость таблицы \(m\). При ограниченном коэффициенте заполнения \(m = O(n)\) для непустой таблицы.

Средняя постоянная сложность основных операций предполагает достаточно равномерное распределение хеш-кодов.

Общая пространственная сложность хранения составляет O(m), где \(m\) — вместимость таблицы.

После исправления все три массива увеличиваются согласованно, что предотвращает обращение за границы массива.
