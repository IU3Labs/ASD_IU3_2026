# Лабораторная работа № 2. Структуры данных

## Сравнение производительности собственных структур данных со стандартными реализациями Java

### 1. Цель измерений

Сравнить время выполнения операций для собственных реализаций структур данных и соответствующих стандартных реализаций Java.

Рассматриваются задания:

- **1А** — очередь с приоритетом `PriorityQueueCustom` на основе бинарной минимальной кучи.
- **2А** — хеш-таблица `HashMapCustom` с линейным пробированием.
- **3А** — поиск `k` наибольших элементов массива с помощью собственной очереди с приоритетом (`TopK`).

### 2. Методика измерений

Для измерения времени используется метод `System.nanoTime()`.

Тестирование проводится для трёх размеров входных данных:

- N = 10 000;
- N = 50 000;
- N = 100 000.

Для каждого размера выполняется по 5 запусков. Результат представляется как среднее время выполнения в миллисекундах.

Измерения выполнены с помощью программы `Benchmarks.java`.

### 4. Анализ результатов

**Задание 1А. Очередь с приоритетом**

При увеличении количества элементов время работы собственной очереди с приоритетом возрастает. Стандартная `PriorityQueue` во всех трёх измерениях показала меньшее время выполнения. Обе реализации используют бинарную кучу, поэтому имеют одинаковые асимптотические оценки основных операций: O(log n) для добавления и извлечения элемента.

**Задание 2А. Хеш-таблица**

Собственная `HashMapCustom` использует открытое хеширование с линейным пробированием, а стандартная `HashMap` — другую организацию хранения элементов. При небольших размерах данных собственная реализация показала сопоставимое время работы. При N = 100 000 стандартная реализация оказалась быстрее. Средняя сложность поиска и вставки при благоприятном распределении хешей составляет O(1), однако при большом количестве коллизий время операций увеличивается.

**Задание 3А. Поиск k наибольших элементов**

Алгоритм `TopK` поддерживает минимальную кучу из не более чем `k` элементов. Благодаря этому нет необходимости сортировать весь входной массив. Асимптотическая сложность составляет O(n log k), а дополнительная память — O(k). Полученные результаты показывают небольшое время выполнения обеих реализаций, однако отдельные измерения заметно различаются.

### 5. Оценка дополнительной памяти

| Структура или алгоритм | Асимптотическая сложность памяти |
|---|---|
| PriorityQueueCustom | O(n) |
| HashMapCustom | O(n) |
| TopK | O(k) |

Очередь с приоритетом хранит элементы в динамическом массиве. Хеш-таблица использует массивы ключей, значений и состояний ячеек, поэтому её дополнительная память пропорциональна вместимости таблицы. Алгоритм `TopK` хранит только `k` кандидатов на попадание в результат и выходной массив длины `k`.

### 6. Вывод

Реализованы собственные структуры данных и проведено сравнение их производительности со стандартными средствами Java.

Результаты подтверждают, что собственные реализации способны выполнять необходимые операции за сопоставимое время, хотя стандартные библиотечные структуры часто оказываются быстрее.

Измерения времени зависят от условий выполнения программы, поэтому полученные численные результаты характеризуют конкретный запуск и не являются универсальной оценкой производительности.
