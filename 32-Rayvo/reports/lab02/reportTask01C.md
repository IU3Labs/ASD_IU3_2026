## Задача 1C. Удаление по значению

В `ru.bmstu.lab02.task_01c.RemovablePriorityQueue<T>` добавлена операция `boolean remove(T item)`.
Класс наследует базовые операции и поддержку компаратора.

### Идея решения

Линейно просматривается занятая часть массива. Удаляется первое найденное по equals вхождение,
а не все дубликаты и не любой объект с равным приоритетом. Под «первым» понимается порядок
внутреннего массива кучи: порядок вставки и стабильность для равных приоритетов не обещаются.
Для пустой очереди, отсутствующего значения и null возвращается false.

Найденная ячейка заменяется последним элементом. Если он меньше родителя в выбранном порядке,
нужно siftUp; иначе — siftDown. Проверять только просеивание вниз недостаточно:
последний элемент мог находиться в другой ветви и оказаться меньше нового родителя.
При удалении последней ячейки просеивание не требуется. Освободившаяся ссылка очищается.
Восстановление выполняется общим removeAt из задачи 1A, которым также пользуется poll.

### Асимптотика

Поиск занимает O(n) сравнений equals, восстановление — O(log n).
Итого remove — O(n + log n) = O(n), при условии O(1) для equals и компаратора.
Дополнительная память удаления — O(1), очередь занимает O(c), где c — ёмкость массива.
Сложности add, poll, peek, size и isEmpty совпадают с предыдущими вариантами.

### Проверки

12 независимых тестов JUnit 5 покрывают все требуемые случаи: корень, середину,
несуществующий элемент и пустую очередь. Дополнительно проверяются восстановление вверх
и вниз, последняя ячейка, единственный элемент, одно вхождение из дубликатов, null,
max-heap и различие equals/равенства компаратора. В 5000 случайных смешанных операциях
результаты, размер и минимум сравниваются с java.util.PriorityQueue.
Тестовый класс: [RemovablePriorityQueueTest.java](../../src/test/java/ru/bmstu/lab02/task_01c/RemovablePriorityQueueTest.java).

| Юнит-тест | Что проверяет |
|---|---|
| `shouldReturnFalseWhenRemovingFromEmptyQueue` | Удаление из пустой очереди возвращает false. |
| `shouldRemoveRoot` | Удаляется минимум в корне; оставшиеся элементы сохраняют порядок. |
| `shouldSiftDownAfterRemovingMiddleElement` | После удаления 2 из кучи 1–9 требуется просеивание вниз. |
| `shouldSiftUpAfterRemovingMiddleElement` | После удаления 11 из 0, 10, 1, 11, 12, 2, 3 требуется просеивание вверх. |
| `shouldRemoveLastArrayElement` | Удаление последней ячейки не требует просеивания. |
| `shouldPreserveQueueWhenValueIsAbsent` | Несуществующее значение даёт false; размер и содержимое не меняются. |
| `shouldRemoveOnlyOneOccurrence` | Из нескольких равных значений удаляется ровно одно. |
| `shouldRemoveSingleElementAndAllowReuse` | Удаляется единственный элемент; очередь можно использовать повторно. |
| `shouldReturnFalseForNullValue` | remove(null) возвращает false и сохраняет содержимое. |
| `shouldRemoveFromMaxHeap` | Удаление корня и другого значения работает с reverseOrder. |
| `shouldUseEqualsInsteadOfComparatorEquality` | Приоритет по длине не заменяет equals; равный по значению объект можно удалить. |
| `shouldMatchStandardQueueOnMixedOperations` | 5000 случайных add/remove/poll сравниваются с JDK, включая size, isEmpty и peek. |

Ручные примеры и ожидаемые результаты:


| Ручная проверка | Ожидаемый результат poll после remove | Зачем нужна |
|---|---|---|
| 4, 1, 6, 3, 2; remove(1) | 2, 3, 4, 6 | Удаление корня |
| 1, 2, 3, 4, 5, 6, 7, 8, 9; remove(2) | 1, 3, 4, 5, 6, 7, 8, 9 | Просеивание вниз |

| Пустая очередь; remove(5) | false, размер 0 | Граничный случай |
| 1, 2, 3; remove(99) | false; затем 1, 2, 3 | Неуспешный поиск ничего не меняет |
