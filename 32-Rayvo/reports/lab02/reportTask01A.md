## Задача 1A. Очередь с приоритетом на динамическом массиве

Реализован `ru.bmstu.lab02.task_01a.PriorityQueueCustom<T>`:
`add`, `poll`, `peek`, `size`, `isEmpty`. Элементы извлекаются в порядке неубывания.

### Идея решения

Используется двоичная min-heap в массиве `Object[]`, начальная ёмкость — 16.
Дети узла i имеют индексы `2*i + 1`, `2*i + 2`, родитель — `(i - 1) / 2`.
При вставке элемент помещается в конец и поднимается приватным методом `siftUp`.
При извлечении корень заменяется последним элементом, затем приватный `siftDown` выбирает
меньшего ребёнка и восстанавливает порядок. Последняя занятая ячейка очищается от ссылки.
При заполнении массива ёмкость удваивается; элементы копируются через `System.arraycopy`.
Готовые коллекции в реализации не используются.

Для задач 1B–1D предусмотрены защищённые compare, elementAt, removeAt и buildHeap:
общие алгоритмы не копируются между пакетами. Все публичные операции 1A работают самостоятельно.

### Асимптотика

Высота двоичной кучи — O(log n); каждое просеивание проходит не более одного пути.

| Метод | Время | Дополнительная память операции |
|---|---|---|
| add без расширения | O(log n) в худшем случае | O(1) |
| add с расширением | O(n) в конкретном вызове | O(n) на новый массив |
| add, амортизированно | O(log n) | O(1) амортизированных новых ячеек |
| poll | O(log n) | O(1) |
| peek | O(1) | O(1) |
| size, isEmpty | O(1) | O(1) |

Копирования при последовательных удвоениях имеют суммарную стоимость
`16 + 32 + 64 + ... < 2*m` для m вставок, поэтому расширение даёт O(1) амортизированно
на вставку. Указанная в условии O(log n) для динамического массива понимается амортизированно:
строгая худшая оценка отдельного add при копировании — O(n).
Очередь занимает O(c) памяти, где c — ёмкость, соответствующая максимальному достигнутому размеру.
Удаления массив не сжимают, что сохраняет худшую оценку O(log n) для poll.

### Проверки

12 независимых тестов JUnit 5 проверяют пустую очередь, одиночный элемент, peek без удаления,
неотсортированный и отсортированный ввод, дубликаты, отрицательные и крайние int,
несколько расширений, повторное использование, запрет null и чередование add/poll.
Тестовый класс: [PriorityQueueCustomTest.java](../../src/test/java/ru/bmstu/lab02/task_01a/PriorityQueueCustomTest.java).

| Юнит-тест | Что проверяет |
|---|---|
| `shouldStartEmpty` | Пустая очередь: size = 0, isEmpty = true, peek = null. |
| `shouldThrowWhenPollingEmptyQueue` | poll пустой очереди бросает NoSuchElementException и не меняет размер. |
| `shouldPeekWithoutRemovingMinimum` | Два вызова peek возвращают минимум 3 и сохраняют оба элемента. |
| `shouldHandleSingleElement` | Вставка и извлечение 42 возвращают очередь в пустое состояние. |
| `shouldPollUnsortedInputInNondecreasingOrder` | Неотсортированные числа извлекаются как 1, 2, 3, 4, 7, 9. |
| `shouldKeepDuplicateElements` | Все три одинаковых значения 5 сохраняются и извлекаются. |
| `shouldHandleNegativeAndExtremeValues` | Проверяются MIN_VALUE, MAX_VALUE, отрицательное число и ноль. |
| `shouldGrowArraySeveralTimes` | 2000 убывающих значений вызывают несколько расширений; порядок извлечений сохраняется. |
| `shouldAllowReuseAfterDraining` | После полного опустошения очередь принимает новые значения. |
| `shouldRejectNullWithoutChangingQueue` | add(null) бросает NullPointerException; размер и минимум не меняются. |
| `shouldHandleAlreadySortedInput` | Отсортированные значения 1–6 извлекаются в том же порядке. |
| `shouldSupportInterleavedAddAndPoll` | Проверяются чередование вставок и извлечений и исключение после опустошения. |

| Ручная проверка | Ожидаемый результат | Зачем нужна |
