## Задача 1D. Построение кучи за O(n)

Реализованы конструкторы `HeapifyPriorityQueue(T[] array)` и
`HeapifyPriorityQueue(T[] array, Comparator<? super T> comparator)` в пакете `task_01d`.
Пустые конструкторы и все операции задач 1A–1C также доступны.

### Идея решения

Используется алгоритм Флойда. После проверки null массив копируется в собственный Object[].
Размер присваивается сразу; последовательные add не вызываются. С последнего внутреннего
узла `n / 2 - 1` до корня вызывается приватный siftDown из общего базового класса.
У листьев нет детей, поэтому их отдельная обработка не нужна. При проходе вверх обе
подкучи текущего узла уже корректны, и просеивание превращает всю подкучу в кучу.

Входной массив не сортируется и не разделяется с очередью: изменение его ячеек после
конструктора не меняет очередь. Сами объекты элементов не клонируются — копируются ссылки.
Пустой массив допустим, null-массив и null-элемент приводят к NullPointerException.

### Асимптотика

Линейные проверка элементов и копирование стоят O(n). В полной двоичной куче узлов
высоты h не больше O(n / 2^h). Поэтому суммарная работа просеиваний ограничена
`O(n * sum(h / 2^h)) = O(n)`, поскольку этот бесконечный ряд сходится.
Итого конструктор — O(n) в худшем случае. Память нового массива — O(n), служебная
память прохода — O(1); рекурсия не применяется.

При последовательных add общая худшая граница — O(n log n), а копирования из-за
удвоений суммарно стоят O(n). На случайных значениях ожидаемая суммарная работа
вставок может быть линейной, поэтому замер не обязан показывать логарифмический разрыв.
На убывающем массиве для min-heap каждая новая вставка поднимается к корню;
линейный heapify сохраняет свою гарантию независимо от порядка входа.

### Проверки

12 независимых тестов JUnit 5 проверяют пустой и одноэлементный массив, оба направления
сортировки, дубликаты и крайние int, копирование без изменения или разделения массива,
null-массив и null-элемент, max-heap, рост и remove после heapify, пустые конструкторы.
Отдельный тест на 8192 убывающих элементах проверяет менее 2*n сравнений при построении,
а затем порядок всех извлечений: временных ограничений в тестах нет.
Тестовый класс: [HeapifyPriorityQueueTest.java](../../src/test/java/ru/bmstu/lab02/task_01d/HeapifyPriorityQueueTest.java).

| Юнит-тест | Что проверяет |
|---|---|
| `shouldBuildFromEmptyArray` | Пустой массив даёт size = 0; poll бросает NoSuchElementException. |
| `shouldBuildFromSingleElement` | Из одного значения 12 строится корректная очередь. |
| `shouldBuildFromAscendingArrayWithNullComparator` | Возрастающий массив и null-компаратор дают естественный порядок. |
| `shouldBuildFromDescendingArray` | Убывающий массив преобразуется в min-heap. |
| `shouldKeepDuplicatesAndExtremeValues` | При heapify сохраняются дубликаты, отрицательные и крайние int. |
| `shouldCopyInputWithoutModifyingOrSharingArray` | Конструктор не изменяет массив; последующая замена его ячейки не влияет на очередь. |
| `shouldRejectNullArray` | null-массив вызывает NullPointerException. |
| `shouldRejectNullArrayElement` | null внутри массива вызывает исключение без изменения исходного массива. |
| `shouldBuildMaxHeapFromRandomArray` | Heapify 1000 случайных значений с reverseOrder сверяется с сортировкой. |
| `shouldSupportGrowthAndRemovalAfterHeapify` | После построения от 32 элементов работают расширение через add и remove. |
| `shouldSupportEmptyQueueConstructors` | Проверяются пустые конструкторы с естественным и обратным порядком. |
| `shouldBuildWithLinearNumberOfComparisons` | На 8192 убывающих значениях heapify делает менее 2*n сравнений; все извлечения упорядочены. |
