# Отчёт по задаче 1B — Min-heap и max-heap через компаратор

**Лабораторная работа:** №2 — структуры данных  
**Группа:** ИУ3-32  
**ФИО:** Щукин Алексей Романович  
**Модуль:** `32-Shchukin`  
**Стоимость задачи:** 2 балла  
**Класс:** `ru.bmstu.lab2.task_1.PriorityQueueCustom`

## 1. Условие задачи

Добавить конструктор с `Comparator<T>`. При отсутствии компаратора использовать естественный порядок;
поддержать минимальную и максимальную кучу. Сравнить время обоих режимов на одинаковых
100 000 случайных чисел.

## 2. Идея и реализация алгоритма

В обоих режимах используется одна двоичная куча. Метод `compare` передаёт сравнение указанному
компаратору; при его отсутствии использует `Comparable`. Для max-heap применяется
`Comparator.reverseOrder()`. Остальные операции кучи не меняются.

**Обоснование:** направление приоритета задаётся сравнением элементов, поэтому отдельный класс
для максимальной кучи не требуется.

## 3. Анализ асимптотики

Порядок сравнения не меняет высоту кучи. Операции `add` и `poll` имеют время O(log n)
(для `add` — амортизированно с учётом расширения), `peek` — O(1). Дополнительная память
при смене компаратора — O(1); вся очередь занимает O(n).

## 4. Граничные случаи и тестирование

| Проверка | Ожидаемый результат | Назначение |
|---|---|---|
| Min-heap: `[1, 4, 2, 5, 3]` | `1, 2, 3, 4, 5` | Естественный порядок |
| Max-heap: `[1, 4, 2, 5, 3]` | `5, 4, 3, 2, 1` | Обратный порядок |
| Строки `"beta", "alpha"` | `"alpha", "beta"` | Естественный порядок строк |
| Компаратор длины строк | По возрастанию длины | Произвольный компаратор |

Оба режима измеряются на одном массиве из 100 000 случайных элементов; результаты, условия замера
и вывод приведены в `benchmarks.md`.
