# Отчёт по задаче 1D — Построение кучи за O(n)

**Лабораторная работа:** №2 — структуры данных  
**Группа:** ИУ3-32  
**ФИО:** Щукин Алексей Романович  
**Модуль:** `32-Shchukin`  
**Стоимость задачи:** 2 балла  
**Класс:** `ru.bmstu.lab2.task_1.PriorityQueueCustom`

## 1. Условие задачи

Добавить конструктор `PriorityQueueCustom(T[] array)`, который строит кучу за O(n).
Сравнить на 100 000 элементов построение через последовательные `add` и непосредственно из массива.

## 2. Идея и реализация алгоритма

Конструктор копирует элементы входного массива, затем последовательно вызывает `siftDown`
для внутренних узлов, начиная с индекса `n / 2 - 1` и заканчивая корнем.
Листья уже являются корректными кучами, поэтому обрабатывать их не нужно.

**Обоснование:** большинство узлов расположено близко к листьям, для них просеивание короткое.
Суммарная работа всех просеиваний ограничена O(n), хотя отдельное просеивание может занять O(log n).

## 3. Анализ асимптотики

- **Построение через последовательные `add`:** O(n log n) в худшем случае.
- **Построение снизу вверх:** O(n) по времени.
- **Память:** O(n), поскольку входной массив копируется во внутренний массив кучи.

## 4. Граничные случаи и тестирование

| Проверка | Ожидаемый результат | Назначение |
|---|---|---|
| Конструктор с `[7, 2, 8, 1, 3]` | Извлечение `1, 2, 3, 7, 8` | Корректность построения |
| Изменение исходного массива после создания | Куча не меняется | Независимое хранение |
| Конструктор с пустым массивом | Очередь пуста, затем принимает элементы | Граничный случай |
| `null` среди элементов массива | `NullPointerException` | Запрет недопустимых данных |

В `benchmarks.md` приведены реальные замеры обоих способов на одном убывающем массиве
из 100 000 элементов, результаты и краткий вывод.
