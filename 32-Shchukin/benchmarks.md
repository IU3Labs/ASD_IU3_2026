# Бенчмарки ЛР №2 — 32-Shchukin

Замеры получены запуском `PriorityQueueBenchmark`. Для каждого набора: 2 прогревочных и 5 измеряемых запусков. Для 1A и 1B использованы одинаковые случайные данные `Random(42)`, для 1D — 100 000 чисел по убыванию.

**Среда:** Java 25.0.4.1, Windows 11, amd64.

| Структура | Операция | N элементов | Среднее время (мс) | Примечание |
|---|---|---:|---:|---|
| `PriorityQueueCustom` | add + poll (min-heap) | 10000 | 1.371 | Собственная куча |
| `java.util.PriorityQueue` | add + poll (min-heap) | 10000 | 1.288 | Библиотека Java |

| `java.util.PriorityQueue` | add + poll (min-heap) | 50000 | 5.762 | Библиотека Java |

| `java.util.PriorityQueue` | add + poll (min-heap) | 100000 | 13.226 | Библиотека Java |
| `PriorityQueueCustom` | add + poll (min-heap) | 100000 | 14.125 | Задача 1B |
| `PriorityQueueCustom` | add + poll (max-heap) | 100000 | 14.081 | Тот же набор, обратный порядок |
| `PriorityQueueCustom` | построение через add | 100000 | 3.172 | Убывающий массив |

## Вывод

Собственная очередь и `java.util.PriorityQueue` используют двоичную кучу, поэтому у них одинаковые основные асимптотические оценки; время зависит от реализации и работы JVM. Min-heap и max-heap выполняют одинаковые по сложности действия, а разница в замерах может объясняться сравнениями и особенностями входных данных. Построение снизу вверх имеет оценку O(n), а последовательное добавление — O(n log n) в худшем случае; на конкретном наборе времена могут быть близкими. Обе очереди используют O(n) ссылок в массивах; отдельное измерение потребления памяти не проводилось.
