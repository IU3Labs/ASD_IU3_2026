# Замеры ЛР2

Замеры выполнены на Windows 10, Microsoft OpenJDK 21.0.12.1, с размером кучи JVM
512 МБ. Для каждого размера с генератором `Random(42)` подготовлен набор
уникальных случайных `Integer`. Все реализации в одной серии получают одни
и те же элементы в одинаковом порядке. Генерация данных находится вне замера.

Один прогон включает создание новой структуры и выполнение всех операций.
Для очереди это вставка всех элементов и извлечение до опустошения. Для таблицы
это вставка всех пар, поиск каждого ключа и удаление всех пар. Для каждого
сценария выполнено 10 прогревочных и 20 измеряемых прогонов в одной JVM.
Порядок запуска сценариев циклически меняется. В таблице приведено среднее
арифметическое времени одного прогона.

| Структура | Операция | N | Среднее время, мс |
| --- | --- | ---: | ---: |
| `PriorityQueueCustom (min)` | add + poll | 10 000 | 0.784 |
| `PriorityQueueCustom (max)` | add + poll | 10 000 | 1.049 |
| `java.util.PriorityQueue` | add + poll | 10 000 | 0.734 |
| `HashMapCustom` | put + get + remove | 10 000 | 0.510 |
| `java.util.HashMap` | put + get + remove | 10 000 | 0.285 |
| `PriorityQueueCustom (min)` | add + poll | 50 000 | 5.358 |
| `PriorityQueueCustom (max)` | add + poll | 50 000 | 6.939 |
| `java.util.PriorityQueue` | add + poll | 50 000 | 5.091 |
| `HashMapCustom` | put + get + remove | 50 000 | 3.358 |
| `java.util.HashMap` | put + get + remove | 50 000 | 2.215 |
| `PriorityQueueCustom (min)` | add + poll | 100 000 | 12.464 |
| `PriorityQueueCustom (max)` | add + poll | 100 000 | 15.699 |
| `java.util.PriorityQueue` | add + poll | 100 000 | 11.552 |
| `HashMapCustom` | put + get + remove | 100 000 | 6.809 |
| `java.util.HashMap` | put + get + remove | 100 000 | 4.806 |

Команды для повтора из корня репозитория на Windows.

```powershell
mvn -pl 31-Rogov test-compile
java -Xms512m -Xmx512m -cp "31-Rogov/target/classes;31-Rogov/target/test-classes" ru.bmstu.lab02.StructuresBenchmark
```

В Linux и macOS разделитель путей в `-cp` — `:`.

## Вывод

На 100 000 элементов max-heap заняла 15,699 мс, min-heap — 12,464 мс при
одинаковой асимптотике. На время могут влиять вызов обратного компаратора
и число шагов просеивания при разных порядках приоритетов.
Стандартная очередь в этом прогоне опередила обе версии нашей кучи, хотя все
три варианта держат ссылки на элементы в массиве и выделяют память при его росте.
На всех трёх размерах `java.util.HashMap` оказался быстрее `HashMapCustom`,
где кластеры линейного пробирования могут удлинять поиск, а маркеры занимают
ячейки до повторной вставки или перехеширования.
