## Очередь с приоритетом

`PriorityQueueCustom<T>` хранит двоичную кучу в массиве. У вершины с индексом `i`
дети находятся по индексам `2i + 1` и `2i + 2`. При добавлении элемент поднимается
к своему месту через `siftUp`. При извлечении корня его место занимает последний
элемент, затем `siftDown` опускает его ниже по куче. Компаратор задаёт порядок
во всех сравнениях, поэтому обратный компаратор превращает min-heap в max-heap.

`remove` ищет первое совпадение по `equals` в массиве. Если удалённый элемент
заменяется последним, достаточно одного просеивания. Новый элемент поднимается,
когда он предшествует родителю по порядку кучи, а в остальных случаях опускается.
Очередь отклоняет `null` при добавлении. На пустой очереди `peek` возвращает
`null`, а `poll` бросает `NoSuchElementException`.

| Операция | Время | Обоснование |
| --- | --- | --- |
| `add` | O(log n) амортизированно, O(n) при росте | Просеивание по высоте кучи. При удвоении ёмкости массив копируется. |
| `poll` | O(log n) | Одно просеивание вниз. |
| `remove` | O(n) | Линейный поиск и до одного просеивания. |
| `peek`, `size`, `isEmpty` | O(1) | Чтение корня или счётчика. |

Память — O(m) для массива ёмкости m. Ёмкость зависит от максимального размера
очереди за время её жизни. Просеивание использует O(1) дополнительной памяти.

## Хеш-таблица

`HashMapCustom<K, V>` начинает поиск с `abs(hashCode) % capacity`. Хеш расширяется
до `long` перед вызовом `Math.abs`, чтобы корректно обработать
`Integer.MIN_VALUE`. При коллизии поиск проверяет следующую ячейку и при
достижении конца массива переходит к началу. Маркер `DELETED` освобождает
ячейку для вставки, сохраняя цепочку поиска. Вставка запоминает первый маркер
и продолжает поиск до совпадения ключа или до пустой ячейки.

Таблица удваивается перед вставкой новой пары при превышении загрузки 0,75.
Если вместе с маркерами заняты 7/8 ячеек и вставка потребует ещё одну пустую
ячейку, таблица перехешируется при той же ёмкости. Это ограничивает число
маркеров и сохраняет пустые ячейки для остановки поиска. Таблица допускает
ключ и значение `null`. `containsKey` отличает отсутствующий ключ от ключа
со значением `null`.

| Операция | Время | Обоснование |
| --- | --- | --- |
| `put` | Ожидаемое амортизированное O(1) | При равномерных хешах число проб невелико. Перехеширование стоит ожидаемое O(m). |
| `get`, `containsKey`, `remove` | Ожидаемое O(1), худшее O(m) | Кластер коллизий и маркеров может занимать часть массива порядка m. |
| `size`, `capacity` | O(1) | Чтение счётчика или длины массива. |

Здесь m — текущая ёмкость, n — число хранимых пар. При патологических
коллизиях вставка с перехешированием может занять O(m + n²), поскольку
вставки при переносе тоже пробируют ячейки. Память — O(m), включая пары
и временный массив при перехешировании.

## Проверка

| Сценарий | Ожидаемый результат |
| --- | --- |
| Добавить в очередь `3, 1, 3, 2` | В естественном порядке извлекаются `1, 2, 3, 3`. С обратным компаратором — `3, 3, 2, 1`. |
| Добавить `49, 7, 38, 10, 1, 33, 14, 34, 20, 0` и удалить `38` | Последний элемент `10` поднимается выше `14`. Извлечение остаётся упорядоченным. |
| В пустую таблицу ёмкости 16 добавить ключи `15, 31, 47`, затем удалить `15` | Поиск `31` и `47` проходит через маркер в конце массива к началу. |
| Вставить пару `"key" → null` | `get("key")` возвращает `null`, а `containsKey("key")` возвращает `true`. |
