# Замеры скорости

Дата: 21.11.2026. Java 25.0.4.1, Windows 11.

Сравниваются своя очередь `PriorityQueueCustom` и стандартная `java.util.PriorityQueue`.
Каждая очередь получает одинаковые числа. Сначала добавляются все элементы, затем извлекаются все.
Перед замером выполняются 5 прогревочных запусков. В таблице — среднее время 10 измерений.
Время измеряется через `System.nanoTime()`, создание входного массива не учитывается.
Случайные числа создаются с фиксированным seed = 31.

## Добавление и извлечение

В режиме «минимум» сначала извлекаются меньшие числа, в режиме «максимум» — большие.

|---|---|---:|---:|---|
| PriorityQueueCustom | добавить и извлечь все | 10000 | 2.148 | минимум первым |
| java.util.PriorityQueue | добавить и извлечь все | 10000 | 2.149 | минимум первым |
| PriorityQueueCustom | добавить и извлечь все | 10000 | 2.914 | максимум первым |
| java.util.PriorityQueue | добавить и извлечь все | 10000 | 3.184 | максимум первым |
| PriorityQueueCustom | добавить и извлечь все | 50000 | 22.256 | минимум первым |
| java.util.PriorityQueue | добавить и извлечь все | 50000 | 18.400 | минимум первым |
| PriorityQueueCustom | добавить и извлечь все | 50000 | 19.667 | максимум первым |
| java.util.PriorityQueue | добавить и извлечь все | 50000 | 17.665 | максимум первым |
| PriorityQueueCustom | добавить и извлечь все | 100000 | 40.211 | минимум первым |
| java.util.PriorityQueue | добавить и извлечь все | 100000 | 37.700 | минимум первым |

## Построение очереди: задача 1D

Один убывающий массив из 100000 чисел используется во всех вариантах.
Измеряется только построение очереди, без извлечения.
При таком порядке последовательные вставки требуют много подъёмов к корню.

| Структура | Операция | N элементов | Среднее время (мс) | Примечание |
|---|---|---:|---:|---|
| PriorityQueueCustom | последовательные add | 100000 | 8.748 | O(n log n), худший случай |
| PriorityQueueCustom | конструктор из массива | 100000 | 1.353 | O(n) |
| java.util.PriorityQueue | конструктор из коллекции | 100000 | 1.054 | O(n) |

## Вывод

На 100000 чисел своя очередь в режиме минимума заняла 40.211 мс, стандартная — 37.700 мс.
Режимы минимума и максимума дали 40.211 и 43.795 мс: алгоритм тот же, но порядок сравнений и работа Java влияют на время.
Построение сразу из массива заняло 1.353 мс против 8.748 мс через add и оказалось быстрее на этом наборе.
Обе очереди используют массив с запасом места, поэтому память зависит от его ёмкости; точное число байтов не измерялось.
