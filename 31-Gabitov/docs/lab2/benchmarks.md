# Замеры производительности

Дата запуска: 21.11.2026. Microsoft OpenJDK 25.0.4.1, Windows 11, amd64.
Это фактически выполненные локальные замеры, не предполагаемые числа.

## Методика

5 прогревочных запусков и 10 измерений; в таблице среднее время в миллисекундах.
Используется System.nanoTime(). Перед каждым измерением создаётся новая очередь.
Массив случайных Integer заранее создаётся с seed = 31 и не входит во время операции.
Для каждой длины реализации получают одни и те же данные; порядок собственная/стандартная чередуется.
Один цикл означает добавление всех N элементов и извлечение всех N элементов.
Результат используется в контрольной сумме, чтобы вычисление не оказалось неиспользуемым.
Это простой учебный замер, без JMH и без статистических доверительных интервалов.

## Вывод

На 100000 элементов min-heap собственной реализации заняла 44.662 мс, стандартная очередь — 39.862 мс.
Min- и max-режимы на одинаковом случайном наборе дали 44.662 и 45.989 мс: асимптотика одинакова, различия связаны с порядком сравнений, JIT и шумом измерений.
Такие одиночные учебные замеры не доказывают постоянного преимущества одной реализации на всех входных данных.
Обе очереди хранят массив ссылок и требуют O(n) памяти при росте, но запас ёмкости и выделения при расширении отличаются; точные байты здесь не измерялись, а после удалений сохранённая ёмкость может быть больше текущего размера.
