# ЛР2 в модуле 31-Gabitov

Код ЛР2 находится в src/main/java/ru/bmstu/lab2.
Тесты и QueueBenchmark находятся в src/test/java/ru/bmstu/lab2.
Документы ЛР2 находятся в docs/lab2: README.md, report.md, benchmarks.md.
Пакет lab1 и прежний отчёт ЛР1, если они уже есть в основной ветке, не заменяются.

## Проверка

Нужны JDK 25 или новее, Maven и доступ к Maven Central при первом запуске.
Откройте корневой pom.xml проекта в IntelliJ, обновите Maven.
Запустите Maven → 31-Gabitov → Lifecycle → verify.
Или из корня проекта выполните:

```powershell
mvn -pl 31-Gabitov clean verify
```

Если mvn не найден, используйте путь из своей установки IntelliJ:

```powershell
& "C:\жава\IntelliJ IDEA 2026.2.3\plugins\maven-plugin\lib\maven3\bin\mvn.cmd" -pl 31-Gabitov clean verify
```

При переносе IntelliJ укажите новый путь к mvn.cmd.
Внутренний 31-Gabitov/pom.xml подготовлен с JUnit 5 и JaCoCo.
Он не ограничивает агент пакетом lab1: проверяется весь имеющийся код модуля.
Если этот pom.xml уже существует и содержит ваши дополнительные настройки,
сначала сохраните копию и сравните изменения, не заменяйте настройки вслепую.

ЛР2 содержит 14, 19, 28 или 35 тестов в зависимости от шага.
Если в ветке уже есть тесты ЛР1, общее число будет больше — это нормально.
При проверке отдельной ЛР2 покрытие её класса 100%; общее покрытие модуля зависит и от ЛР1.
Отчёт покрытия: 31-Gabitov/target/site/jacoco/index.html.
Нельзя отключать проверки или исключать ЛР1 из покрытия ради нужного процента.

## Замеры

Сначала выполните verify, затем в том же терминале:

```powershell
java "-Dstdout.encoding=UTF-8" -cp "31-Gabitov/target/classes;31-Gabitov/target/test-classes" ru.bmstu.lab2.QueueBenchmark
```

Если java не найдена, используйте полный путь к java.exe своего JDK.
Также можно запустить main в QueueBenchmark.java через IntelliJ.

Таблицы скопируйте в 31-Gabitov/docs/lab2/benchmarks.md и обновите числа в выводе.
В комплекте уже есть реальные замеры 21.11.2026; время зависит от компьютера, JIT и нагрузки.
Не записывайте их как результаты своего нового запуска, если ещё не запускали программу.

## Ограничения очереди

null не хранится. Пустые poll и peek выбрасывают NoSuchElementException.
Без Comparator элементы должны поддерживать Comparable и быть взаимно сравнимы.
Очередь не предназначена для одновременного изменения из нескольких потоков.
