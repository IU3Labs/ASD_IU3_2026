**Тесты:** `src/test/java/ru/bmstu/lab02/task1a/PriorityQueueCustomTest.java`

## Условие

Реализовать `PriorityQueueCustom<T>` на динамическом массиве: `add` за O(log n), `poll` за O(log n)
(на пустой очереди — `NoSuchElementException`), `peek` за O(1), `size` и `isEmpty` за O(1).
Дети узла `i` — `2*i + 1` и `2*i + 2`, родитель — `(i - 1) / 2`. Просеивание — приватные методы `siftUp` и `siftDown`.
Массив должен расширяться автоматически, элементы извлекаются в порядке неубывания.

## 1. Идея решения и структура данных

Структура данных — **двоичная min-куча** в обычном массиве `Object[] items`. Дерево явно не строится:
связь «родитель — дети» считается по индексам. Каждый элемент не больше своих детей, поэтому минимум
всегда лежит в `items[0]`.

Почему куча, а не отсортированный массив: в отсортированном массиве вставка стоит O(n) из-за сдвига элементов,
а в куче и вставка, и извлечение минимума стоят O(log n), потому что меняется только один путь от листа до корня.

Особенности реализации:

- **Порядок хранится в поле `order` (компаратор).** Публичный конструктор без параметров задаёт естественный
  порядок (`compareTo`). Защищённый конструктор `PriorityQueueCustom(Comparator)` позволяет задаче 1B
  передать другой порядок, при этом ни один метод кучи не переопределяется.
- **Просеивание «через дырку»** вместо обменов `swap`. Перемещаемый элемент запоминается в переменной `moving`,
  элементы на пути сдвигаются на одну позицию, и `moving` записывается один раз в конце. На каждом уровне —
  одна запись в массив вместо трёх.
- `poll()` берёт `items[0]` и вызывает `extractAt(0)`: на место корня ставится последний элемент, затем `siftDown`.
- `expand()` увеличивает массив в `GROWTH_FACTOR = 2` раза (начальная ёмкость 8).
- `positionOf` и `extractAt` — защищённые методы для задачи 1C. Сами `siftUp` и `siftDown` приватные, как требует условие.

## 2. Анализ асимптотики

`n` — количество элементов, высота кучи `h = ⌊log₂ n⌋`.

| Операция | Время | Доп. память |
|---|---|---|
| `add` | O(log n) амортизированно, O(n) в момент расширения | O(1), при расширении O(n) на новый массив |
| `poll` | O(log n) | O(1) |
| `peek` | O(1) | O(1) |
| `size`, `isEmpty` | O(1) | O(1) |
| Вся структура | — | O(n): ёмкость массива меньше `2n` (при n > 8) |

### Обоснование кодом

**`siftUp` — O(log n).** Каждая итерация переходит к родителю: `index = (index - 1) / 2`, индекс уменьшается
примерно вдвое. От листа до корня не больше `h = ⌊log₂ n⌋` шагов, на шаге одно сравнение.

```java
while (index > 0) {
    int parent = (index - 1) / 2;
    if (compare(moving, items[parent]) >= 0) {
        break;
    }
    items[index] = items[parent];
    index = parent;
}
items[index] = moving;
```

**`siftDown` — O(log n).** Каждая итерация переходит к ребёнку `2 * index + 1` или `2 * index + 2`, индекс растёт
минимум вдвое, поэтому шагов не больше `h`. На шаге 2 сравнения: выбор меньшего ребёнка и сравнение с ним.

```java
while (2 * index + 1 < count) {
    int child = 2 * index + 1;
    int right = 2 * index + 2;
    if (right < count && compare(items[right], items[child]) < 0) {
        child = right;
    }
    ...
    index = child;
}
```

**`poll` — O(log n).** `peek()` за O(1), затем `extractAt(0)`: перенос последнего элемента в корень за O(1) и один
`siftDown` за O(log n). Следом может вызваться `siftUp(0)`, но у корня нет родителя, и цикл сразу заканчивается.

**`peek`, `size`, `isEmpty` — O(1).** Возвращают `items[0]` или поле `count`, циклов нет.

**`add` — O(log n) амортизированно.** Сама вставка — запись в конец и `siftUp`, то есть O(log n).
`expand()` копирует все элементы за O(n), но вызывается только при `count == items.length`.
Ёмкость растёт 8 → 16 → 32 → …, поэтому при вставке `n` элементов всего копируется
`8 + 16 + … + n/2 + n < 2n` элементов — O(1) копирований на одну вставку в среднем.

```java
if (count == items.length) {
    expand();
}
items[count] = item;
count++;
siftUp(count - 1);
```

**Дополнительная память.** `siftUp`, `siftDown` и `poll` используют только несколько локальных переменных — O(1).
`expand()` на время копирования держит два массива — O(n). Сама очередь — массив ёмкостью меньше `2n`, то есть O(n).

## 3. Ручные тесты

12 тестов, у каждого есть `@DisplayName` с описанием на русском.

| Тест | Что проверяет | Граничный случай |
|---|---|---|
| `shouldBeEmptyWhenCreated` | новая очередь пустая, `size() == 0` | пустая очередь |
| `shouldThrowWhenPollFromEmptyQueue` | `poll` на пустой бросает `NoSuchElementException` | пустая очередь |
| `shouldThrowWhenPeekFromEmptyQueue` | `peek` на пустой бросает исключение | пустая очередь |
| `shouldThrowWhenAddingNull` | `add(null)` запрещён, очередь не меняется | null |
| `shouldReturnMinimumOnPeekWithoutRemoving` | `peek` возвращает минимум и не удаляет | — |
| `shouldBecomeEmptyAfterPollingSingleElement` | один элемент → пусто → снова исключение | один элемент |
| `shouldWorkAgainAfterBecomingEmpty` | очередь работает после опустошения | повторное использование |
| `shouldKeepDuplicates` | одинаковые значения не теряются | дубликаты |
| `shouldExpandWhenStartCapacityIsFull` | 9-й элемент вызывает `expand()` (ёмкость 8 → 16) | ровно на границе ёмкости |
| `shouldHandleSortedAndReversedInput` | возрастающий и убывающий ввод | худший случай для `siftUp` |
| `shouldPollElementsInNonDecreasingOrder` | 1000 случайных чисел (с отрицательными) против сортировки | главное требование задачи |
| `shouldUseNaturalOrderForStrings` | работа с `String`, а не только с числами | другой тип данных |

**Почему эти тесты важны.** Пустая очередь и очередь из одного элемента — места, где чаще всего ошибаются
с индексами (`count - 1`, `items[0]`). Тест на 9-й элемент проверяет ровно момент расширения массива.
Убывающий ввод заставляет каждый новый элемент подниматься до самого корня. Случайный тест сравнивает
результат с `Collections.sort`.
