## Условие

Добавить операцию `boolean remove(T item)` — удаление первого вхождения элемента по значению за O(n).
После удаления свойство кучи должно восстанавливаться. Тесты: удаление корня, удаление из середины,
удаление несуществующего элемента, удаление из пустой очереди.

## 1. Идея решения и структура данных

Структура — та же куча на массиве. `RemovablePriorityQueue<T>` наследуется от `ComparatorPriorityQueue<T>`
(задача 1B), поэтому удаление работает и в min-, и в max-куче.

Удаление делается в два этапа:

1. **Поиск** (`find`) — линейный проход по массиву слева направо, сравнение через `equals`.
   Возвращается индекс первого совпадения или `-1`. Ускорить поиск нельзя: куча упорядочена только
   «по вертикали» (родитель ≤ ребёнок), поэтому нужный элемент может оказаться в любой ветке.
2. **Удаление позиции** (`deleteAt` из базового класса):

```java
protected void deleteAt(int index) {
    count--;
    Object last = items[count];
    items[count] = null;
    if (index == count) {
        return;
    }
    items[index] = last;
    siftDown(index);
    if (items[index] == last) {
        siftUp(index);
    }
}
```

На место удалённого элемента ставится последний элемент массива, и последняя ячейка освобождается.
Перенесённый элемент может нарушить порядок в обе стороны:

- он **больше** ребёнка → его нужно опустить (`siftDown`);
- он **меньше** нового родителя (он пришёл из другой ветки) → его нужно поднять (`siftUp`).

Сначала пробуем `siftDown`. Если элемент остался на месте (`items[index] == last`), пробуем `siftUp`.
Отдельный случай — удаление последнего элемента массива: там переносить нечего, поэтому сразу `return`.
Тот же метод `deleteAt(0)` используется в `poll`, поэтому код удаления не дублируется.

## 2. Анализ асимптотики

| Операция | Время | Доп. память |
|---|---|---|
| `find` | O(n) | O(1) |
| `deleteAt` | O(log n) | O(1) |
| `remove` | O(n) | O(1) |
| остальные операции | как в 1A/1B | как в 1A/1B |

### Обоснование кодом

**`find` — O(n).** Один цикл по всем элементам, в худшем случае (элемента нет или он последний) — `n` вызовов `equals`:

```java
for (int i = 0; i < size(); i++) {
    if (item.equals(itemAt(i))) {
        return i;
    }
}
return -1;
```

**`deleteAt` — O(log n).** Перенос последнего элемента — O(1). Затем `siftDown` (не больше `⌊log₂ n⌋` шагов вниз)
и, возможно, `siftUp` (не больше `⌊log₂ n⌋` шагов вверх). Итого O(2 log n) = O(log n).

**`remove` — O(n).** `find` + `deleteAt` = O(n) + O(log n) = **O(n)**, что совпадает с требованием условия.

**Дополнительная память — O(1):** только индексы `i`, `position` и ссылка `last`, новых массивов нет.

## 3. Ручные тесты

11 тестов.

| Тест | Что проверяет | Граничный случай |
|---|---|---|
| `shouldRemoveRoot` | удаление минимума через `remove` | **удаление корня** (из условия) |
| `shouldSiftUpAfterRemovingFromMiddle` | куча `[1, 50, 5, 60, 70, 8, 6]`, удаляем `60`, на его место встаёт `6`, который меньше родителя `50` | **удаление из середины**, нужен `siftUp` |
| `shouldSiftDownAfterRemovingFromMiddle` | куча `[1..7]`, удаляем `2`, на его место встаёт `7` | **удаление из середины**, нужен `siftDown` |
| `shouldRemoveLastElementOfArray` | удаление последней ячейки массива | ветка `index == count` |
| `shouldReturnFalseWhenRemovingMissingElement` | элемента нет → `false`, размер не меняется | **несуществующий элемент** (из условия) |
| `shouldReturnFalseWhenRemovingFromEmptyQueue` | `remove` на пустой очереди | **пустая очередь** (из условия) |
| `shouldReturnFalseWhenRemovingNull` | `remove(null)` → `false` | null |
| `shouldRemoveOnlyFirstOccurrence` | из трёх одинаковых удаляется одно | дубликаты |
| `shouldBecomeEmptyAfterRemovingEverything` | удаление всех элементов по одному | очередь становится пустой |
| `shouldRemoveFromMaxHeap` | удаление корня и элемента из max-кучи | другой компаратор |
| `shouldKeepOrderAfterRandomRemovals` | 200 случайных удалений сверяются с `ArrayList.remove` | большой набор |

**Почему эти тесты важны.** Тесты из середины кучи подобраны так, чтобы один требовал `siftDown`, а другой — `siftUp`.
Я проверил: если убрать вызов `siftUp` из `deleteAt`, тест `shouldSiftUpAfterRemovingFromMiddle` падает.
Тест со случайными удалениями сверяет и возвращаемое `true/false`, и итоговый порядок со стандартным списком.
