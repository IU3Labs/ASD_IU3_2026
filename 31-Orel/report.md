## Идея решения и выбор структуры данных

Очередь с приоритетом реализована как **двоичная куча в массиве**. Куча — полное двоичное дерево, в котором
каждый родитель не больше своих детей; поэтому минимум всегда в корне. Полное дерево без пропусков удобно
хранить в массиве без указателей: дети узла `i` — `2i + 1` и `2i + 2`, родитель — `(i − 1) / 2`.

Почему массив, а не дерево из узлов или отсортированный список:

* **отсортированный массив/список** даёт `poll` за O(1), но `add` за O(n) — надо сдвигать элементы;
* **дерево из узлов** даёт те же O(log n), но тратит память на ссылки и плохо ложится в кэш процессора;
* **куча в массиве** даёт O(log n) на `add`/`poll`, O(1) на `peek` и хранит только сами элементы.

Ключевые решения:

* **Порядок через `Comparator` (1B).** Сравнение всех элементов идёт через один метод `compare(i, j)`: если
  компаратор задан — вызывается он, иначе элементы приводятся к `Comparable`. Поэтому один и тот же код
  работает как min-heap (`naturalOrder()` или без компаратора) и как max-heap (`reverseOrder()`).
* **Расширение массива.** Начальная ёмкость 16, при заполнении — удвоение через `System.arraycopy`.
  Суммарно на n вставок копируется не более 2n элементов, так что амортизированно рост стоит O(1).
* **Удаление (1C) и `poll` — один общий метод `removeAt(index)`.** На место удаляемого ставится последний
  элемент. Он пришёл из другой ветви дерева, поэтому может нарушать порядок в любую сторону: сначала
  вызывается `siftDown`, а если элемент не сдвинулся — `siftUp`. Для `poll` (`index = 0`) работает только
  `siftDown`.
* **Построение за O(n) (1D).** Массив копируется как есть, затем `siftDown` вызывается для узлов
  от последнего внутреннего (`size / 2 − 1`) до корня. Листья — уже кучи из одного элемента.
* **`peek` на пустой очереди** бросает `NoSuchElementException`, как и `poll` (условие этого не уточняет;
  так ошибка не маскируется возвратом `null`).
* **`null` запрещён** (`NullPointerException`): его нельзя сравнить, и он неотличим от пустой ячейки.
  Элемент без `Comparable` при отсутствии компаратора отклоняется сразу при вставке (`ClassCastException`).
* **Освобождение ссылок.** После удаления освободившаяся ячейка обнуляется, иначе удалённый объект
  не смог бы собрать сборщик мусора.

## Анализ асимптотики

Пусть n — число элементов, h = ⌊log₂ n⌋ — высота кучи.

| Операция | Время | Доп. память | Обоснование |
|----------|-------|-------------|-------------|
| `add` | O(log n), амортизированно | O(1) аморт. | `siftUp` поднимается не выше корня: ≤ h шагов по 1 сравнению; расширение — см. ниже |
| `poll` | O(log n) | O(1) | `siftDown` опускается не ниже листа: ≤ h шагов по 2 сравнения |
| `peek`, `size`, `isEmpty` | O(1) | O(1) | чтение `heap[0]` / поля `size` |
| `remove(item)` | O(n) | O(1) | линейный поиск ≤ n сравнений `equals` + O(log n) на `siftDown`/`siftUp` |
| конструктор из массива | O(n) | O(n) | копия массива O(n) + heapify O(n), см. ниже |
| хранение очереди | — | O(n) | массив ёмкостью от n до 2n ссылок |

**Почему `remove` — O(n).** Куча упорядочивает только пары «родитель — потомок», между ветвями порядка нет,
поэтому значение нельзя искать бинарным поиском и приходится просматривать массив целиком.

**Амортизация роста.** Массив удваивается при размерах 16, 32, 64, …, до n. Суммарно копируется
16 + 32 + … + n/2 + n < 2n элементов, т.е. в среднем ≤ 2 копирования на вставку — O(1). Худший отдельный
`add` (с расширением) стоит O(n), но такое случается только при размерах, равных степени двойки.

**Почему построение из массива — O(n), а не O(n log n).** `siftDown` узла на высоте k стоит O(k).
В полной куче узлов на высоте k не больше ⌈n / 2^(k+1)⌉, поэтому общая работа

```
T(n) ≤ Σ (k = 0..h) n / 2^(k+1) · k  =  (n / 2) · Σ k / 2^k  ≤  (n / 2) · 2  =  n
```

(ряд Σ k / 2^k сходится к 2). С учётом двух сравнений на шаг — не более 2n сравнений. Это подтверждают
и тест `shouldUseLinearNumberOfComparisons`, и замер: при n = 100 000 конструктор сделал 199 978 сравнений,
а 100 000 последовательных `add` на убывающем массиве — 1 468 946 ≈ n · log₂ n.

## Тесты

Всего 48 тестов JUnit 5 (не менее 10 на каждую задачу). Тесты проходят по всем строкам `PriorityQueueCustom`,
кроме `return false` в служебном методе `isValidHeap` — он срабатывает только при ошибке в самой куче.
Точные проценты покрытия — в отчёте JaCoCo `31-Orel/target/site/jacoco/index.html` после `mvn test`
(требование курса — не менее 80 %).

Граничные случаи и почему они важны:

| Тест | Что проверяет |
|------|---------------|
| `shouldThrowWhenPollingEmptyQueue`, `shouldThrowWhenPeekingEmptyQueue` | пустая очередь не возвращает мусор, а сообщает об ошибке |
| `shouldReturnSingleElement`, `shouldRemoveOnlyElement` | куча из одного узла: у корня нет детей и родителя |
| `shouldGrowBeyondInitialCapacity` | расширение массива сохраняет все элементы и свойство кучи |
| `shouldKeepAllDuplicates`, `shouldRemoveOnlyFirstOccurrenceOfDuplicate` | равные элементы не теряются, `remove` удаляет ровно одно вхождение |
| `shouldRemoveRoot`, `shouldRemoveMiddleElement`, `shouldReturnFalseForNonexistentElement`, `shouldReturnFalseWhenRemovingFromEmptyQueue` | обязательные случаи из условия 1C |
| `shouldSiftUpWhenMovedElementIsSmallerThanNewParent` | редкая ветка `remove`, когда перенесённый элемент надо поднимать, а не опускать |
| `shouldWorkAsMaxHeapWithReversedComparator`, `shouldGiveOppositeOrdersForMinAndMaxHeapsOnSameData` | оба режима 1B на одних данных |
| `shouldNotModifySourceArray` | конструктор 1D копирует массив, а не портит исходный |
| `shouldUseLinearNumberOfComparisons` | построение из 100 000 элементов делает ≤ 2n сравнений — асимптотика O(n) проверена автоматически |
| `shouldMatchStandardPriorityQueueOnRandomOperations` | 20 000 случайных `add`/`poll` дают тот же результат, что `java.util.PriorityQueue` |
| `shouldKeepHeapValidAfterRandomRemovals` | после каждого из 1 000 случайных удалений свойство кучи выполняется |

Пример ручной проверки (можно выполнить в IDEA через *Evaluate Expression* или в `jshell`):

```java
PriorityQueueCustom<Integer> q = new PriorityQueueCustom<>(new Integer[] {5, 3, 8, 1});
q.poll();       // 1
q.remove(8);    // true
q.poll();       // 3
q.poll();       // 5
q.isEmpty();    // true
```

Этот пример за несколько строк проходит все ветки: построение из массива, `poll` из корня,
`remove` листа и опустошение очереди.
