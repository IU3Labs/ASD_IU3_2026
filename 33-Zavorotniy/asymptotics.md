# Расчёт асимптотики

## PriorityQueueCustom

Пусть `n` — текущий размер кучи, `C` — длина её массива. Стоимость одного сравнения или
проверки равенства принимается за `O(1)`.

| Операция | Время | Дополнительная память |
|---|---|---|
| `add` | `O(log n)` амортизированно, `O(n)` при расширении | `O(1)` без расширения, `O(C)` при расширении |
| `poll` | `O(log n)` | `O(1)` |
| `peek` | `O(1)` | `O(1)` |
| `remove` | `O(n)` | `O(1)` |
| `size`, `isEmpty` | `O(1)` | `O(1)` |

У заполненного слева двоичного дерева высота `⌊log₂ n⌋`. Каждое просеивание проходит
один путь по дереву, поэтому выполняет `O(log n)` сравнений. При удалении по значению
сначала идёт просмотр до `n` элементов, затем одно просеивание. Суммарно получается
`O(n + log n) = O(n)`.

Массив удваивается при заполнении. За `m` вставок в пустую очередь число
скопированных ссылок ограничено геометрической суммой `16 + 32 + … + C/2 < C = O(m)`.
Копирование добавляет амортизированное `O(1)` к вставке. Очередь хранит `O(C)` ссылок,
а ёмкость определяется пиковым размером. Освободившиеся позиции обнуляются.

## HashMapCustom

Пусть `n` — число живых пар, `C` — ёмкость. Считаем `hashCode` и `equals` операциями
за `O(1)`. Ожидаемые оценки предполагают хорошо распределённые хеш-коды.

| Операция | Ожидаемое время | Худшее время | Дополнительная память |
|---|---|---|---|
| `put` | `O(1)` амортизированно | `O(C)` без перехеширования, `O(C + n²)` с ним | `O(1)` без перехеширования, `O(C)` с ним |
| `get`, `containsKey`, `remove` | `O(1)` | `O(C)` | `O(1)` |
| `size`, `capacity` | `O(1)` | `O(1)` | `O(1)` |

При линейном пробировании каждая следующая проверка переходит на одну ячейку с
циклическим возвратом к началу. Живые пары занимают не более `3C/4` ячеек, а живые пары
вместе с метками удаления — не более `7C/8`. Поиск завершается на совпадении или
на первой ячейке, в которой нет ни ключа, ни метки.

Перехеширование просматривает `C` ячеек и повторно вставляет `n` пар. При хорошем
распределении это `O(C + n) = O(C)`. При одинаковых хешах на повторные вставки
уходит до `1 + 2 + … + n = O(n²)` проб. Ёмкость удваивается при превышении порога
`3/4`. После роста до текущей ёмкости до следующего удвоения нужно добавить
как минимум `3C/8` живых ключей. Очистка меток без удвоения выполняется только
при наличии хотя бы `C/8` меток, для накопления которых нужны удаления.
Поэтому ожидаемая стоимость перехеширований амортизируется на последовательности
операций.

Таблица хранит два массива длины `C` и одну общую метку удаления. Память — `O(C)`.
При удалении ссылки на ключ и значение освобождаются, ёмкость сохраняется.
