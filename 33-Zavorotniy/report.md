# Отчёт по лабораторной работе № 2

**Заворотний Никита Игоревич, ИУ3-33Б**

## Очередь с приоритетом (1A, 1C)

Двоичная min-куча хранится в расширяемом массиве. Минимум находится в позиции 0.
После вставки элемент просеивается вверх. При извлечении минимума последний
элемент переносится в корень и просеивается вниз. Чтобы удалить произвольное
значение, просматриваем массив до первого совпадения по `equals`, переносим
на его место последний элемент и выбираем направление просеивания по отношению
к новому родителю.

Вставка занимает `O(log n)` амортизированно, извлечение — `O(log n)`,
удаление по значению — `O(n)`. Размер, проверка пустоты и просмотр минимума
выполняются за `O(1)`. Для пустой очереди `poll` бросает `NoSuchElementException`,
а `peek` возвращает `null`. Массив занимает `O(C)` памяти.

## Хеш-таблица (2A)

Выбор ячейки начинается с `abs(hashCode) % capacity`. Модуль вычисляется
после преобразования к `long`, чтобы обработать `Integer.MIN_VALUE`. При коллизии
проверяем следующие ячейки. Маркер `DELETED` сохраняет цепочку поиска после удаления
и позволяет повторно использовать освобождённое место. Вставка сначала ищет
сам ключ, даже если уже встретилась метка, чтобы обновление не создало дубликат.

Если новая пара заполнит больше 75% ячеек, таблица удваивает ёмкость
и перехеширует живые пары. Когда ключи и метки занимают 7/8 ячеек, перед
вставкой в ещё не использованную ячейку таблица очищает метки с сохранением
ёмкости. Ключи должны быть ненулевыми. Значение `null` разрешено, наличие пары
с таким значением проверяется через `containsKey`.

При хорошо распределённых хешах поиск, удаление и проверка наличия занимают
`O(1)` в среднем, вставка — ожидаемое амортизированное `O(1)`. Хранение
двух массивов требует `O(C)) памяти. Худшие случаи разобраны в
[расчёте асимптотики](asymptotics.md).

## Ручная проверка

| Сценарий | Ожидаемый результат | Что проверяется |
|---|---|---|
| Добавить в кучу `4, 1, 3, 1`, вызвать `peek`, затем извлечь все элементы | `peek → 1`, размер остаётся 4. Извлечение даёт `1, 1, 3, 4` | Порядок, дубликаты и чтение без удаления |
| Добавить `1, 10, 2, 12, 13, 3, 4` и удалить `12` | Извлечение даёт `1, 2, 3, 4, 10, 13` | Последний элемент `4` после замены должен подняться над `10` |
| При ёмкости 16 вставить ключи `15, 31, 47`, удалить `15`, обновить `47` | `31` и `47` доступны, размер равен 2 | Пробирование с переходом через край и обновление за меткой удаления |
| Вставить 12 разных ключей, обновить существующий ключ, затем вставить 13-й | При обновлении ёмкость остаётся 16. После вставки 13-го ключа ёмкость равна 32 | Порог роста и сохранение данных при переносе |
