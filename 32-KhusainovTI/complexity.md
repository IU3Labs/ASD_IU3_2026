# Анализ асимптотики ЛР2, 1A–1D

Обозначения: n — число элементов, C — ёмкость массива. Предполагается, что одно сравнение,
`equals` и копирование ссылки выполняются за O(1).

| Метод | Время | Дополнительная память операции |
|---|---|---|
| Пустой конструктор, с компаратором или без | O(1) | O(1), начальная ёмкость 16 |
| Конструктор из массива, с компаратором или без | O(n) | O(n), собственная копия массива |
| add без расширения | O(log n) | O(1) |
| add с расширением | O(n) в этой операции | O(n) под новый массив |
| add по последовательности вставок | O(log n) амортизированно | O(n) на хранение очереди |
| poll | O(log n) | O(1) |
| peek, size, isEmpty | O(1) | O(1) |
| remove | O(n) | O(1) |

## Куча и просеивания

Для узла i дети имеют индексы 2i+1 и 2i+2, родитель — (i−1)/2.
Каждый переход siftUp/siftDown меняет глубину на один уровень. Высота полного двоичного дерева
равна O(log n), поэтому каждое просеивание выполняет O(log n) сравнений.
Вершина всегда хранится в `elements[0]`, размер — в отдельном поле.

## Расширение и требование add

При заполнении ёмкость удваивается. За m вставок суммарно копируется не более
16 + 32 + 64 + … + O(m) = O(m) ссылок. Амортизированная стоимость расширения — O(1),
а вставки с просеиванием — O(log n).
Строгое O(log n) **в худшем случае каждой отдельной вставки** несовместимо с обычным
расширяемым непрерывным массивом: вставка, вызвавшая копирование, требует O(n).
Поэтому требование 1A трактуется как амортизированная оценка, с явным указанием этого ограничения.

## Удаление

Последовательный просмотр массива в поисках первого `equals` требует O(n).
На его место переносится последний элемент; если он меньше родителя по компаратору,
выполняется siftUp, иначе siftDown. Это достаточно, поскольку до замены все остальные
рёбра удовлетворяли свойству кучи. Итог — O(n) + O(log n) = O(n).
Старая последняя ячейка обнуляется: удалённый объект больше не удерживается очередью.

## Bottom-up heapify

Листья уже являются кучами. Идём от последнего внутреннего узла n/2−1 к нулю,
просеивая каждый узел вниз в уже построенные дочерние кучи.
Узлов высоты h не более O(n/2^h), работа одного просеивания — O(h).
Общая работа ограничена O(n) · Σ(h/2^h) = O(n), поскольку ряд сходится.
Копирование и проверка входных элементов также линейны.

Последовательные add имеют худшую суммарную стоимость O(n log n):
для убывающего входа каждый новый минимум поднимается до корня.
Для случайного входа среднее число подъёмов мало, поэтому различие времён с heapify
может быть небольшим; эксперимент содержит оба набора.

## Память

Хранится один Object[] из C ссылок, размер и компаратор: O(C) памяти.
Для последовательных вставок C = O(max(16, n)), запас после удвоения меньше примерно n ссылок.
Во время расширения одновременно существуют старый и новый массивы, всё ещё O(n) памяти.
Автоматического уменьшения нет: после удалений память пропорциональна достигнутой ёмкости,
а не текущему числу элементов. Объекты элементов и компаратор дополнительно не копируются.
