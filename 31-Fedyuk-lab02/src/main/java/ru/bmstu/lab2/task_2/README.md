# Задачи 2A и 2C. Хеш-таблица и коллизии

Идея: два массива ключей и значений, линейное пробирование и DELETED вместо пустой
ячейки при удалении. Загрузка живыми записями ограничена 0.75; ёмкость удваивается.
Отдельный порог 7/8 учитывает удалённые ячейки и запускает очистку без роста.

Время: ожидаемо O(1) на get/containsKey/remove и амортизированно O(1) на put при
хорошем распределении. Худший поиск — O(C), перехеширование при коллизиях — O(C²).
size и capacity работают за O(1).

Память: O(C), C — ёмкость. Уменьшения ёмкости после удаления нет.

CollisionKey — строковая обёртка с одним хешем для всех строк. Десять тысяч таких
ключей проверяются на вставку, поиск и удаление. Время ухудшается из-за длинной цепочки,
но equals и DELETED обеспечивают корректность.

Пример: два различных CollisionKey("a") равны и обновляют одну запись;
CollisionKey("b") имеет тот же хеш, но представляет другую запись.
Null-ключи запрещены, null-значения разрешены.
