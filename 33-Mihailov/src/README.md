# Задача 2C. Искусственные коллизии

Для проверки коллизий используется `LabaTask2C_CollisionKey`: класс хранит строку, а метод `hashCode()` для любого ключа возвращает число `17`. Метод `equals()` при этом сравнивает строки, поэтому ключи с одинаковыми хешами не считаются одинаковыми.

В тесте `tenThousandCollisions` в собственную хеш-таблицу добавляются 10 000 разных ключей. После вставки проверяются количество и значения всех элементов, затем все ключи удаляются. Проверка подтверждает, что коллизии не приводят к потере данных.

## Сравнение времени

| Тип ключей | Количество | Вставка, поиск и удаление (мс) |
|---|---:|---:|
| Строки с обычным хешем | 1 000 | 1.852 |
| Ключи с одинаковым хешем | 1 000 | 9.802 |
| Строки с обычным хешем | 10 000 | 7.041 |
| Ключи с одинаковым хешем | 10 000 | 857.566 |

При одинаковых хешах новые ключи попадают в одну область таблицы. Линейное пробирование вынуждено последовательно просматривать всё больше занятых ячеек. Поэтому операции, которые обычно выполняются в среднем за O(1), в худшем случае требуют O(n). На 10 000 элементов разница во времени особенно заметна.
