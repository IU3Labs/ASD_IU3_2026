## PriorityQueueCustom&lt;T&gt; (1A–1D)

Двоичная куча на массиве `Object[]`: дети узла `i` — `2*i + 1` и `2*i + 2`, родитель — `(i - 1) / 2`.
На вершине — минимальный по компаратору элемент.

| Операция | Сложность | Комментарий |
|---|---|---|
| `PriorityQueueCustom()` | O(1) | естественный порядок (min-куча) |
| `PriorityQueueCustom(Comparator<? super T>)` | O(1) | `null` — естественный порядок; `reverseOrder()` — max-куча |
| `PriorityQueueCustom(T[] array)` / `(T[], Comparator)` | O(n) | построение просеиванием вниз (1D) |
| `add(T item)` | O(log n) амортизированно | вставка в конец + `siftUp`; при заполнении массив удваивается |
| `poll()` | O(log n) | последний элемент на место корня + `siftDown`; пустая — `NoSuchElementException` |
| `peek()` | O(1) | пустая — `NoSuchElementException` |
| `remove(T item)` | O(n) | линейный поиск по `equals` + восстановление за O(log n) (1C) |
| `size()`, `isEmpty()` | O(1) | |

Ключевые решения:

- **Компаратор хранится всегда.** Без явного компаратора подставляется лямбда, сравнивающая через
  `Comparable`, поэтому в `siftUp`/`siftDown` нет ветвления «есть компаратор или нет». Min- и max-куча —
  один и тот же код, отличается только компаратор (1B).
- **Просеивание сдвигом, а не обменом.** Перемещаемый элемент запоминается, родители/дети сдвигаются
  на его место, а сам он записывается один раз в конечную позицию — вдвое меньше записей в массив.
- **Расширение массива** в 2 раза через `Arrays.copyOf` — амортизированно O(1) на `add`.
- **`remove` из середины.** На место удалённого ставится последний элемент. Он может нарушить порядок
  в любую сторону: сначала `siftDown`, и если элемент не сдвинулся — `siftUp` (он может оказаться меньше
  нового родителя). Удаление последнего элемента массива ничего не восстанавливает.
- **Построение за O(n) (1D).** Массив копируется (исходный не меняется), затем `siftDown` для узлов
  от `size / 2 - 1` до `0`: листья уже являются кучами. Суммарная работа `Σ (высота узла) = O(n)`.
- **`null` запрещён** (`NullPointerException` в `add` и в конструкторе из массива): иначе `null` в массиве
  был бы неотличим от пустой ячейки и ломал бы сравнения. `remove(null)` просто возвращает `false`.
- Освободившаяся ячейка обнуляется, чтобы куча не удерживала ссылки на извлечённые объекты.

## HashMapCustom&lt;K, V&gt; (2A)

Открытая адресация с линейным пробированием: ключи и значения лежат в двух параллельных массивах,
при коллизии проверяется следующая ячейка `(index + 1) % capacity`.

| Операция | Сложность | Комментарий |
|---|---|---|
| `HashMapCustom()` / `HashMapCustom(int)` | O(capacity) | по умолчанию ёмкость 16 |
| `put(K, V)` | O(1) в среднем, амортизированно | обновляет значение, если ключ уже есть |
| `get(K)` | O(1) в среднем | значение или `null` |
| `containsKey(K)` | O(1) в среднем | |
| `remove(K)` | O(1) в среднем | ставит маркер `DELETED` |
| `size()`, `capacity()` | O(1) | |
| перехеширование | O(capacity) | при превышении загрузки |

Худший случай всех операций — O(n) (все ключи в одной цепочке), он проверен тестом с одинаковым `hashCode`.

Ключевые решения:

- **Хеш-функция** `Math.abs(key.hashCode()) % capacity`. `Math.abs(Integer.MIN_VALUE)` остаётся
  отрицательным, поэтому отрицательный остаток сдвигается на `+ capacity` (тест `shouldHandleMinValueHashCode`).
- **Маркер `DELETED`** — отдельный объект-синглтон в массиве ключей. Поиск проходит через него дальше,
  останавливаясь только на пустой ячейке (`null`), поэтому удаление в середине цепочки не теряет ключи после него.
- **`put` сначала ищет ключ по всей цепочке**, и только если его нет — вставляет в первую свободную
  ячейку (пустую или `DELETED`). Так удалённые ячейки переиспользуются, а ключ не задваивается,
  если он стоит в цепочке дальше маркера.
- **Загрузка не более 0.75.** Перед вставкой нового ключа:
  если `size + 1 > 0.75 · capacity` — ёмкость удваивается с перехешированием;
  если превышение только за счёт маркеров (`size + deleted + 1 > 0.75 · capacity`) — перехеширование
  в ту же ёмкость, которое очищает маркеры. В итоге в таблице всегда есть ≥ 25% пустых ячеек,
  поиск гарантированно завершается, а многократные `put`/`remove` не раздувают таблицу.
- **Ключ `null` запрещён** в `put` (`NullPointerException`), в `get`/`containsKey`/`remove` он просто
  «не найден». Значения `null` разрешены — отличить их от отсутствия ключа можно через `containsKey`.

## TopK.topK (3A)

`List<T> topK(List<T> input, int k)` (и перегрузка с `Comparator`) — **O(n log k)** по времени, **O(k)** памяти.

- Используется min-куча `PriorityQueueCustom` размера не больше k: на вершине — худший из текущих лучших.
  Пока куча не заполнена — `add`; дальше элемент заменяет вершину (`poll` + `add`), только если он больше её.
- Результат — неизменяемый список (`List.of`) в порядке невозрастания: элементы извлекаются из кучи
  по возрастанию и записываются в массив с конца.
- Границы: `k = 0` или пустой вход — пустой список; `k > n` — все элементы по убыванию;
  `k < 0` — `IllegalArgumentException`; `null` в списке — `NullPointerException`.
- Вход читается через итератор, поэтому для `LinkedList` тоже O(n log k), а не O(n²).
- Проверка: совпадение с «сортировка по убыванию + первые k», в том числе на 1 000 000 элементов.

## SlidingMinimum.slidingMin (3D)

`int[] slidingMin(int[] arr, int k)` — **O(n log n)** по времени, **O(n)** памяти в худшем случае.

- В min-куче лежат пары `Entry(value, index)` (приватный `record`), упорядоченные по значению.
- **Ленивое удаление:** элементы, вышедшие из окна, не ищутся в куче (это было бы O(n)). Вместо этого перед
  ответом с вершины снимаются записи, у которых `index < i - k + 1`. Каждый элемент добавляется
  и извлекается не больше одного раза — всего O(n log n).
- Худший случай по памяти — убывающий массив: минимум всегда самый новый, старые записи не всплывают
  на вершину и копятся в куче (до n штук).
- Ответ имеет длину `n - k + 1`; `k` вне `[1, n]` (в том числе пустой массив) — `IllegalArgumentException`.
- Проверка: совпадение с перебором O(n · k) на 200 000 элементах с окном 1 000.
