# ЛР №2, задача 2A — расчёт асимптотики

**Бабкин Дмитрий Витальевич, ИУ3-33Б**

Пусть `n` — число действующих записей, `C` — ёмкость, `hashCode` и
`equals` работают за `O(1)`. При равномерном распределении хешей и
ограниченной загрузке ожидаемая длина пробирования равна `O(1)`. Длинная
цепочка коллизий и удалённых ячеек может потребовать до `O(C)` шагов.

| Операция | Ожидаемое время | Худший случай |
|---|---|---|
| Пустой конструктор | `O(1)` | `O(1)` |
| `get`, `containsKey`, `remove` | `O(1)` | `O(C)` |
| `put` без перестроения | `O(1)` | `O(C)` |
| `put` с перестроением | `O(C)` для одной операции, `O(1)` амортизированно | `O(C + n²)` |
| `size`, `capacity` | `O(1)` | `O(1)` |

Перестроение сканирует старый массив и переносит оставшиеся записи.
Если ключи попадают в один кластер, повторные вставки при перестроении
могут потребовать `1 + 2 + … + n = Θ(n²)` проб. При равномерных хешах
ожидаемая стоимость перестроения линейна по ёмкости.

После удвоения загрузка падает примерно до 3/8, и до следующего удвоения
нужны `Ω(C)` вставок. После очистки маркеров заполнено не более `3C/4`
ячеек, а очистка повторится только после заполнения хотя бы `C/8`
ранее свободных ячеек. Поэтому ожидаемая стоимость перестроений вносит
`O(1)` амортизированного времени на вставку.

Два массива требуют `Θ(C)` памяти. При перестроении одновременно существуют
старые и новые массивы, поэтому пиковая память тоже `Θ(C)`. Удаление
освобождает ссылки на ключ и значение, ёмкость сохраняется.
