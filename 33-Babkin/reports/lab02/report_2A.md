# ЛР №2, задача 2A — Хеш-таблица с линейным пробированием

**Бабкин Дмитрий Витальевич, ИУ3-33Б**

## Реализация

`HashMapCustom<K, V>` хранит ключи и значения в параллельных массивах.
Начальный индекс вычисляется как `abs(hashCode) % capacity`. Перед
`Math.abs` хеш приводится к `long`, чтобы обработать `Integer.MIN_VALUE`.
При коллизии поиск переходит к следующей ячейке и при необходимости
продолжается с начала массива.

Удаление ставит маркер `DELETED` и очищает ссылку на значение. Поиск
проходит за маркер, а вставка запоминает первую удалённую ячейку и
продолжает поиск ключа. Если записи ещё нет, ячейка используется повторно.
При добавлении записи сверх загрузки 0,75 таблица удваивается и действующие
записи перехешируются. Если занятые ячейки вместе с маркерами достигли 7/8
ёмкости и для вставки нужна свободная ячейка, перестроение при той же
ёмкости удаляет накопившиеся маркеры. Поэтому пробирование всегда может
завершиться на свободной ячейке.

Ключ `null` отклоняется. Значение `null` разрешено, наличие соответствующей
записи определяет `containsKey`.

## Ручная проверка

При начальной ёмкости 16 вставить ключи `15`, `31` и `47` со значениями
`10`, `20` и `30`. Удалить `15`, затем обновить значение ключа `47`
до `99`. Должны выполняться `get(47) = 99`, `containsKey(15) = false`
и `size() = 2`. Пример проверяет переход через конец массива, поиск за
маркером и обновление ключа без создания дубликата.

`HashMapCustomTest` включает проверку границы загрузки, повторного
перехеширования, коллизий и сравнение со стандартной таблицей.
Запуск проверок из корня проекта — `mvn clean verify`.
