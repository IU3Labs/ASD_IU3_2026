# ЛР №2, задача 1A — Очередь с приоритетом

**Бабкин Дмитрий Витальевич, ИУ3-33Б**

## Реализация

`PriorityQueueCustom<T>` хранит двоичную min-heap в расширяемом массиве.
Для узла с индексом `i` дети находятся по индексам `2i + 1` и `2i + 2`,
а родитель при `i > 0` — по индексу `(i - 1) / 2`. Элементы сравниваются
в естественном порядке.

`add` помещает элемент в конец и поднимает его через `siftUp`.
`poll` заменяет корень последним элементом, очищает освободившуюся ячейку
и опускает новый корень через `siftDown`, выбирая меньшего ребёнка.
После каждого просеивания родитель не больше ни одного из своих детей,
поэтому при последовательном извлечении элементы идут по неубыванию.
Массив удваивается при заполнении.

## Ручная проверка

1. Вставить `7, -2, 7, 0`. Два вызова `peek()` должны вернуть `-2`,
   размер должен остаться равным 4.
2. Извлечь все элементы. Ожидаемый порядок — `-2, 0, 7, 7`. Пример проверяет
   просеивания, отрицательные значения и сохранение дубликатов.
3. В пустой очереди `peek()` возвращает `null`, `poll()` бросает
   `NoSuchElementException`. Вставка `null` отклоняется.

`PriorityQueueCustomTest` проверяет рост массива и сравнивает порядок
извлечения с `java.util.PriorityQueue`. Запуск проверок из корня проекта —
`mvn clean verify`.
