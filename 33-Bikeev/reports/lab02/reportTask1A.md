# Задача 1A. Базовая очередь с приоритетом

Лабораторная работа № 2.

Стоимость задачи: 2 балла.

## Условие

Реализовать `PriorityQueueCustom<T>` на динамическом массиве со следующими операциями:

- `add(T item)` — добавить элемент;
- `poll()` — извлечь и вернуть минимальный элемент;
- `peek()` — получить минимальный элемент без удаления;
- `size()` — получить количество элементов;
- `isEmpty()` — проверить, пуста ли очередь.

При извлечении из пустой очереди необходимо выбрасывать `NoSuchElementException`.
Массив должен автоматически расширяться при заполнении.
Элементы должны извлекаться в порядке неубывания.

## Идея решения

Используется двоичная минимальная куча.

Для каждого узла значение родителя не больше значений его детей.
Поэтому минимальный элемент находится в корне.
При этом весь массив не обязан быть полностью отсортирован.

Куча хранится в собственном массиве `Object[] elements`.
Готовые реализации коллекций для хранения очереди не используются.

Активные элементы занимают позиции от `0` до `size - 1`.
Корень находится по индексу `0`.

Для узла с индексом `i`:

- левый ребёнок имеет индекс `2 * i + 1`;
- правый ребёнок имеет индекс `2 * i + 2`;
- родитель имеет индекс `(i - 1) / 2`, если `i > 0`.

Начальная ёмкость массива равна 16.

### Добавление элемента

Метод `add` проверяет допустимость элемента и наличие свободного места.

Если массив заполнен, создаётся массив удвоенной ёмкости.
Имеющиеся ссылки копируются в новый массив.

Затем новый элемент помещается в конец активной части массива.
Приватный метод `siftUp` поднимает его вверх, пока свойство кучи не восстановится.

### Извлечение минимального элемента

Метод `poll` сохраняет значение корня.

Последний элемент переносится на место корня, а размер очереди уменьшается.
Приватный метод `siftDown` опускает замену вниз, каждый раз выбирая меньшего ребёнка.

Освободившаяся последняя ячейка обнуляется, чтобы за пределами активной части
массива не сохранялись лишние ссылки.

При вызове `poll` для пустой очереди выбрасывается `NoSuchElementException`.

### Остальные операции

Метод `peek` возвращает элемент с индексом `0` без удаления.
Для пустой очереди возвращается `null`.

Метод `size` возвращает значение поля `size`.
Метод `isEmpty` проверяет условие `size == 0`.

Добавление `null` запрещено и приводит к `NullPointerException`.
Благодаря этому результат `null` у метода `peek` однозначно означает пустую очередь.

## Обоснование выбора структуры

Двоичная куча позволяет поддерживать минимальный элемент в корне
и восстанавливать порядок после изменения за число шагов, ограниченное её высотой.

В обычном неотсортированном массиве поиск минимума потребовал бы просмотра
всех элементов, то есть `O(n)` времени.

## Асимптотическая сложность

Пусть `n` — текущее количество элементов, а `C` — ёмкость внутреннего массива.
Стоимость одного сравнения элементов считается равной `O(1)`.

Высота двоичной кучи составляет `O(log n)`.
Методы `siftUp` и `siftDown` перемещаются вдоль одного пути дерева,
поэтому выполняют не более `O(log n)` шагов.

| Операция | Время | Дополнительная память сверх существующего массива |
|---|---|---|
| `add` без расширения массива | `O(log n)` | `O(1)` |
| `add` с расширением массива | `O(n)` | `O(n)` |
| `add`, амортизированная оценка | `O(log n)` | `O(1)` без расширения; `O(n)` в момент расширения |
| `poll` | `O(log n)` | `O(1)` |
| `peek` | `O(1)` | `O(1)` |
| `size` | `O(1)` | `O(1)` |
| `isEmpty` | `O(1)` | `O(1)` |

### Почему добавление имеет амортизированную оценку

При заполнении массива его ёмкость увеличивается геометрически:
`16, 32, 64, 128, ...`.

За `m` последовательных вставок в изначально пустую очередь суммарное число
скопированных ссылок составляет `O(m)`, поскольку сумма предыдущих ёмкостей
ограничена геометрической прогрессией.

Следовательно, расширение добавляет `O(1)` амортизированного времени на вставку.
С учётом просеивания вверх операция `add` занимает `O(log n)` амортизированно.

Отдельный вызов `add`, при котором копируются `n` ссылок, занимает `O(n)`.
Поэтому требование `O(log n)` для добавления при использовании расширяемого
массива выполняется в амортизированном смысле.

### Использование памяти

Очередь занимает `O(C)` памяти для хранения ссылок.

После удаления элементов массив не сжимается.
Поэтому его ёмкость зависит от максимального достигнутого размера очереди,
а не только от текущего количества элементов.

Если `n_max` — максимальный размер за время существования очереди,
то память под массив составляет `O(max(1, n_max))`.

Отсутствие сжатия позволяет выполнять `poll` без линейного копирования массива.
Сами объекты элементов очередь не копирует.

## Автоматические тесты

В классе `PriorityQueueBaseTest` реализовано 11 тестов JUnit 5.

Проверяются:

- начальное состояние пустой очереди;
- исключение при извлечении из пустой очереди;
- просмотр элемента без удаления;
- правильный порядок извлечения после добавления убывающей последовательности;
- отрицательные значения и границы типа `Integer`;
- сохранение повторяющихся элементов;
- расширение массива при добавлении 2048 элементов;
- чередование добавлений и извлечений;
- запрет добавления `null` с сохранением прежнего содержимого;
- естественный порядок строк;
- повторное использование очереди после полного опустошения.

Результат запуска этого класса: 11 тестов, 0 ошибок, 0 неуспешных проверок,
0 пропусков.

## Производительность

В программе `PriorityQueueBenchmark` собственная очередь сравнивается
со стандартной `java.util.PriorityQueue`.

Для каждого размера — 10 000, 50 000 и 100 000 элементов — измеряется полный цикл:
добавление всех элементов и последующее извлечение всех элементов.

Подготовка входных данных и проверка правильности результата выполняются
вне измеряемого интервала. Перед основными измерениями выполняется прогрев.

Таблицы фактически полученных значений, параметры среды, методика
и выводы приведены в [benchmarks.md](benchmarks.md).

## Вывод

Реализована очередь с приоритетом на собственном динамическом массиве
с использованием двоичной минимальной кучи.

Последовательное извлечение возвращает элементы в неубывающем порядке.
Получение минимума, размера и проверка пустоты выполняются за `O(1)`.
Извлечение занимает `O(log n)`, добавление — `O(log n)` амортизированно.

Корректность базовых операций подтверждена 11 автоматическими тестами.
