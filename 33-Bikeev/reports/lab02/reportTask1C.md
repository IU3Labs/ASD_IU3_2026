# Задача 1C. Удаление элемента по значению

Лабораторная работа № 2.

Стоимость задачи: 2 балла.

## Условие

Добавить в очередь с приоритетом операцию:

```text
boolean remove(T item)
```

Операция должна удалять первое вхождение заданного значения за O(n).
После удаления необходимо восстановить свойство кучи.

Требуется проверить:

- удаление корня;
- удаление элемента из середины кучи;
- удаление несуществующего элемента;
- удаление из пустой очереди.

## Поведение метода

Метод remove возвращает:

- true, если элемент найден и одно его вхождение удалено;
- false, если соответствующего значения в очереди нет.

При наличии нескольких одинаковых значений удаляется ровно одно вхождение.
Размер очереди после успешного удаления уменьшается на единицу.

Первое вхождение определяется просмотром текущего внутреннего массива
с индекса 0 до первого совпадения.

Куча переставляет элементы при добавлении и удалении, поэтому первое
вхождение во внутреннем массиве не обязательно было добавлено раньше остальных.

Для пустой очереди метод возвращает false.
Вызов remove(null) также возвращает false, поскольку значения null
в данной реализации не допускаются.

## Поиск элемента

Свойство кучи задаёт порядок между родителем и его детьми.
Оно не задаёт полного отсортированного порядка всего внутреннего массива.

Поэтому для поиска произвольного значения выполняется последовательный
просмотр активной части массива — от индекса 0 до size - 1.

Совпадение проверяется выражением:

```text
item.equals(elements[index])
```

После первого совпадения вызывается приватный метод removeAt,
а remove возвращает true.

Если просмотр завершился без совпадения, возвращается false.

### Равенство значений и равенство приоритетов

Для поиска используется equals.

Компаратор определяет приоритет элементов, но одинаковый приоритет
не обязательно означает одинаковое значение.

Например, при сравнении строк только по длине строки aa и bb имеют
одинаковый приоритет. При этом equals считает их различными.

Поэтому вызов remove("aa") должен удалить строку aa,
сохранив строку bb в очереди.

## Удаление и восстановление кучи

Удаление по найденному индексу выполняет приватный метод removeAt.

Алгоритм:

1. Размер очереди уменьшается на единицу.
2. Сохраняется элемент из последней занятой ячейки.
3. Последняя занятая ячейка обнуляется.
4. Если удаляемый элемент находился в этой последней ячейке,
   операция завершается.
5. В остальных случаях сохранённый элемент переносится
   на место удалённого.
6. Если замена находится не в корне и должна располагаться раньше
   своего родителя согласно компаратору, выполняется siftUp.
7. Иначе выполняется siftDown.

Условие выбора просеивания вверх:

```text
index > 0 && compare(moved, parent) < 0
```

Просеивание выполняется по тому же компаратору, который используется
при добавлении элементов. Поэтому удаление работает и для min-heap,
и для max-heap.

Обнуление освободившейся ячейки убирает лишнюю ссылку за пределами
активной части массива.

## Почему нужны оба направления просеивания

После переноса последнего элемента возможны два вида нарушения:

- новый элемент должен находиться раньше своего родителя;
- новый элемент должен находиться позже одного из своих детей.

В первом случае требуется просеивание вверх.
Во втором случае требуется просеивание вниз.

При корректной исходной куче достаточно выбрать одно из направлений.
Отношения между узлами, которые не затрагиваются заменой и просеиванием,
остаются корректными.

### Пример просеивания вверх

Рассмотрим min-heap, внутренний массив которой имеет вид:

```text
1, 8, 2, 10, 11, 3, 4, 12, 13, 14, 15, 5, 6, 7
```

Удаляется значение 10 с индекса 3.

На его место переносится последнее значение 7.
Родителем узла с индексом 3 является узел с индексом 1,
в котором находится значение 8.

Получается нарушение:

```text
7 < 8
```

Поэтому значение 7 просеивается вверх.

После удаления последовательные вызовы poll должны вернуть:

```text
1, 2, 3, 4, 5, 6, 7, 8, 11, 12, 13, 14, 15
```

### Пример просеивания вниз

Рассмотрим min-heap:

```text
1, 2, 3, 4, 5, 6, 7, 8, 9
```

После удаления значения 2 на его место переносится последнее значение 9.

Порядок с родителем 1 сохраняется, но значение 9 больше детей 4 и 5.
Поэтому выполняется просеивание вниз.

После удаления последовательные вызовы poll должны вернуть:

```text
1, 3, 4, 5, 6, 7, 8, 9
```

## Асимптотическая сложность

Обозначения:

- n — количество элементов до удаления;
- C — ёмкость внутреннего массива.

Предполагается, что equals и одно сравнение компаратором занимают O(1).

Поиск выполняет не более n проверок равенства, поэтому его сложность — O(n).

После нахождения элемента выполняется перенос последнего элемента за O(1)
и одно просеивание за O(log n).

Итоговая сложность в худшем случае:

```text
O(n) + O(log n) = O(n)
```

Если значение отсутствует, выполняется только последовательный поиск.

Для пустой очереди и для remove(null) время работы составляет O(1).
Успешное удаление корня не требует просмотра всего массива
и занимает O(log n) с учётом восстановления кучи.

Дополнительная память операции составляет O(1):
используются несколько индексов и временная ссылка на элемент.

Просеивания реализованы итеративно.
Новый массив при удалении не создаётся.
Ёмкость существующего массива не уменьшается.

Общая память очереди остаётся O(C).
После большого количества удалений ёмкость C может значительно превышать
текущее количество элементов.

Если equals или компаратор выполняют сложные вычисления,
их стоимость необходимо учитывать дополнительно.

8. Вызов remove(null).
9. Проверка равенства через equals при одинаковых приоритетах.
10. Удаление единственного элемента.
11. Сравнение случайных операций min-heap со стандартной очередью.
12. Сравнение случайных операций max-heap со стандартной очередью.

Результат отдельного запуска класса тестов:
12 тестов выполнено, ошибок и неудачных проверок нет.

### Проверка равенства через equals

В очередь со сравнением строк по длине добавляются:

```text
bb, aa, cccc
```

Затем вызывается:

```text
queue.remove(new String("aa"))
```

Метод должен вернуть true.
В очереди должны остаться строки bb и cccc.

В тесте создаётся новый объект String с тем же содержимым,
чтобы проверить удаление по значению, а не по совпадению ссылок.

### Случайные последовательности операций

В каждом из двух случайных тестов выполняется по 5 000 операций.

Используются добавление, извлечение, просмотр вершины и удаление по значению.
Одинаковые операции выполняются над собственной очередью
и java.util.PriorityQueue.

После каждой операции сравниваются:

- возвращаемые результаты, если они предусмотрены операцией;
- размер очереди;
- признак пустоты;
- значение вершины.

В конце сравнивается вся последовательность оставшихся элементов
при полном извлечении из очередей.

Для воспроизводимости используется фиксированный seed 20261120.
Min-heap и max-heap проверяются отдельными тестами.

Стандартная очередь используется как эталон только в тестах.

```text

```

## Вывод

Операция remove удаляет одно вхождение заданного значения
и сохраняет остальные элементы.

После замены удалённого элемента последним выполняется просеивание
вверх или вниз в зависимости от нарушенного отношения.

В худшем случае время определяется последовательным поиском
и составляет O(n). Дополнительная память операции — O(1).

Корректность проверена 12 тестами, включая оба направления просеивания,
граничные случаи и случайные последовательности операций
для min-heap и max-heap.
