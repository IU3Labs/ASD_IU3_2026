# Задача 1D. Построение кучи из массива за O(n)

Лабораторная работа № 2.

Стоимость задачи: 2 балла.

## Условие

Добавить конструктор:

```text
PriorityQueueCustom(T[] array)
```

Конструктор должен строить кучу за O(n) методом просеивания вниз:
от последнего внутреннего узла к корню.

Дополнительно требуется сравнить два способа построения очереди
из 100 000 элементов:

- последовательное добавление элементов методом add;
- построение из массива за O(n).

Результаты необходимо оформить таблицей в benchmarks.md
и дополнить кратким выводом.

В этом отчёте рассматривается построение кучи снизу вверх.

## Подготовка внутреннего массива

Пусть n — длина переданного массива.

Конструктор выполняет следующие действия:

1. Проверяет, что ссылка на исходный массив не равна null.
2. Создаёт собственный внутренний массив ёмкости max(16, n).
3. Проверяет каждый входной элемент и копирует его ссылку
   во внутренний массив.
4. Устанавливает размер очереди равным n.
5. Выполняет построение кучи снизу вверх.

Передача null вместо массива или наличие null среди элементов
вызывает NullPointerException.

Копирование поверхностное: копируются ссылки на элементы,
а сами объекты не клонируются.

У очереди и вызывающего кода разные массивы.
Поэтому замена ячейки исходного массива после создания очереди
не изменяет соответствующую ячейку внутреннего массива.

Конструктор и операции очереди не переставляют ячейки исходного массива.

Для пустого входного массива создаётся очередь размером 0
с внутренним буфером на 16 элементов.
В неё можно впоследствии добавлять значения.

## Алгоритм построения

При индексации с нуля для узла i:

```text
левый ребёнок:  2 * i + 1
правый ребёнок: 2 * i + 2
родитель:      (i - 1) / 2
```

Для непустой кучи индексы от n / 2 до n - 1 соответствуют листьям.
Здесь деление целочисленное.

Каждый лист уже является корректной кучей из одного элемента.

Последний внутренний узел имеет индекс:

```text
n / 2 - 1
```

Поэтому конструктор обходит внутренние узлы в порядке:

```text
n / 2 - 1, n / 2 - 2, ..., 0
```

Для каждого узла вызывается siftDown.

Если массив пуст или содержит один элемент,
внутренних узлов нет и цикл просеивания не выполняется.

## Почему алгоритм корректен

Обход начинается с самых нижних внутренних узлов.

К моменту обработки очередного узла оба его дочерних поддерева
уже являются корректными кучами:

- в начале обхода это листья;
- на следующих шагах это поддеревья, обработанные ранее.

Метод siftDown выбирает ребёнка, который должен находиться раньше
согласно компаратору, и при необходимости перемещает элемент вниз.

Для min-heap выбирается меньший ребёнок.
Для max-heap с обратным компаратором выбирается больший ребёнок.

После просеивания всё поддерево текущего узла становится корректной кучей.
Когда обработан корень с индексом 0, свойство кучи выполняется
для всей очереди.

В реализации также предусмотрен конструктор с массивом и компаратором.
Он использует тот же алгоритм построения.

## Почему сложность составляет O(n)

Предполагается, что проверка элемента и одно сравнение компаратором
занимают O(1).

Высота отдельной вершины определяет, насколько далеко её элемент
может опуститься при siftDown.

Большинство вершин находится близко к листьям:

- листья вообще не требуют просеивания;
- вершины высоты 1 могут опуститься не более чем на один уровень;
- вершины высоты 2 — не более чем на два уровня;
- вершин большой высоты значительно меньше.

Для высоты h число вершин такой высоты не превышает n / 2^h,
а обработка каждой занимает O(h).

Суммарную работу можно ограничить выражением:

$$
T(n) = O(n) + O\left(n \sum_{h=1}^{\infty}\frac{h}{2^h}\right).
$$

Первое слагаемое учитывает проверку и копирование входного массива.

Ряд сходится:

$$
\sum_{h=1}^{\infty}\frac{h}{2^h} = 2.
$$

Следовательно:

$$
T(n) = O(n).
$$

Для непустого массива конструктор также должен прочитать
и скопировать все n элементов.
Поэтому полная оценка времени построения — Θ(n).

Для пустого массива время работы составляет O(1).

Если стоимость одного сравнения не является константной,
её необходимо учитывать дополнительно.

## Использование памяти

Конструктор создаёт внутренний массив ёмкости:

```text
C = max(16, n)
```

Память созданного массива составляет Θ(max(1, n)).
Для непустого массива это O(n).

Сверх этого буфера требуется O(1) временной памяти:
несколько индексов и ссылок.

Просеивание выполняется итеративно, без рекурсивных вызовов.

После последующих добавлений ёмкость массива может увеличиваться.
Общая память очереди в дальнейшем определяется текущей ёмкостью C.

## Сравнение с последовательными вставками

При последовательном вызове add новая вершина может подниматься
через всю высоту кучи.

В худшем случае суммарное время n вставок составляет O(n log n).
Геометрическое расширение массива добавляет O(n) суммарного копирования
и не меняет эту итоговую оценку.

Например, при добавлении различных чисел в убывающем порядке
в min-heap каждый новый элемент становится новым минимумом
и поднимается к корню.

При построении снизу вверх большая часть вершин требует
небольшого количества работы, поэтому итоговая оценка — O(n).

На случайных данных многие последовательные вставки могут
выполнять короткие просеивания.
Поэтому конкретный замер не обязан показывать большой выигрыш
построения снизу вверх.

Асимптотическая оценка обосновывается анализом алгоритма.
Измерения показывают время работы на выбранных данных
и в конкретной среде выполнения.

7. Сохранение исходного массива при построении и операциях очереди.
8. Построение max-heap с обратным компаратором.
9. Сравнение извлечения из очереди с сортировкой случайного массива.
10. Проверка количества сравнений при построении снизу вверх.

Результат отдельного запуска класса тестов:
10 тестов выполнено, ошибок и неудачных проверок нет.

### Проверка на случайном массиве

Создаётся массив из 4 096 случайных чисел.

Одна его копия сортируется стандартным методом Arrays.sort.
Из другого массива создаётся PriorityQueueCustom.

Затем все элементы последовательно извлекаются из очереди.
Полученная последовательность должна полностью совпадать
с отсортированным эталоном.

Стандартная сортировка используется только в тесте для проверки результата.

### Проверка количества сравнений

Создаётся убывающий массив из 4 096 элементов.

В конструктор передаётся компаратор,
который дополнительно считает свои вызовы.

После построения проверяется условие:

```text
число сравнений <= 4 * n
```

Также проверяются размер очереди и значение её вершины.

Эта проверка не зависит от скорости компьютера.
Она подтверждает заданную границу на конкретном тестовом входе.
Общая линейная сложность обоснована отдельно через сумму работ
по высотам вершин.

## Примеры для ручной проверки

В примерах min-heap использует естественный порядок чисел.
Полное извлечение означает вызовы poll до опустошения очереди.

### Неупорядоченный массив с повторениями

Исходный массив:

```text
5, -2, 5, 0, 1, -2
```

Ожидаемое полное извлечение:

```text
-2, -2, 0, 1, 5, 5
```

### Пустой массив

После создания очереди ожидается:

```text
size() = 0
isEmpty() = true
```

После добавления чисел 2 и 1 ожидаемое извлечение:

```text
1, 2
```

### Единственный элемент

При построении из массива с числом 42 размер должен быть равен 1.

Первый poll возвращает 42.
После этого очередь должна быть пустой.

### Независимость внутреннего массива

Создать очередь из массива:

```text
3, 1, 2
```

Затем заменить все ячейки исходного массива значением 99.

Из очереди по-прежнему должны извлекаться:

```text
1, 2, 3
```

### Сохранение исходного массива

Создать очередь из массива 3, 1, 2.

Затем выполнить:

```text
poll()
remove(2)
add(0)
```

Исходный массив должен остаться равным 3, 1, 2.
Из очереди после этих операций должны извлекаться 0 и 3.

### Построение max-heap

Создать очередь из массива:

```text
3, 7, 1, 7, 2
```

Передать Comparator.reverseOrder().

Ожидаемое полное извлечение:

```text
7, 7, 3, 2, 1
```

### Некорректный вход

При передаче null вместо массива ожидается NullPointerException.

При передаче массива 2, null, 1 также ожидается NullPointerException.

## Эксперимент с 100 000 элементов

Измерения выполняет класс PriorityQueueBenchmark.

Оба способа получают один и тот же массив
из 100 000 случайных значений Integer.

Для генерации используется фиксированный seed 20261120.
Генерация данных и подготовка отсортированного эталона
выполняются до начала измерений.

### Последовательные вставки

В измеряемый участок входят:

1. Создание пустой очереди.
2. Добавление всех элементов методом add.
3. Расширения внутреннего массива, если они требуются.

### Построение снизу вверх

В измеряемый участок входит вызов конструктора из массива,
включая:

1. Создание очереди и её внутреннего массива.
2. Проверку и копирование элементов.
3. Просеивание внутренних узлов снизу вверх.

Полное извлечение элементов и проверка результата
в обоих вариантах выполняются после остановки таймера.

### Повторы и обработка результатов

Для каждого способа выполняются:

- 5 прогревочных запусков;
- 10 измеряемых запусков.

Запуски объединены в пары.
Порядок способов в соседних парах чередуется,
чтобы один вариант не запускался постоянно первым.

Прогревочные результаты в среднее время не включаются.

После каждого построения проверяются размер очереди
и вся последовательность извлечённых элементов.

Фактические результаты приведены в разделе
«Построение кучи: задача 1D» файла [benchmarks.md](benchmarks.md).

В таблице представлены среднее время, стандартное отклонение,
минимальное и максимальное время.
Параметры среды выполнения указаны в том же файле.

Отдельные результаты запусков сохранены

## Объяснение результатов

Построение снизу вверх гарантирует O(n) времени
при постоянной стоимости сравнения.

Последовательные вставки имеют оценку O(n log n) в худшем случае,
но на случайном наборе могут выполнять небольшое число перемещений.

На фактическое время также влияют копирование массива,
его расширения, выделение памяти, оптимизации JVM
и текущая нагрузка компьютера.

Поэтому вывод о соотношении времени двух способов относится
к выполненному измерению.
Численные результаты конкретного запуска приведены в benchmarks.md.
