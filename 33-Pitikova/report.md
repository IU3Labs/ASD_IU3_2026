## Очередь с приоритетом (1A–1D)

Двоичная куча хранится в массиве. Для индекса `i` дети находятся по индексам
`2*i + 1` и `2*i + 2`, а родитель при `i > 0` находится по индексу `(i - 1) / 2`.
Родитель предшествует детям или равен им по порядку сравнения.
При естественном порядке корень содержит минимум, при обратном — максимум.
При вставке элемент поднимается через родителей. При извлечении минимума корень
заменяется последним элементом, который опускается через первого по порядку ребёнка.
В массиве удалённая ссылка очищается. При заполнении ёмкость удваивается.

Конструктор с массивом делает копию и просеивает вниз все внутренние узлы от
последнего к корню. К моменту обработки узла обе его дочерние подкучи уже построены.
На высоте не менее `h` находится не более `n / 2^h` узлов. Сумма числа возможных
шагов по высотам ограничена геометрической прогрессией и даёт O(n). Копирование
и проверка входа также занимают O(n).

| Операция | Время |
|---|---|
| `add` | O(log n) амортизированно. Вставка с расширением занимает O(n). |
| `poll` | O(log n) |
| `remove` | O(n) |
| `peek`, `size`, `isEmpty` | O(1) |
| Построение из массива | O(n) |

Память занимает O(C), где C — ёмкость массива. После извлечения элементов массив
сохраняет прежнюю ёмкость. При росте временно существуют оба массива.

Конструктор с `Comparator` задаёт порядок сравнения. Для `remove(item)` сначала
линейно ищется первое равное значение по `equals` в массиве кучи. Найденная
ячейка заменяется последним элементом. Если он должен стоять раньше нового
родителя, выполняется просеивание вверх, иначе вниз. Поиск занимает O(n),
восстановление кучи — O(log n). Для пустой очереди `peek` и
`poll` бросают `NoSuchElementException`. Элементы `null` отклоняются.

## Хеш-таблица (2A)

Ключи и значения лежат в двух массивах с общей индексацией. Начальный индекс
вычисляется как `abs(hashCode) % capacity`. Перед вычислением модуля хеш
преобразуется в `long`, чтобы корректно обработать `Integer.MIN_VALUE`.
При коллизии проверяются соседние ячейки с переходом через конец массива.
Удаление помечает ключ как `DELETED` и освобождает ссылку на значение. Для вставки
запоминается первая удалённая ячейка, а поиск равного ключа продолжается до
первой пустой ячейки.

Число активных записей ограничено 75% ёмкости. При превышении порога таблица
удваивается и записи переносятся с пересчётом индексов. Для активных записей
и маркеров удаления действует отдельный порог 87,5%. Если его пересекла бы
вставка в ранее пустую ячейку, таблица перестраивается с той же ёмкостью.
Для такой перестройки при ёмкости C накопилось как минимум C/8 маркеров,
поэтому её ожидаемая стоимость O(C) амортизируется по уже выполненным удалениям.

| Операция | Время |
|---|---|
| `put` | Ожидаемое амортизированное O(1). Перестройка занимает ожидаемое O(C). |
| `get`, `containsKey`, `remove` | Ожидаемое O(1), до O(C) при сильных коллизиях. |
| `size`, `capacity` | O(1) |

Оценки ожидаемого времени предполагают достаточно равномерное распределение
хешей. При совпадающих хешах перестройка может занять O(C²) из-за повторного
прохода по цепочке пробирования. Память составляет O(C) для обоих массивов
и временных массивов при перестройке. Ключи `null` отклоняются. Значения
`null` разрешены, наличие ключа проверяется через `containsKey`.

## Примеры ручной проверки

| Действия | Ожидаемый результат | Что проверяется |
|---|---|---|
| Построить очередь из `[4, 1, 4, 1, -3]` и извлечь все элементы | `[-3, 1, 1, 4, 4]` | Порядок извлечения и сохранение повторов |
| Вызвать `peek()` дважды после `add(9)` и `add(2)` | Оба раза `2`, размер остаётся `2` | Поиск минимума без удаления |
| При ёмкости 16 вставить ключи `15` и `31`, удалить `15`, найти `31` | Значение для `31` доступно | Переход через конец массива и поиск за маркером |
| Удалить `6` из кучи `[1, 5, 2, 6, 7, 3, 4]` | `true`, порядок извлечения `[1, 2, 3, 4, 5, 7]` | Просеивание вверх после замены на `4` |
| Вставить ключ со значением `null`, затем вызвать `get` и `containsKey` | `null` и `true` | Различие между отсутствием ключа и значением `null` |

Замеры и выводы приведены в [benchmarks.md](benchmarks.md).
