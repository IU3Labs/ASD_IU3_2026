# ЛР2. Базовые структуры данных

1A — минимальная очередь с приоритетом (2 балла), 1D — построение кучи из массива (2 балла), 2A — таблица с линейным пробированием (3 балла). Всего 7 баллов.

## 1A. Очередь с приоритетом

В массиве родитель расположен по индексу `(i - 1) / 2`, дети — по индексам `2*i + 1` и `2*i + 2`. После добавления элемент поднимается к корню, пока он меньше родителя. При извлечении последний элемент переносится на место минимума и опускается к меньшему ребёнку. Так минимум всегда доступен в корне.

`poll` занимает O(log n), `peek`, `size` и `isEmpty` — O(1). Для `add` просеивание занимает O(log n), удвоение массива стоит O(n) в отдельном вызове и O(1) амортизированно на вставку. Итого O(log n) амортизированно. Оценки предполагают O(1) для сравнения элементов. Память пропорциональна ёмкости массива, которая после удалений не уменьшается.

Пример: после добавления 4, −2, −2 извлечения дают −2, −2, 4; очередной poll бросает NoSuchElementException. Проверяются повторы и опустошение очереди.

## 1D. Построение снизу вверх

Конструктор копирует входной массив и вызывает siftDown от последнего родителя к корню. К моменту обработки узла оба его поддерева уже являются кучами. Узлов высоты не меньше h не более n / 2^h, поэтому суммарное число уровней просеивания ограничено геометрической суммой O(n). С копированием время Θ(n), память результата Θ(n), рабочая память помимо результата O(1).

Пример: из [8, 2, 1] извлекаются 1, 2, 8. Изменение исходного массива после построения не меняет очередь.

## 2A. Хеш-таблица

Ключи и значения хранятся в двух массивах. Начальная позиция равна модулю хеша по ёмкости после взятия абсолютной величины в long, включая случай Integer.MIN_VALUE. При коллизии пробируем следующую ячейку с переходом через конец. Метка DELETED позволяет продолжить поиск. Вставка запоминает первую метку и продолжает искать существующий ключ, чтобы обновление не создало дубликат.

Начальная ёмкость 16. При превышении загрузки 0,75 ёмкость удваивается. Если живых элементов мало, но доля живых и удалённых ячеек превысила бы 0,875, таблица перестраивается без роста. Поэтому всегда остаются пустые ячейки для завершения поиска. Допускаются значения null; ключи должны быть ненулевыми.

Пусть C — ёмкость. При равномерных хешах и постоянной стоимости hashCode/equals поиск, containsKey и удаление в среднем O(1), вставка — O(1) амортизированно. При коллизиях одна цепочка требует до O(C) проб. Перестроение просматривает C ячеек и заново вставляет ключи: ожидаемо O(C), до O(C²) при одинаковых хешах. Это также худшая оценка отдельного put с перестроением. size и capacity всегда O(1). Память Θ(C), в том числе во время перестроения.

Пример: при ёмкости 16 ключи 15 и 31 попадают в один стартовый слот. После удаления 15 значение 31 всё ещё находится за границей массива. Повторный put(31, ...) обновляет значение и сохраняет размер 1.
