## 2. Задача 1A. Очередь с приоритетом

Реализован класс `PriorityQueueCustom<T>` на основе двоичной min-кучи.

Элементы хранятся в динамическом массиве. Минимальный элемент всегда находится в корне кучи.

Для восстановления свойства кучи используются два метода:

- `siftUp()` — просеивание вверх при добавлении элемента;
- `siftDown()` — просеивание вниз при извлечении минимального элемента.

При заполнении внутреннего массива его вместимость увеличивается вдвое.

### Асимптотическая сложность

| Операция | Временная сложность |
|---|---|
| `add()` | O(log n), амортизированно |
| `poll()` | O(log n) |
| `peek()` | O(1) |
| `size()` | O(1) |
| `isEmpty()` | O(1) |

Пространственная сложность хранения n элементов составляет O(n).

### Тестирование

Разработано 12 автоматических тестов JUnit 5. Проверены добавление и извлечение элементов, соблюдение порядка, обработка дубликатов, отрицательных чисел, пустой очереди и автоматическое расширение массива.

Все 12 тестов пройдены успешно.

## 3. Задача 2A. Хеш-таблица

Реализован класс `HashMapCustom<K, V>` с открытой адресацией и линейным пробированием.

Хранение организовано с помощью массивов ключей, значений и состояний ячеек.

Для разрешения коллизий используется последовательная проверка соседних ячеек с циклическим переходом к началу массива.

Для удаления используется специальное состояние `DELETED`, позволяющее сохранить корректность цепочек пробирования.

При превышении установленного порога загрузки выполняется увеличение ёмкости вдвое с повторным размещением существующих элементов.

### Асимптотическая сложность

| Операция | Средняя сложность | Худшая сложность |
|---|---|---|
| `put()` | O(1), амортизированно | O(n) |
| `get()` | O(1) | O(n) |
| `containsKey()` | O(1) | O(n) |
| `remove()` | O(1) | O(n) |
| `size()` | O(1) | O(1) |
| `capacity()` | O(1) | O(1) |

Средняя сложность O(1) предполагает достаточно равномерное распределение хеш-кодов и ограниченную загрузку таблицы.

Пространственная сложность составляет O(n).

### Тестирование

Разработано 15 тестов JUnit 5. Проверены вставка, поиск, обновление и удаление элементов, обработка коллизий, повторное использование удалённых ячеек, расширение таблицы, отрицательные хеш-коды и граничные случаи.

Все 15 тестов пройдены успешно.

## 4. Задача 3A. Поиск Top-K

Реализован алгоритм `TopK.topK()`, находящий k наибольших элементов входного списка с использованием собственной очереди с приоритетом.

Алгоритм последовательно обрабатывает входные элементы и поддерживает min-кучу размером не более k.

Если очередной элемент больше минимального элемента кучи, минимальный элемент заменяется новым.

После обработки всех входных элементов содержимое кучи извлекается и представляется в порядке убывания.

### Асимптотическая сложность

Временная сложность: **O(n log k)** при k ≥ 2.

Для k = 1 время составляет O(n), для k = 0 — O(1).

Дополнительная пространственная сложность: **O(k)**.

### Тестирование

Разработано 15 тестов JUnit 5, включая сравнение с результатом стандартной сортировки на случайном наборе данных.

Все 15 тестов пройдены успешно.
