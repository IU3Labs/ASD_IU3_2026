## Задача 2A. Хеш-таблица с линейным пробированием

Реализация: [HashMapCustom.java](../../src/main/java/ru/bmstu/lab02/HashMapCustom.java).

### Идея решения

Ключи и значения лежат в двух массивах с одинаковыми индексами. Начальная позиция —
`abs((long) hashCode) % capacity`. Приведение к `long` нужно для `Integer.MIN_VALUE`.
При коллизии идём к следующей ячейке, после конца массива продолжаем с нуля.

Удалённая ячейка помечается как `DELETED`. Поиск проходит мимо неё, а вставка запоминает её как
возможное место для нового ключа. Сначала она проверяет оставшуюся цепочку, чтобы не создать
вторую запись для уже существующего ключа. Ёмкость удваивается, когда новая запись подняла бы долю
живых ключей выше 0,75. Если занято 7/8 ячеек с учётом удалённых и для новой записи нужна
пустая ячейка, маркеры очищаются перехешированием в прежнюю ёмкость.

### Асимптотика

| Операция | Время |
|---|---|
| `get`, `containsKey`, `remove` | В среднем O(1) при хорошем распределении, в худшем O(C) |
| `put` | В среднем O(1) амортизированно при хорошем распределении |
| `size`, `capacity` | O(1) |

Без перехеширования `put` в худшем случае просматривает O(C) ячеек. Само перехеширование
при хорошем распределении занимает O(C), при массовых коллизиях — вплоть до O(C²).
Память — O(C), где C — текущая ёмкость. Ключ `null` запрещён. Для значения `null`
наличие записи проверяется через `containsKey`.

### Проверки

JUnit 5: прошли 12 тестов, без ошибок и пропусков.
Тестовый класс: [HashMapCustomTest.java](../../src/test/java/ru/bmstu/lab02/HashMapCustomTest.java).

| Юнит-тест | Что проверяет |
|---|---|
| `shouldReportMissingKeysInEmptyTable` | У пустой таблицы нет записей. |
| `shouldStoreAndFindAValue` | Вставленное значение находится по ключу. |
| `shouldReplaceExistingValueWithoutGrowingAtLoadLimit` | Обновление значения на пороге не меняет ёмкость. |
| `shouldDoubleCapacityOnlyWhenLiveLoadExceedsThreshold` | Следующий ключ за порогом удваивает ёмкость. |
| `shouldFindCollidingKeysAfterWraparoundAndDeletion` | Поиск проходит через конец массива и удалённую ячейку. |
| `shouldUpdateKeyBeyondTombstoneWithoutCreatingDuplicate` | Обновление за маркером удаления не создаёт дубликат. |
| `shouldReuseDeletedSlotForNewCollidingKey` | Новое значение может занять удалённую ячейку. |
| `shouldRehashTombstonesWithoutGrowingSparseTable` | Маркеры очищаются без увеличения разреженной таблицы. |
| `shouldDifferentiateNullValueFromMissingKey` | Значение null отличается от отсутствующего ключа. |
| `shouldHandleNegativeHashIncludingMinimumInt` | Отрицательные хеши, включая MIN_VALUE, обрабатываются корректно. |
| `shouldRejectNullKeysForAllKeyOperations` | Операции с ключом null отклоняются. |
| `shouldMatchStandardMapDuringMixedOperations` | Смешанные операции сверяются со стандартной хеш-таблицей. |
