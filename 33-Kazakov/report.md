Казаков И. С., группа ИУ3-33Б

Выбраны задачи 1A (2 балла), 1C (2 балла) и 2A (3 балла). Всего 7 баллов.

## Задачи 1A и 1C. Очередь с приоритетом

Элементы лежат в динамическом массиве, который представляет двоичную мин-кучу. Для узла с индексом `i`
его дети имеют индексы `2 * i + 1` и `2 * i + 2`, а родитель — `(i - 1) / 2` при `i > 0`.
Значение в родителе не больше значений в его детях, поэтому минимум всегда лежит в начале массива.
Массив позволяет находить соседние узлы по индексам за постоянное время и не требует отдельных
объектов для каждого узла.

При добавлении элемент записывается в конец и поднимается методом `siftUp`. При извлечении корня на
его место ставится последний элемент, после чего `siftDown` опускает его до подходящей позиции.
При удалении по значению линейно ищется первое совпадение по `equals` в порядке индексов массива.
Последний элемент ставится на освободившееся место. Если он меньше родителя, выполняется подъём,
иначе — спуск. Ссылка из освобождённой ячейки убирается.

Пустой `poll` выбрасывает `NoSuchElementException`. Для `peek` на пустой очереди выбран результат
`null`, как у стандартной очереди. Значения `null` добавлять нельзя.

| Операция | Время | Обоснование |
|---|---|---|
| `add` | Амортизированное `O(log n)`, отдельная вставка с ростом массива — `O(n)` | Подъём ограничен высотой кучи. При удвоении массива суммарное число копирований за серию вставок линейно |
| `poll` | `O(log n)` | Замена корня и спуск не более чем на высоту кучи |
| `remove` | `O(n)` | Линейный поиск и восстановление кучи за `O(log n)` |
| `peek`, `size`, `isEmpty` | `O(1)` | Доступ к корню или счётчику |

Куча занимает `O(c)` памяти, где `c` — текущая ёмкость массива. Она линейна по максимальному числу
одновременно хранившихся элементов, поскольку после удаления массив не уменьшается. Рабочая память
просеивания — `O(1)`. При расширении на время копирования одновременно существуют два массива.

## Задача 2A. Хеш-таблица с линейным пробированием

Ключи и значения хранятся в двух параллельных массивах. Начальная позиция для ключа —
`Math.abs((long) key.hashCode()) % capacity`. Преобразование к `long` перед взятием модуля сохраняет
неотрицательный результат даже для `Integer.MIN_VALUE`. При коллизии проверяются следующие ячейки
по кругу.

При удалении ключ заменяется маркером `DELETED`, чтобы поиск следующих ключей в цепочке продолжался.
Вставка запоминает первую удалённую ячейку, но ищет до совпадения или первой никогда не занятой ячейки:
это позволяет обновить существующий ключ за маркером вместо создания дубликата. Ключи `null`
запрещены, значения `null` разрешены. Для них наличие записи определяется через `containsKey`.

Размер массива удваивается, если новая пара поднимет долю живых записей выше 0,75. Если вместе с
маркерами занято 7/8 ячеек и под вставку нужна новая ячейка, таблица перестраивается с прежней
ёмкостью. До перестроения остаются пустые ячейки, поэтому пробирование может завершиться.

| Операция | Ожидаемое время при хорошем распределении хешей | Худший случай |
|---|---|---|
| `put` | Амортизированное `O(1)` | `O(c)` без перестроения, до `O(c²)` с перестроением при массовых коллизиях |
| `get`, `containsKey`, `remove` | `O(1)` | `O(c)` |
| `size`, `capacity` | `O(1)` | `O(1)` |

`c` — текущая ёмкость. При хорошем распределении хешей перестроение занимает ожидаемое `O(c)`:
старый массив обходится один раз, а каждая живая запись вставляется за ожидаемое постоянное время.
Очищать маркеры имеет смысл после накопления заметной их доли, поэтому полное перестроение не
повторяется при каждом удалении. Память таблицы — `O(c)`, при перестроении старые и новые массивы
временно хранятся одновременно. Ёмкость при удалении не уменьшается.

## Примеры ручных проверок

| Действия | Ожидаемый результат | Зачем проверять |
|---|---|---|
| В очередь добавить `5, -2, 5, 0`, затем извлечь всё | `-2, 0, 5, 5` | Проверяет порядок и сохранение дубликатов |
| В очередь добавить `1, 5, 2, 8, 9, 3, 4`, удалить `8` и извлечь всё | `1, 2, 3, 4, 5, 9` | Последний элемент должен подняться после замены |
| На пустой очереди вызвать `peek`, `remove(7)` и `poll` | `null`, `false`, затем исключение | Проверяет контракт пустой очереди |
| В таблицу ёмкости 16 записать `put(0, "a")` и `put(16, "b")`, удалить ключ `0`, затем прочитать ключ `16` | `"b"` | Маркер удаления должен сохранять цепочку пробирования |
| В таблицу записать `put(1, null)`, вызвать `get(1)` и `containsKey(1)` | `null` и `true` | Отличает существующий ключ с пустым значением от отсутствующего |
| В новую таблицу добавить 12 различных ключей, обновить один из них и добавить 13-й ключ | Ёмкость 16 после обновления, 32 после вставки, все 13 записей доступны | Проверяет порог расширения и сохранение данных |

## Автоматическая проверка

Из корня репозитория запустить `mvn clean test`. В модуле ЛР2 проходят 15 тестов очереди и
13 тестов хеш-таблицы на JUnit 5. Тесты включают граничные случаи и сравнение последовательностей
операций со стандартными коллекциями. JaCoCo показал 100% покрытия строк и ветвлений у обоих классов.

Результаты замеров и команда воспроизведения приведены в [benchmarks.md](benchmarks.md).
