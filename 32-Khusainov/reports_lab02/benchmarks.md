# Сравнение производительности

Хусаинов Тимур Маратович · ИУ3-32Б · Алгоритмы и структуры данных · Лабораторная работа № 2

## Условия эксперимента

OpenJDK 21.0.13, Linux x86-64, максимальный размер кучи JVM 768 МБ. Для каждой строки выполнены три прогрева и семь измерений. В таблице указано среднее время полной серии в миллисекундах по System.nanoTime(). Генерация чисел с seed = 2026 вынесена за границы замера.

Для очереди серия включает N вставок и N извлечений. Для таблицы измеряются N вставок различных ключей, N успешных поисков и N удалений. В каждом повторе создаётся новая структура. Для Top-K на одном входе сравниваются ограниченная куча и сортировка копии списка по убыванию. До измерений проверяется равенство двух ответов.

| Структура | Операция | N | Среднее, мс |
|---|---|---:|---:|
| PriorityQueueCustom | add + poll | 10000 | 2.081 |
| PriorityQueue | add + poll | 10000 | 2.370 |
| HashMapCustom | put + get + remove | 10000 | 2.098 |
| HashMap | put + get + remove | 10000 | 1.615 |
| PriorityQueueCustom | add + poll | 50000 | 10.378 |
| PriorityQueue | add + poll | 50000 | 8.911 |
| HashMapCustom | put + get + remove | 50000 | 6.228 |
| HashMap | put + get + remove | 50000 | 5.377 |
| PriorityQueueCustom | add + poll | 100000 | 30.295 |
| PriorityQueue | add + poll | 100000 | 24.883 |
| HashMapCustom | put + get + remove | 100000 | 14.889 |
| HashMap | put + get + remove | 100000 | 10.409 |
| TopK | k = 100 | 1000000 | 6.261 |
| ArrayList.sort | сортировка копии и первые 100 | 1000000 | 269.980 |

## Интерпретация

На 100 000 ключах серия для собственной таблицы заняла 14,889 мс, для HashMap — 10,409 мс; время включает расширения, вычисление индексов и пробирование. Для очередей порядок результатов менялся с размером набора. При k = 100 куча удерживает сто кандидатов, тогда как полная сортировка создаёт копию миллиона чисел и упорядочивает её целиком; в этом запуске получено 6,261 и 269,980 мс соответственно. Объём памяти в байтах не измерялся: вывод о памяти основан на размерах рабочих структур.
