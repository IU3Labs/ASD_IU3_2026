# 3A. Выбор k наибольших элементов

Хусаинов Тимур Маратович · ИУ3-32Б · Алгоритмы и структуры данных · Лабораторная работа № 2

## Постановка задачи

Для списка и числа k вернуть до k наибольших значений с учётом повторов. Входной список сохраняет исходный порядок.

## Устройство алгоритма

После обработки первых k элементов корень кучи хранит наименьший из текущих кандидатов. Каждый следующий элемент больше корня заменяет его, меньший или равный можно пропустить. Этот шаг сохраняет k наибольших значений просмотренной части, включая повторы. Для выдачи извлекаем минимумы и записываем в ответ с конца.

## Разбор на примере

| Следующее число, k = 2 | Значения в куче после шага | Причина |
|---:|---|---|
| 4 | {4} | Есть свободное место |
| 1 | {1, 4} | Есть свободное место |
| 7 | {4, 7} | 7 заменяет минимум 1 |
| 7 | {7, 7} | Второй экземпляр 7 заменяет 4 |
| 2 | {7, 7} | 2 меньше текущей границы отбора |

После двух извлечений ответ равен [7, 7].

## Оценка сложности

n — число элементов, C — ёмкость массива, m = min(n, k). Сравнение и вычисление хеша считаются операциями постоянной стоимости.

| Метод | Время | Обоснование |
|---|---|---|
| Top-K | O(n log(m+1)) при k ≥ 1, O(1) при k = 0 | Один проход, куча содержит до m элементов. Финальные m извлечений укладываются в ту же оценку. При k = 1 алгоритм линейный. |

Куча и массив ответа занимают по O(m) памяти. Обход входного списка выполняется через итератор, поэтому связный список тоже обрабатывается за один проход.

## Проверка результата

10 тестов. Для 300 псевдослучайных чисел каждый ответ при k от 0 до 300 сравнивается с первыми k значениями отсортированной копии. При k = 0 результат пуст, при k больше длины выдаются все элементы, при отрицательном k возникает IllegalArgumentException.
