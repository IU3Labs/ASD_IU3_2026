## Задача №3: Подсчёт вхождений

Дан массив целых чисел `a` длины `n` (по условию `2 < n < 100 000`) и число `x`.
Требуется подсчитать количество элементов массива, равных `x`.


### Идея решения
Алгоритм основан на **полном линейном проходе** по массиву со счётчиком:

1. Инициализируем переменную-счётчик `count` нулём.
2. Проходим по всем элементам массива от индекса `0` до `n - 1`.
3. Для каждого элемента проверяем условие `array[i] == x`.
4. Если условие истинно — увеличиваем `count` на единицу.
5. После завершения цикла возвращаем итоговое значение `count`.

В отличие от поиска первого вхождения, здесь мы **не можем** прервать цикл досрочно, так как нам нужно проверить каждый элемент, чтобы найти все совпадения.


### Анализ асимптотики

1. **Время**

- **`O(n)`**, где `n` — длина массива.
- Обоснование: цикл `for` выполняется ровно `n` раз (от `0` до `n - 1`), каждое сравнение и инкремент — `O(1)`. Досрочный выход невозможен, так как нужно просмотреть весь массив.
- Инициализация счётчика — `O(1)`.
- Итог: суммарно `O(n)` в любом случае (и в лучшем, и в худшем).

2. **Память**

- **`O(1)`** дополнительной памяти.
- Обоснование: для работы алгоритма используется только одна переменная `count` для хранения количества совпадений, независимо от размера входного массива.
- Итог: `O(1)` (не считая входного массива).


### Список тестов

| Тест | Что проверяет | Вход | Ожидание |
|---|---|---|---|
| `shouldCountMultipleOccurrences` | Корректный подсчёт, если элемент встречается несколько раз | `{4, 7, 2, 9, 2, 2, 5}`, `x = 2` | `3` |
| `shouldReturnZeroWhenNotFound` | Корректный возврат `0`, если искомого элемента нет | `{4, 7, 2, 9, 5}`, `x = 100` | `0` |
| `shouldWorkWithMaximumAllowedLength` | Граничный случай: массив максимальной длины, элементы в начале, середине и конце | `99 999` элементов, `x = 42` встречается 3 раза | `3` |

## Задача №5: Сумма элементов на чётных позициях

Дан массив целых чисел `a` длины `n` (по условию `2 < n < 100 000`).
Требуется вычислить сумму элементов, стоящих на чётных индексах (0, 2, 4, ...).


### Идея решения
Алгоритм использует **линейный проход с шагом 2**:

1. Инициализируем переменную `sum` типа `long` для накопления суммы нулём.
2. Запускаем цикл `for` от индекса `0` до конца массива с шагом `i += 2`.
3. На каждом шаге к текущей сумме прибавляем элемент `array[i]`.
4. Возвращаем итоговое значение `sum`.

**Важное замечание по типам данных:** тип возвращаемого значения и аккумулятора выбран `long`, а не `int`. Если массив заполнен значениями `Integer.MAX_VALUE`, их сумма превысит максимально возможное значение `int`, что приведет к переполнению. Использование `long` гарантирует корректность вычислений на всём допустимом диапазоне входных данных.


### Анализ асимптотики

1. **Время**

- **`O(n)`**, где `n` — длина массива.
- Обоснование: алгоритм совершает ровно `n / 2` итераций. В асимптотической нотации константа `1/2` отбрасывается, оставляя сложность `O(n)`.
- Итог: суммарно `O(n)`.

2. **Память**

- **`O(1)`** дополнительной памяти.
- Обоснование: используется только одна переменная-аккумулятор `sum` и счетчик цикла. Дополнительные массивы или структуры данных не создаются.
- Итог: `O(1)` (не считая входного массива).


### Список тестов

| Тест | Что проверяет | Вход | Ожидание |
|---|---|---|---|
| `shouldSumElementsOnEvenIndices` | Базовый подсчёт суммы на смешанном массиве | `{4, 7, 2, 9, 5}` | `11` |
| `shouldPreventIntegerOverflow` | Защита от переполнения `int` | `{MAX_VALUE, 0, MAX_VALUE}` | `4294967294` |
| `shouldWorkWithMaximumAllowedLength` | Граничный случай: массив максимальной длины | `99 999` элементов, заполненных единицами | `50 000` |

## Задача №9: Проверка отсортированности

Дан массив целых чисел `a` длины `n` (по условию `2 < n < 100 000`).
Требуется проверить, является ли массив неубывающим.
Выход: строка "YES", если массив неубывающий; строка "NO" иначе.


### Идея решения
Алгоритм использует **линейный проход** с попарным сравнением:

1. Запускаем цикл `for` с индекса `1` (второй элемент) до конца массива.
2. На каждом шаге сравниваем текущий элемент `array[i]` с предыдущим `array[i - 1]`.
3. Если `array[i] < array[i - 1]` — порядок нарушен, массив не является неубывающим. Сразу возвращаем строку `"NO"` (досрочный выход).
4. Если цикл завершился и ни одного нарушения не найдено, возвращаем строку `"YES"`.


### Анализ асимптотики

1. **Время**

- **`O(n)`** в худшем случае, где `n` — длина массива.
- Обоснование: если массив отсортирован, цикл выполнится ровно `n - 1` раз, каждое сравнение — `O(1)`. В худшем случае сложность линейна.
- **`O(1)`** в лучшем случае (если нарушение порядка стоит на первом же шаге цикла).
- Итог: асимптотическая сложность — `O(n)`.

2. **Память**

- **`O(1)`** дополнительной памяти.
- Обоснование: используется только счетчик цикла `i`. Строки "YES" и "NO" являются константными литералами в пуле строк, дополнительная динамическая память под них не выделяется.
- Итог: `O(1)` (не считая входного массива).


### Список тестов

| Тест | Что проверяет | Вход | Ожидание |
|---|---|---|---|
| `shouldReturnYesForNonDecreasingArray` | Корректная работа на неубывающем массиве (с дубликатами) | `{1, 2, 2, 3, 4}` | `"YES"` |
| `shouldReturnNoForUnsortedArray` | Обнаружение нарушения порядка | `{1, 3, 2, 4}` | `"NO"` |
| `shouldWorkWithMaximumAllowedLength` | Граничный случай: массив максимальной длины | `99 999` элементов от `0` до `99 998` | `"YES"` |

## Задача №25: Сумма элементов

Дан массив целых чисел `a` длины `n` (по условию `2 < n < 100 000`).
Требуется вычислить сумму всех элементов массива.


### Идея решения
Алгоритм использует **один линейный проход** по массиву:

1. Инициализируем переменную `sum` типа `long` нулём.
2. Проходим по всем элементам массива от индекса `0` до `n - 1`.
3. На каждом шаге прибавляем текущий элемент `array[i]` к общей сумме.
4. Возвращаем итоговое значение `sum`.

**Важное замечание по типам данных:** тип возвращаемого значения и аккумулятора выбран `long`, а не `int`. Так как массив может содержать значения, близкие к `Integer.MAX_VALUE`, их сумма легко превысит максимально возможное значение `int`. Использование `long` гарантирует отсутствие переполнения на всём допустимом диапазоне входных данных.


### Анализ асимптотики

1. **Время**

- **`O(n)`**, где `n` — длина массива.
- Обоснование: цикл `for` выполняется ровно `n` раз, каждое сложение — `O(1)`. 
- Инициализация суммы — `O(1)`.
- Итог: суммарно `O(n)`.

2. **Память**

- **`O(1)`** дополнительной памяти.
- Обоснование: используется только одна переменная-аккумулятор `sum` и счетчик цикла. Дополнительные массивы или структуры данных не создаются.
- Итог: `O(1)` (не считая входного массива).

## Задача №43: Перемещение нулей в конец

Дан массив целых чисел `a` длины `n` (по условию `2 < n < 100 000`).
Требуется переместить все нули в конец массива, сохранив порядок остальных элементов.
Требование: модификация на месте.


### Идея решения
Алгоритм использует метод **двух указателей** (без выделения дополнительной памяти под новый массив):

1. Заводим указатель `insertPos = 0`, который показывает, куда нужно записать следующий ненулевой элемент.
2. Проходим по массиву циклом `i` от `0` до `n - 1`:
   - если `array[i] != 0`, записываем этот элемент в позицию `array[insertPos]` и сдвигаем `insertPos` на шаг вперёд.
3. После завершения первого прохода все ненулевые элементы будут стоять в начале массива в исходном порядке.
4. Запускаем второй цикл от `insertPos` до конца массива и заполняем оставшиеся ячейки нулями.

Поскольку `insertPos` всегда меньше или равно `i`, мы не затираем данные, которые ещё не успели прочитать. Это позволяет обойтись без копирования массива.


### Анализ асимптотики

1. **Время**

- **`O(n)`**, где `n` — длина массива.
- Обоснование: алгоритм выполняет два независимых линейных прохода по массиву. В сумме количество операций пропорционально `n`. Константные множители в асимптотике отбрасываются.
- Итог: `O(n)`.

2. **Память**

- **`O(1)`** дополнительной памяти.
- Обоснование: модификация происходит на месте. Используются только две переменные-счётчика (`i`, `insertPos`). Новые массивы или коллекции не создаются.
- Итог: `O(1)`.


### Список тестов

| Тест | Что проверяет | Вход | Ожидание |
|---|---|---|---|
| `shouldMoveZeroesToEndPreservingOrder` | Базовое перемещение нулей с сохранением порядка | `{0, 1, 0, 3, 12}` | `{1, 3, 12, 0, 0}` |
| `shouldNotChangeArrayWithoutZeroes` | Отсутствие изменений, если нулей в массиве нет | `{1, 2, 3}` | `{1, 2, 3}` |
| `shouldWorkWithMaximumAllowedLength` | Стресс-тест с максимальной длиной и чередованием нулей | `99 999` элементов | Все ненулевые в начале, нули в конце |
