## Задача №1: Максимум и минимум

Дан массив целых чисел `a` длины `n` (по условию `1 < n < 100 000`).
Требуется найти минимальный и максимальный элементы массива.


### Идея решения
Алгоритм основан на **одном линейном проходе** по массиву:

1. Инициализируем `min` и `max` значением первого элемента `array[0]`.
2. Проходим по всем остальным элементам с индекса `1` до `n - 1`.
3. Для каждого элемента:
   - если `array[i] < min` — обновляем `min`;
   - если `array[i] > max` — обновляем `max`.
4. Возвращаем массив `{min, max}`.

Такой подход позволяет найти оба значения **за один проход**, не сортируя массив и не делая лишних копий.



### Анализ асимптотики.

1. **Время**

- **`O(n)`**, где `n` — длина массива.
- Обоснование: цикл `for` выполняется ровно `n - 1` раз, каждое сравнение — `O(1)`.
- Инициализация `min`/`max` — `O(1)`.
- Итог: суммарно `O(n)`.

2. **Память**

- **`O(1)`** дополнительной памяти.
- Обоснование: используются только две переменные `min` и `max`, независимо от `n`. Возвращаемый массив `{min, max}` имеет фиксированный размер 2 и не зависит от `n`.
- Итог: `O(1)` (не считая входного массива).



### Список тестов

| Тест | Что проверяет | Вход | Ожидание |
|---|---|---|---|
| `shouldReturnMinMaxForMixedNumbers` | Смешанные положительные и отрицательные числа | `{-10, 0, 5, -20, 30}` | `{-20, 30}` |
| `shouldReturnMinMaxForAlternatingSequence` | Чередование знаков на большом массиве (стресс-тест) | `99 999` элементов: `-(i+1)` и `(i+1)` | `{-99 999, 99 998}` |

## Задача №2: Индекс первого вхождения

Дан массив целых чисел `a` длины `n` (по условию `2 < n < 100 000`) и число `x`.
Требуется найти индекс первого элемента, равного `x`. Если такого нет — вернуть `-1`.


### Идея решения
Алгоритм основан на **линейном поиске** с досрочным выходом:

1. Проходим по элементам массива слева направо от индекса `0` до `n - 1`.
2. Для каждого элемента проверяем условие `array[i] == x`.
3. Если условие истинно — сразу возвращаем текущий индекс `i` и **прерываем** выполнение цикла.
4. Если цикл завершился, а элемент не был найден — возвращаем `-1`.

Такой подход позволяет не просматривать весь массив, если искомый элемент находится в начале.



### Анализ асимптотики

1. **Время**

- **`O(n)`** в худшем случае, где `n` — длина массива.
- Обоснование: если элемента нет в массиве (или он стоит в самом конце), цикл `for` выполнится ровно `n` раз, каждое сравнение — `O(1)`.
- **`O(1)`** в лучшем случае (элемент стоит на первом месте).
- Итог: асимптотическая сложность — `O(n)`.

2. **Память**

- **`O(1)`** дополнительной памяти.
- Обоснование: для работы алгоритма используется только одна переменная-счетчик `i` внутри цикла. Дополнительные структуры данных не выделяются.
- Итог: `O(1)` (не считая входного массива).



### Список тестов

| Тест | Что проверяет | Вход | Ожидание |
|---|---|---|---|
| `shouldReturnFirstOccurrenceIndexForDuplicates` | Возврат индекса именно *первого* вхождения, если в массиве есть дубликаты | `{4, 7, 2, 9, 2, 5}`, `x = 2` | `2` (а не `4`) |
| `shouldReturnMinusOneWhenNotFound` | Корректный возврат `-1`, если искомого элемента нет | `{4, 7, 2, 9, 5}`, `x = 100` | `-1` |
| `shouldWorkWithMaximumAllowedLength` | Граничный случай: массив максимальной длины (стресс-тест) | `99 999` элементов, `array[50 000] = 42` | `50 000` |
