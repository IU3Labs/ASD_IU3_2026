## Идея решения

Очередь хранит двоичную кучу в массиве. Добавляемый элемент поднимается к корню, пока он меньше
родителя. При извлечении корня последний элемент переносится в начало и опускается вниз.
Для максимума используется обратный компаратор; второй алгоритм кучи не нужен.

Хеш-таблица хранит ключи, значения и состояния ячеек в трёх массивах. При коллизии проверяется
следующая ячейка. После удаления остаётся маркер DELETED, чтобы поиск не потерял другие записи
из той же цепочки. При превышении загрузки 0.75 ёмкость удваивается и записи перехешируются.

Готовые PriorityQueue и HashMap используются только в тестах и для сравнения производительности.

## Асимптотика

Подробный расчёт находится в [complexity.md](complexity.md).

| Структура | Операция | Оценка |
|---|---|---|
| Очередь | add | O(log n) амортизированно; одна вставка с расширением O(n) |
| Очередь | poll | O(log n) в худшем случае |
| Очередь | peek, size, isEmpty | O(1) |
| Хеш-таблица | get, containsKey, remove | ожидаемо O(1), худшее O(C) |
| Хеш-таблица | put | ожидаемо амортизированно O(1); при плохих хешах и расширении O(C + n²) |
| Хеш-таблица | size, capacity | O(1) |
| Обе структуры | память | O(C), C — ёмкость массивов |

Ожидаемые оценки таблицы предполагают хорошее распределение хешей и отсутствие длинных цепочек
удалённых ячеек. Массивы после удаления не уменьшаются, поэтому память зависит от ёмкости,
а не только от текущего количества элементов.

## Ручные проверки

| Ситуация | Действия | Ожидаемый результат | Зачем проверять |
|---|---|---|---|
| Min-heap | add(5), add(1), add(3), три poll() | 1, 3, 5 | Проверка порядка |
| Max-heap | Те же вставки с reverseOrder() | 5, 3, 1 | Проверка компаратора |
| Пустая очередь | poll() или peek() | NoSuchElementException | Граничный случай |
| Повтор ключа | put("a", 1), put("a", 2) | get("a") = 2, size = 1 | Обновление без дубля |
| Коллизия | При C = 16: put(1, 10), put(17, 20), remove(1), get(17) | 20 | Поиск через DELETED |
| Расширение | Вставить 13 различных ключей | Ёмкость 32, записи доступны | Порог 0.75 и перехеширование |
| Null-значение | put("a", null) | get("a") = null, containsKey("a") = true | Отличие от отсутствия ключа |

## Автоматические проверки

Для очереди предусмотрено 18 тестов, для таблицы — 20. Проверяются пустые структуры, рост массивов,
повторы, отрицательные и крайние значения, собственный компаратор, коллизии, маркеры удаления.
Дополнительно смешанные случайные операции сравниваются со стандартными структурами при фиксированном seed.

## Вывод

Реализованы две структуры на массивах. Двоичная куча позволяет быстро извлекать элемент с нужным
приоритетом, а компаратор меняет порядок без дублирования алгоритма. Линейное пробирование
позволяет хранить пары ключ–значение, но требует правильной обработки удалённых ячеек и расширений.
Для проверки корректности написаны тесты. Производительность собственных структур
сравнена со стандартными реализациями на одинаковых наборах данных.
