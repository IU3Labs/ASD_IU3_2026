# Расчёт асимптотики ЛР2

Реализованы задачи 1A, 1B и 2A. Обозначения: n — текущее число элементов, C — текущая ёмкость массива.
Сравнение элементов, hashCode() и equals() считаются O(1).

## 1A. Очередь с приоритетом

Куча — полное двоичное дерево, записанное в массив. На уровне h не более 2^h узлов.
Из 1 + 2 + ... + 2^h = 2^(h+1) - 1 следует, что высота дерева O(log n).
Для пустой структуры и одного элемента операции требуют постоянного времени.

### add(item)

1. Проверяем, что элемент не null, — O(1).
2. Если массив заполнен, создаём массив вдвое больше и копируем элементы — O(n).
3. Записываем элемент в конец занятой части — O(1).
4. siftUp поднимает элемент по пути к корню. На каждом уровне выполняется одно сравнение
   и, возможно, обмен — O(log n).

Без расширения верхняя граница времени O(log n). При расширении одна операция имеет худшее время O(n).
При последовательности добавлений массивы имеют ёмкости 16, 32, 64 и т.д. Сумма копирований
16 + 32 + ... + 2^p меньше 2^(p+1), то есть O(N) на N вставок.
Поэтому копирование добавляет O(1) амортизированно на вставку, а add в целом — O(log n)
амортизированно (точнее O(log(n+1))).


### poll()

Читаем корень, переносим последний элемент в корень, обнуляем освободившуюся ссылку — O(1).
Затем siftDown выбирает меньшего ребёнка и спускается не более чем на высоту дерева — O(log n).
Лучший случай O(1), худший O(log n). Массив при удалении не уменьшается.

### peek(), size(), isEmpty()

Возвращают значение поля или элемент с индексом 0. Каждая операция — O(1).

### Память

Object[] хранит C ссылок: O(C). Несколько полей, индексы и временная переменная — O(1).
Просеивания итеративные и не создают рекурсивный стек. При расширении одновременно существуют
старый и новый массивы: пиковая память тоже O(C).

После удалений массив не уменьшается, поэтому память оценивается как O(C),
где C — текущая ёмкость массива.

## 1B. Компаратор

Меняется только правило сравнения. Для min-heap используется естественный порядок;
для max-heap — Comparator.reverseOrder(). Число уровней и алгоритмы siftUp/siftDown сохраняются.
Асимптотика всех операций совпадает с 1A. Если само сравнение стоит t, просеивание стоит O(t log n).

Добавление N элементов и их полное извлечение имеют верхнюю границу O(N log N) в обоих режимах.
Измерения min/max на одинаковых 100 000 элементах приведены в benchmarks.md.

## 2A. Хеш-таблица с линейным пробированием

Индекс рассчитывается как Math.abs((long) key.hashCode()) % C. Приведение к long сделано ДО abs,
поскольку Math.abs(Integer.MIN_VALUE) в типе int остаётся отрицательным.
Коэффициент загрузки α = n / C. При вставке нового ключа, если (n + 1) / C > 0.75,
ёмкость удваивается и занятые ячейки перехешируются.

### get(), containsKey(), remove()

Начальный индекс вычисляется за O(1), затем проверяются соседние ячейки.
При хорошем распределении хешей и небольшом количестве DELETED ожидаемое число пробирований
ограничено константой, поэтому ожидаемое время — O(1).
Если много коллизий или маркеров DELETED, возможен просмотр всех C ячеек — O(C) в худшем случае.
Цикл findIndex ограничен C итерациями, поэтому завершается даже при отсутствии ячеек EMPTY.
Удаление после поиска обнуляет ссылки, ставит DELETED и уменьшает size — O(1).

### put()

Сначала ищем ключ. Если он существует, меняем значение без расширения и изменения size.
Иначе при необходимости увеличиваем массивы, затем ищем свободную или удалённую ячейку.
Без расширения ожидаемое время O(1), худшее O(C).

Перехеширование просматривает C старых ячеек. При хорошем распределении каждая повторная вставка
требует ожидаемо O(1), поэтому расширение имеет ожидаемое время O(C).
Ёмкость удваивается, и суммарные затраты расширений на N вставок ожидаемо O(N).
Отсюда ожидаемая амортизированная оценка put — O(1).

Если все ключи имеют один хеш, повторные вставки стоят 1 + 2 + ... + n = O(n²).
Следовательно, одна вставка с расширением в худшем случае может потребовать O(C + n²),
а не гарантированное O(n). При пороге расширения n пропорционально C, это O(n²).

Маркеры DELETED удаляются при перехешировании. До этого их накопление может увеличивать
длину поиска, поэтому оценка O(1) предполагает небольшое количество таких маркеров.

### size(), capacity()

Читают поле или длину массива — O(1).

### Память

Массив ключей, массив значений и массив состояний имеют длину C. Всего O(C) дополнительной памяти,
не считая содержимого самих ключей и значений. При расширении старые и новые массивы существуют
одновременно, что увеличивает константу, но оставляет O(C).
После удаления ёмкость не уменьшается, поэтому память зависит от C, а не только от числа записей.
