# Расчёт сложности задачи 35. Префиксные суммы

`n` — число элементов массива. `q` — количество запросов.
По условию `1 < n < 100000`, входные элементы имеют тип `int`.
Дополнительная память указана без входного массива. Операции над `int` и `long` считаются постоянными.

## Время алгоритма

Строится массив длины `n + 1`: `prefix[0] = 0`,
`prefix[i + 1] = prefix[i] + numbers[i]`. Выполняются `n` сложений: подготовка — `Θ(n)`.
Для отрезка `[l, r]` ответ равен `prefix[r + 1] - prefix[l]`.
Это два обращения к массиву и одно вычитание: один запрос — `Θ(1)`.
Для `q` запросов: `T(n, q) = c₁n + c₂q + c₃ = Θ(n + q)`.
Формула верна, потому что из суммы первых `r + 1` элементов вычитаются элементы перед `l`.

## Память

Массив префиксов из `n + 1` значений `long` требует `Θ(n)` дополнительной памяти.
Вместе с входным массивом вся программа использует `Θ(n)` памяти.
Запросы читаются и обрабатываются по одному, отдельный массив запросов не создаётся.

## С учётом ввода и вывода

Чтение массива требует `Θ(n)` времени, чтение и вывод `q` запросов — `Θ(q)`.
Итоговое время с вводом-выводом — `Θ(n + q)`.

## Числовые границы

При заданных ограничениях модуль любой суммы не превышает
`99999 · 2147483648 = 214746217316352 < Long.MAX_VALUE`.
Поэтому суммы хранятся в `long`, входные значения — в `int`.
Это относится и к префиксам, и к ответам на запросы: каждый ответ является суммой отрезка.
