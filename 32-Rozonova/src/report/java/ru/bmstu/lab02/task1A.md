# Отчет по Лабораторной работе №2 — Задача 1А

## 1. Архитектура и идея решения
Структура `PriorityQueueCustom<T>` реализована на основе бинарной мин-кучи (Binary Min-Heap), хранящейся во внутреннем динамическом массиве `Object[]`. 
- Левый ребенок узла с индексом `i` находится на позиции `2 * i + 1`.
- Правый ребенок — на позиции `2 * i + 2`.
- Родительский узел — на позиции `(i - 1) / 2`.

Для поддержания инварианта кучи используются приватные методы:
- `siftUp(int index)` — просеивание элемента вверх (используется при добавлении в конец).
- `siftDown(int index)` — просеивание элемента вниз (используется при извлечении корня).

## 2. Анализ асимптотической сложности
- **`add(T item)`**: $O(\log n)$ в худшем случае (при подъеме элемента от листьев до корня) и $O(1)$ амортизированное при расширении массива.
- **`poll()`**: $O(\log n)$ (замена корня последним элементом и погружение его вниз по куче).
- **`peek()`**: $O(1)$ (доступ к первому элементу массива `data[0]`).
- **`size()` / `isEmpty()`**: $O(1)$.
- **Память (Space Complexity)**: $O(n)$ для хранения элементов в массиве.

## 3. Тестирование
Реализовано 11 модульных тестов (JUnit 5), покрывающих стандартные сценарии, дубликаты, отрицательные числа, работу с пустыми коллекциями, граничные случаи и автоматическое изменение размера массива при добавлении большого количества элементов (100+).
