# Отчет по задаче 27: Сумма квадратов

## 1. Идея решения и структура данных
**Идея:** Алгоритм совершает один проход по массиву слева направо. На каждом шаге элемент возводится в квадрат и прибавляется к общей сумме. Главная особенность: для предотвращения целочисленного переполнения типа `int`, которое может произойти уже на этапе возведения элемента в квадрат, текущее значение принудительно приводится к типу `long` перед умножением. Результат также накапливается в переменной типа `long`.

**Структура данных:** Базовый массив `int[]`. Для хранения суммы используется переменная типа `long`.

## 2. Анализ асимптотики
**Временная сложность: $O(n)$**

Обоснование на основе кода:
```java
long sum = 0;
for (int num : arr) {
    sum += (long) num * num;
}
```
Алгоритм использует один цикл `for`, выполняющий ровно $n$ итераций. Внутри цикла происходит операция умножения и сложения за константное время $O(1)$. Итоговая сложность — $O(n)$.

**Дополнительная память: $O(1)$**
Для вычислений используется только локальная переменная `sum` примитивного типа `long` и итератор цикла. Объем необходимой памяти не зависит от длины входного массива и равен $O(1)$.

## 3. Ручные тесты
1. **Массив с положительными числами**
   - *Вход:* `3 | 1 2 3`
   - *Выход:* `14`
   - *Значимость:* Проверяет базовую логику суммирования квадратов ($1^2 + 2^2 + 3^2$).
2. **Массив с нулями и отрицательными числами**
   - *Вход:* `3 | -2 0 -3`
   - *Выход:* `13`
   - *Значимость:* Гарантирует, что алгоритм корректно обрабатывает отрицательные числа и нули.
3. **Граничный случай с большими числами (проверка переполнения)**
   - *Вход:* `2 | 100000 100000`
   - *Выход:* `20000000000`
   - *Значимость:* Гарантирует корректность вычислений при превышении лимита типа `int`.
