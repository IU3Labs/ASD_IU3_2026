# Отчет по задаче 25: Сумма элементов

## 1. Идея решения и структура данных
**Идея:** Алгоритм совершает один проход по массиву слева направо, последовательно прибавляя каждый элемент к общей сумме. Главная особенность: для хранения результата используется тип `long`, что предотвращает целочисленное переполнение в случае, если массив состоит из больших чисел.

**Структура данных:** Базовый массив `int[]`. Для хранения накапливаемой суммы используется одна переменная типа `long`.

## 2. Анализ асимптотики
**Временная сложность: $O(n)$**

Обоснование на основе кода:
```java
long sum = 0;
for (int num : arr) {
    sum += num;
}
```
В алгоритме используется ровно один цикл `for`, который выполняет $n$ итераций. Внутри цикла происходит базовая операция сложения, выполняемая за константное время $O(1)$. Итоговая сложность строго линейная — $O(n)$.

**Дополнительная память: $O(1)$**
Алгоритм не создает новых массивов. Дополнительная память ограничивается выделением памяти под переменную `sum` типа `long` и итератор цикла, что никак не зависит от размера входного массива $n$.

## 3. Ручные тесты
1. **Массив с небольшими положительными числами**
   - *Вход:* `5 | 1 2 3 4 5`
   - *Выход:* `15`
   - *Значимость:* Проверяет базовую логику накопления суммы массива.
2. **Массив с нулями и отрицательными числами**
   - *Вход:* `6 | -10 5 0 -6 10 0`
   - *Выход:* `-1`
   - *Значимость:* Гарантирует корректную работу со знаками (компенсация положительных и отрицательных значений) и нейтральным элементом сложения.
3. **Граничный случай с большими числами**
   - *Вход:* `2 | 2000000000 2000000000`
   - *Выход:* `4000000000`
   - *Значимость:* Гарантирует, что при превышении лимита типа `int` (~2.14 млрд) алгоритм не уйдет в отрицательные значения, так как накопитель использует тип `long`.
