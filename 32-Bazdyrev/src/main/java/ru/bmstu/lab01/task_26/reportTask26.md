# Отчет по задаче 26: Произведение элементов

## 1. Идея решения и структура данных
**Идея:** Алгоритм проходит по массиву один раз, последовательно умножая текущее накопленное произведение на очередной элемент. Для предотвращения переполнения типа `int` (и даже `long` при множественных умножениях) на каждом шаге берется остаток от деления на $10^9 + 7$. Важной особенностью является корректная обработка отрицательных чисел: так как в Java операция `%` сохраняет знак делимого, к результату предварительно прибавляется модуль, чтобы значение всегда оставалось в кольце вычетов.

**Структура данных:** Базовый массив `int[]`. Для хранения накапливаемого произведения и промежуточных вычислений используется тип `long`. Константа модуля — $10^9 + 7$.

## 2. Анализ асимптотики
**Временная сложность: $O(n)$**

Обоснование на основе кода:
```java
long product = 1;
for (int num : arr) {
    long val = num % MOD;
    if (val < 0) val += MOD;
    product = (product * val) % MOD;
}
```
Алгоритм совершает один линейный проход циклом `for` по всем $n$ элементам массива. Операции взятия по модулю, сложения и умножения внутри цикла выполняются за константное время $O(1)$. Общая временная сложность составляет $O(n)$.

**Дополнительная память: $O(1)$**
Создаются только локальные переменные `product` и `val` примитивного типа `long`. Их размер не зависит от размера входного массива, поэтому затраты дополнительной памяти равны $O(1)$.

## 3. Ручные тесты
1. **Массив с нулём**
   - *Вход:* `5 | 100 500 0 999 1`
   - *Выход:* `0`
   - *Значимость:* Гарантирует корректную работу при умножении на 0.
2. **Отрицательные элементы**
   - *Вход:* `3 | -1 -1 -1`
   - *Выход:* `1000000006`
   - *Значимость:* Проверяет логику `(val % MOD + MOD) % MOD`.
3. **Граничный случай с большими числами (проверка переполнения)**
   - *Вход:* `2 | 1000000000 1000000000`
   - *Выход:* `49`
   - *Значимость:* Гарантирует отсутствие целочисленного переполнения.
