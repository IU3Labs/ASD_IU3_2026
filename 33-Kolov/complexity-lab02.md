# Расчёт сложности: очередь с приоритетом, задачи 1A–1D

## Обозначения и модель

`n` — число элементов, `c` — ёмкость массива. Сравнение компаратором,
`compareTo` и `equals` считаются O(1); если сравнение объектов дороже,
его стоимость нужно дополнительно учитывать. Высота полной двоичной кучи — O(log n).
Массив содержит ссылки, а не копии самих объектов. Стабильность порядка
элементов с одинаковым приоритетом не гарантируется.

## Итоговые оценки

| Операция | Время | Дополнительная память операции |
|---|---|---|
| Пустой конструктор | O(1) | O(1), начальная ёмкость фиксирована |
| Конструктор из массива | O(n) | O(n), собственная копия ссылок |
| `add` без расширения | O(log n) в худшем случае | O(1) |
| `add` с расширением | O(n) | O(n) на новый массив |
| `add`, амортизированная оценка | O(log n) | O(n) суммарно под массив |
| `peek`, `size`, `isEmpty` | O(1) | O(1) |
| `poll` | O(log n) | O(1) |
| `remove` | O(n) | O(1) |

Память очереди — O(c). При последовательном росте c = O(max(1, n)).
После массового удаления массив не сжимается: тогда ёмкость определяется
максимальным прежним размером, а не текущим n. Старые ссылки за границей
текущего размера очищаются, поэтому удалённые объекты не удерживаются кучей.

## Задача 1A: добавление и извлечение

Элемент добавляется в конец массива и поднимается через `siftUp`.
Каждый переход идёт к родителю `(i - 1) / 2`; переходов не больше высоты кучи.
Следовательно, без расширения `add` требует O(log n).

При заполнении массива создаётся массив удвоенной ёмкости и копируются n ссылок.
Одна такая вставка занимает O(n), а не O(log n). За m последовательных вставок
сумма объёмов копирования образует геометрическую прогрессию и равна O(m),
поэтому копирование добавляет O(1) амортизированно на вставку.
С учётом просеивания итог — O(log n) амортизированно.
Это уточнение необходимо: буквальное O(log n) в худшем случае для каждой
вставки несовместимо с обычным расширением сплошного динамического массива.

`poll` заменяет корень последним элементом и выполняет `siftDown`.
На каждом уровне выбирается более приоритетный из детей `2*i+1`, `2*i+2`.
Проходится не более O(log n) уровней. Массив при извлечении не сжимается.
`peek` читает корень, а `size` и `isEmpty` используют поле размера: O(1).

## Задача 1B: компаратор

Все сравнения сосредоточены в одном методе. При отсутствии компаратора
используется `Comparable`, при его наличии — `Comparator.compare`.
Обращение порядка сравнений меняет min-heap на max-heap, но высота и число
переходов остаются прежними. Асимптотика операций не изменяется.

## Задача 1C: удаление по значению

Сначала выполняется линейный поиск совпадения по `equals`: O(n).
Удаляется первое совпадение в порядке индексов внутреннего массива.
Последний элемент переносится на освободившееся место.
Если он приоритетнее родителя, требуется `siftUp`, иначе — `siftDown`.
Выбор только просеивания вниз был бы ошибкой для некоторых внутренних узлов.
Восстановление занимает O(log n); O(n) + O(log n) = O(n).
Удаление последнего элемента не требует просеивания.

## Задача 1D: построение за O(n)

Конструктор проверяет и копирует n элементов за O(n), затем просеивает узлы
от `n / 2 - 1` до нуля. Листья не обрабатываются: они уже являются кучами.

У большинства узлов малая высота. Не более порядка n / 2^(h+1) узлов
могут требовать работу порядка h. Поэтому суммарная работа ограничена:

`O(n * (1/2 + 2/4 + 3/8 + ...)) = O(n)`.

Ряд сходится к константе; добавление копирования не меняет O(n).
Нельзя оценивать этот алгоритм только как n одинаковых просеиваний по log n:
это не учитывает распределение узлов по высотам.

Альтернатива — n вызовов add — имеет O(n log n) в худшем случае.
На случайном входе она может работать ближе к линейному времени; бенчмарк
не заменяет доказательство оценки худшего случая.
