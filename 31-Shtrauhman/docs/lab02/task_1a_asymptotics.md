# Задача 1A. `PriorityQueueCustom` — асимптотика

**Структура:** двоичная min-куча в массиве. Для узла `i`: дети `2i + 1`, `2i + 2`, родитель `(i − 1) / 2`.

## Высота кучи

Куча — полное двоичное дерево: все уровни, кроме последнего, заполнены. На уровне `k` не больше `2^k` узлов,
поэтому при n элементах высота

h = ⌊log₂ n⌋ = **O(log n)**.

## Время операций

| Операция | Что делает | Оценка |
|---|---|---|
| `add` | запись в конец + `siftUp`: не более h сравнений и сдвигов (от листа к корню) | O(log n) амортизированно |
| `poll` | последний элемент в корень + `siftDown`: на каждом уровне 2 сравнения, уровней не больше h | O(log n) |
| `peek` | чтение `heap[0]` | O(1) |
| `size`, `isEmpty` | чтение поля | O(1) |

**Почему `add` — амортизированно.** Когда массив заполнен, он копируется в новый массив вдвое большего размера (O(n)).
Пусть до n вставок было k расширений ёмкостей c₀, 2c₀, …, 2^(k−1)c₀ ≤ n. Суммарно скопировано

c₀ + 2c₀ + … + 2^(k−1)c₀ < 2^k c₀ ≤ 2n,

то есть на одну вставку в среднем приходится O(1) копирований. Итог: O(1) амортизированно на расширение
плюс O(log n) на `siftUp` — **O(log n)**.

**Цикл «n раз add + n раз poll»** (замер в `benchmarks.md`): Σ log i для i от 1 до n = log n! = **O(n log n)**.

## Память

- Массив `heap`: не меньше n и (из-за удвоения) не больше 2n ячеек, начальная ёмкость 16 — **O(n)**.
- `siftUp` / `siftDown` итеративные, дополнительная память — **O(1)** (без рекурсии и стека вызовов).
- Ячейка извлечённого элемента обнуляется, поэтому очередь не удерживает ссылки на извлечённые объекты.

## Корректность порядка извлечения

После `siftUp` и `siftDown` для каждого узла выполняется `heap[parent] ≤ heap[child]`. Отсюда по транзитивности
корень — минимум всей кучи, поэтому каждый `poll` возвращает минимум оставшихся элементов,
и последовательность извлечений не убывает.
