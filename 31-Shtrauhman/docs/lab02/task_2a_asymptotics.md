# Задача 2A. `HashMapCustom` — асимптотика

**Структура:** открытая адресация, два массива (`keys`, `values`) длины `capacity`, линейное пробирование
`index → (index + 1) % capacity`, маркер `DELETED` для удалённых ячеек.

Обозначения: n — число ключей, m — ёмкость, d — число маркеров `DELETED`,
α = (n + d) / m — коэффициент загрузки с учётом маркеров. Инвариант реализации: **α ≤ 0.75** после каждой операции.

## Почему поиск всегда завершается

Цикл пробирования останавливается на пустой (`null`) ячейке. Так как занято не больше 0.75·m ячеек,
пустая ячейка всегда есть, и любая цепочка проходит не больше m ячеек.

## Время операций

Оценки для линейного пробирования при равномерном хешировании (Кнут, «Искусство программирования», т. 3, §6.4).
Среднее число проверенных ячеек:

- успешный поиск: ½ · (1 + 1 / (1 − α));
- неуспешный поиск: ½ · (1 + 1 / (1 − α)²).

При α ≤ 0.75 это не больше **2.5** и **8.5** ячеек соответственно, то есть константа.

| Операция | Что делает | Среднее | Худшее |
|---|---|---|---|
| `get`, `containsKey` | поиск по цепочке до ключа или `null` | O(1) | O(n) |
| `remove` | поиск + запись `DELETED` | O(1) | O(n) |
| `put` (ключ есть) | поиск + замена значения | O(1) | O(n) |
| `put` (ключа нет) | неуспешный поиск + вставка в первую `null`/`DELETED` ячейку цепочки | O(1) амортизированно | O(n) |
| `size`, `capacity` | чтение поля | O(1) | O(1) |

Худший случай O(n) — все ключи в одной цепочке (именно его моделирует задача 2C).

## Перехеширование и амортизация

Перед вставкой проверяется n + d + 1 > 0.75·m. Если да — все живые ключи переносятся в новые массивы, маркеры исчезают:

- если n + 1 > 0.375·m (половина порога) — ёмкость удваивается;
- иначе — ёмкость прежняя (порог превышен в основном маркерами `DELETED`).

Перенос стоит O(m). После него загрузка не выше ≈ 0.375 от новой ёмкости m', а следующий перенос возможен
только когда заполненность снова дойдёт до 0.75·m'. Каждая операция увеличивает заполненность не больше чем на 1,
значит, между переносами проходит не меньше 0.375·m' операций. Стоимость O(m') распределяется на Ω(m') операций —
**O(1) амортизированно**.

Без варианта «та же ёмкость» таблица при чередовании `put`/`remove` росла бы бесконечно, а без границы 0.375·m
перенос мог бы повторяться каждые несколько операций, когда число ключей держится у порога
(оба случая проверяются тестами `shouldNotGrowWhenPutAndRemoveAlternate` и
`shouldStayCorrectAndBoundedUnderChurnNearThreshold`).

## Память

- Два массива по m ячеек. Без удалений m < n / 0.375 ≈ 2.67n (сразу после удвоения загрузка ≈ 0.375) — **O(n)**.
- Объекты-обёртки для пар (как `Entry` в `java.util.HashMap`) не создаются.
- Пробирование итеративное, дополнительная память на операцию — **O(1)**; при перехешировании временно O(m)
  под старые массивы.

## Хеш-функция

`Math.abs(key.hashCode()) % capacity` — по условию. Единственный особый случай: `Math.abs(Integer.MIN_VALUE)`
переполняется и остаётся отрицательным, остаток тогда тоже отрицателен; к нему добавляется `capacity`.
Это O(1) и не меняет результат для остальных хеш-кодов.
