# Задача 3C. `Distinct.distinct` — асимптотика

**Алгоритм:** один проход по списку. Для каждого элемента — `containsKey` в `HashMapCustom` (множество уже
встреченных). Если элемента ещё не было — `put` в таблицу и добавление в конец результирующего `ArrayList`.
Для `null` вместо таблицы используется флаг.

Обозначения: n — длина входа, u — число уникальных элементов (u ≤ n).

## Время

- n вызовов `containsKey` — O(1) в среднем каждый (задача 2A);
- u вызовов `put` — O(1) амортизированно каждый;
- u добавлений в `ArrayList` — O(1) амортизированно (удвоение массива, как в задаче 1A).

T(n) = n · O(1) + u · O(1) = **O(n)** в среднем.

Худший случай — все элементы с одинаковым хешем (как в 2C): i-я проверка проходит цепочку длины до i,
T(n) = **O(n · u)**, при u = n — O(n²).

Для сравнения: `new LinkedHashSet<>(items)` — тоже O(n) в среднем; в худшем случае `HashMap` превращает длинную
корзину в красно-чёрное дерево, но только для ключей, реализующих `Comparable` (тогда O(n log n)).

## Память

- `HashMapCustom` на u ключей: два массива ёмкостью не больше ≈ 2.67u (см. задачу 2A) — O(u);
- результирующий список: O(u);
- значение в таблице — общий `Boolean.TRUE`, новых объектов на элемент не создаётся.

Итого дополнительная память **O(u)**, в худшем случае O(n).

`LinkedHashSet` хранит на каждый уникальный элемент объект `LinkedHashMap.Entry` (хеш, ключ, значение, ссылки
`next`, `before`, `after` — около 40 байт), а открытая адресация — только по одной ссылке в двух массивах
и одну в списке. Поэтому по памяти собственная реализация выигрывает, асимптотически обе — O(u).
