# Отчёт по ЛР1 (Штраухман, группа 31)

Основные задачи: 25, 30, 32, 49, 58.
Запасные задачи: 27, 34 и 48.

Каждая задача лежит в своём пакете `ru.bmstu.lab01.task_<номер>` и содержит:
- `solve`-метод (чистая функция, тестируется отдельно);
- `run(InputStream, PrintStream)` — чтение и вывод через потоки, чтобы тестировать ввод-вывод без `System.in`;
- `main` — вызывает `run(System.in, System.out)`.

Общий код ввода-вывода вынесен в пакет `common` (`TokenReader`, `OutputFormat`), чтобы не дублировать его.
Расчёты асимптотики — в файлах `task_<номер>_asymptotics.md` рядом с отчётом.

## Задача 25. Сумма элементов

**Идея.** Один проход с накоплением в `long`. Структура данных — обычный массив.
**Асимптотика.** Время O(n), память O(1) сверх входа.
**Ручные тесты и зачем они нужны:**
- `[1 2 3 4 5] → 15` — базовый случай;
- `[-10 4 3] → -3` — смешанные знаки;
- `[MAX, MAX] → 4294967294` — проверка, что сумма не переполняет `int`;
- 99 999 элементов `Integer.MIN_VALUE` — максимальный размер и самое большое по модулю значение.

## Задача 27. Сумма квадратов

**Идея.** Один проход: квадрат элемента считается в `long` (для `int` это безопасно), сумма копится в `BigInteger`,
потому что сумма 10⁵ квадратов (~4,6 · 10²³) не помещается в `long`.
**Асимптотика.** Время O(n), память O(1).
**Ручные тесты и зачем они нужны:**
- `[1 2 3] → 14` — базовый случай;
- `[-3 4] → 25` — знак не влияет, квадрат всегда неотрицателен;
- `[Integer.MIN_VALUE] → 2⁶²` — самый большой квадрат, ещё помещается в `long`;
- 99 999 элементов `Integer.MIN_VALUE` — здесь `long` переполнился бы, это обоснование выбора `BigInteger`.

## Задача 30. Дисперсия

**Идея.** D = (1/n) Σ(aᵢ − μ)². В тексте условия формула отсутствует, поэтому деление на n выбрано по решению автора работы; при необходимости заменить на n − 1 достаточно изменить
одну строку в `variance`. Использован двухпроходный алгоритм (устойчивее, чем E[x²] − E[x]²).
**Асимптотика.** Время O(n), память O(1).
**Вывод.** Шесть знаков после точки, разделитель — точка независимо от региона (`Locale.ROOT`).
**Ручные тесты:**
- `[1 2 3 4] → 1.25` — посчитано вручную: Σ отклонений² = 5, 5/4;
- `[42] → 0` и `[7 7 7 7] → 0` — нулевой разброс;
- `[-1 1] → 1` — отрицательные числа;
- `[10⁹−1, 10⁹+1] → 1` — именно здесь однопроходная формула дала бы неверный результат;
- пустой массив → `IllegalArgumentException`, чтобы не делить на 0.

## Задача 32. Сумма произведений пар

**Идея.** Σ_{i<j} aᵢaⱼ = ((Σaᵢ)² − Σaᵢ²) / 2. Вместо перебора O(n²) пар — один проход.
**Асимптотика.** Время O(n), память O(1). Результат считается в `BigInteger`, так как не помещается в `long`.
**Ручные тесты:**
- `[1 2 3] → 11` (1·2 + 1·3 + 2·3);
- `[5] → 0` — пар нет;
- `[2 -3] → -6` — отрицательный ответ;
- 200 случайных массивов сравниваются с перебором O(n²) — защита от ошибки в формуле;
- массивы с `Integer.MAX_VALUE` и `Integer.MIN_VALUE`, а также 99 999 элементов `MAX_VALUE` — проверка переполнения.

## Задача 34. Максимальная сумма подмассива

**Идея.** Алгоритм Кадане: для каждой позиции хранится наибольшая сумма подмассива, заканчивающегося в ней
(`current = max(a[i], current + a[i])`); ответ — максимум по всем позициям. Если накопленная сумма стала
отрицательной, выгоднее начать подмассив заново.
**Асимптотика.** Время O(n), память O(1). Наивный перебор подмассивов дал бы O(n²) и не подходит по условию.
**Допущение.** Подмассив непустой, поэтому для одних отрицательных чисел ответ — наибольший элемент, а не 0.
**Ручные тесты и зачем они нужны:**
- `[-2 1 -3 4 -1 2 1 -5 4] → 6` — классический пример (подмассив `[4 -1 2 1]`);
- `[-3 -1 -2] → -1` — все числа отрицательные: проверка, что ответ не обнуляется;
- `[5 -1 5] → 9` — выгодно пройти через отрицательное число;
- лучший подмассив в начале (`[4 6 -20 3] → 10`) и в конце (`[3 -20 4 6] → 10`);
- 300 случайных массивов сравниваются с перебором O(n²) — защита от ошибки в самом алгоритме;
- 99 999 элементов `Integer.MAX_VALUE` — самая большая возможная сумма, проверка, что `long` не переполняется;
- пустой массив → `IllegalArgumentException`.

## Задача 48. Транспонирование матрицы

**Идея.** Обмен `a[i][j]` и `a[j][i]` только выше главной диагонали, иначе каждая пара поменялась бы дважды и вернулась на место.
**Асимптотика.** Время O(n²), память O(1): новая матрица не создаётся.
**Формат.** Вход: `n`, затем n строк по n чисел; выход: транспонированная матрица построчно.
**Ручные тесты:**
- `[[1,2],[3,4]] → [[1,3],[2,4]]` и `3×3` с числами от 1 до 9 — проверено вручную;
- `1×1` и симметричная матрица не меняются;
- двойное транспонирование возвращает исходную матрицу — быстрая проверка корректности обмена на матрице 4×4;
- строки после операции остаются теми же объектами — это доказывает, что работа идёт на месте;
- неквадратная матрица `2×3` → `IllegalArgumentException`.

## Задача 49. Сумма строк матрицы

**Идея.** Двойной цикл, сумма каждой строки в `long`.
**Асимптотика.** Время O(n·m), дополнительная память O(n) под результат.
**Формат.** Вход: `n m`, затем n строк по m чисел; выход — n сумм через пробел в одной строке.
**Ручные тесты:**
- `[[1 2 3],[4 5 6]] → 6 15`;
- один столбец и одна строка — вырожденные размеры;
- строка из двух `Integer.MAX_VALUE` → `4294967294`;
- отрицательные числа и нулевая сумма.

## Задача 58. Матрица змейкой

**Идея.** Значение ячейки считается по формуле через чётность строки, без разворота строк.
**Асимптотика.** Время и память O(n·m) — размер самого результата.
**Формат.** Вход: `n m`; выход: n строк по m чисел через пробел.
**Ручные тесты:**
- `3×4` → строки `1 2 3 4`, `8 7 6 5`, `9 10 11 12` — проверено вручную;
- `1×1`, `1×5`, `3×1` — вырожденные размеры (в столбце направление строки не видно, но формула должна давать 1, 2, 3);
- матрица 7×9: каждое число от 1 до 63 встречается ровно один раз — проверка, что нет пропусков и повторов;
- `100000×100000` → `ArithmeticException` до выделения памяти.
