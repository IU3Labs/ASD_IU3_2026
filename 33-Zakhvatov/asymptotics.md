n — число элементов, C — ёмкость таблицы, u — число уникальных элементов,
L — длина текста. Для числовых ключей сравнение и хеширование считаются O(1).

## 1A, 1B: очередь

Высота бинарной кучи O(log(n+1)). siftUp переходит к родителю (i−1)/2,
siftDown — к одному из детей 2i+1, 2i+2. На каждом уровне O(1) сравнений.

| Операция | Время |
|---|---|
| Конструктор пустой очереди | O(1) |
| add без расширения | O(log(n+1)) |
| add при расширении массива | O(n) в этом вызове |
| add амортизированно | O(log(n+1)) |
| poll | O(log(n+1)) |
| peek, size, isEmpty | O(1) |

Сумма копирований при удвоении массива: 16+32+…+2^p=O(n).
Поэтому копирование даёт амортизированное O(1) на вставку. Строгая O(log n)
для каждого вызова add несовместима с обычным расширением одного массива.
Min-heap и max-heap отличаются только порядком сравнения, оценки одинаковы.
Память O(H), где H — максимальная достигнутая ёмкость: после удаления массив не сжимается.

## 1D: heapify

Конструктор идёт от последнего внутреннего узла к корню. Узлов высоты h
не больше n/2^(h+1), просеивание такого узла стоит O(h). Поэтому
сумма n * h/2^(h+1) по всем h равна O(n). Копирование входа требует Ω(n),
итого Θ(n) времени и O(n) памяти. Последовательные add требуют O(n log n)
в худшем случае. Просеивание итеративное, его временная память O(1).

## 2A, 2B: таблица

Линейное пробирование: (base+i) mod C. Квадратичное: (base+i+2i²) mod C,
где C=2^p. Начальный индекс — abs((long) hashCode) mod C.

Для f(i)=i+2i² разность f(i)−f(j)=(i−j)(1+2(i+j)). Второй множитель
нечётный и взаимно прост с C. Поэтому равенство индексов означает, что C делит
разность i−j. Для 0<=i,j<C это возможно только при i=j: обход посещает все ячейки.

| Операция | Ожидаемое время при равномерных хешах | Худшее время |
|---|---|---|
| Конструктор | O(1) | O(1) |
| get, containsKey, remove | O(1) | O(C) |
| put без перехеширования | O(1) | O(C) |
| put с учётом перехеширования | O(1) амортизированно | O(C+n²) |
| size, capacity, чтение/сброс статистики проб | O(1) | O(1) |
| snapshotKeys для результата 3B | O(C) | O(C) |

При одинаковых хешах вставка i-го ключа требует O(i) проб. Поэтому
перехеширование может стоить O(n²), а не только O(C).
При хороших хешах удвоения дают геометрическую сумму стоимости O(n).
Живые пары занимают не более 3/4 C; если живые пары вместе с DELETED
при вставке превысят 7/8 C, маркеры очищаются при той же ёмкости.
После очистки до следующей нужно использовать ещё порядка C/8 ячеек,
поэтому её ожидаемая стоимость O(C) распределяется на Ω(C) операций.
Память двух массивов O(C), в том числе во время перехеширования.
После удаления ёмкость не уменьшается. snapshotKeys выделяет O(n) памяти.

## 3A: Top-K

Куча содержит k наибольших элементов просмотренной части входа. Если новый
элемент больше минимума, минимум заменяется. На элемент требуется O(log(k+1)),
извлечение результата требует O(k log(k+1)). При k<=n итог O(n log(k+1)),
то есть O(n log k) для k>=2; при k=1 — O(n), при k=0 — O(1).
Обход через iterator не зависит от того, массив или связный список лежит во входе.
Память кучи и результата O(k+1). Минимумы записываются с конца, результат идёт по убыванию.

## 3B: частота слов

Нормализация регистра и разбор текста требуют O(L). При хороших хешах поиск
и обновление счётчика требуют ожидаемое O(1) проб; стоимость хеширования
и сравнений строк учитывается их длинами. Итоговое ожидаемое время O(L),
память O(L+u) на нормализованный текст, строки слов, таблицу и результат.
При патологических коллизиях время может достигать O(w*u*ℓmax+L),
где w — число слов, ℓmax — максимальная длина слова.
Map.get/containsKey — ожидаемое O(1) проб; size/isEmpty — O(1).
Создание values/entrySet и проход по карте — ожидаемое O(u) для коротких ключей.
Сортировка для вывода топ-10 выполняется только в бенчмарке и не входит в countWords.

## 3C: уникальные элементы

Список просматривается один раз. На каждый элемент приходится проверка таблицы
и не более одной вставки. Результатный массив растёт вдвое, сумма копирований O(u).
Ожидаемое время O(n), худшее O(nu) при одинаковых хешах, память O(u+1).
Null хранится один раз с помощью отдельного флага.

## Результаты List и Set

ResultList.get/size — O(1); поиск, сравнение, хеширование, копирование и subList — O(r).
Его итератор создаётся за O(1), переход — O(1). ResultSet хранит уже уникальные
элементы без отдельного индекса: contains — O(r), создание итератора — O(r).
Здесь r — число просмотренных или скопированных элементов результата.
Операции изменения бросают UnsupportedOperationException за O(1).
