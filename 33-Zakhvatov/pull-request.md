# lab02-Zakhvatov-33: Лабораторная работа №2 — структуры данных

ФИО: Захватов Антон

Группа: ИУ3-33Б

Лабораторная работа: №2

Задачи: **1A, 1B, 1D, 2A, 2B, 3A, 3B, 3C — 18 баллов**.

## Реализовано

- 1A: PriorityQueueCustom на динамическом массиве с отдельными siftUp и siftDown.
- 1B: Comparator для min-heap/max-heap, сравнение на 100 000 одинаковых случайных элементов.
- 1D: копирующий конструктор массива с bottom-up heapify и сравнением с последовательными add.
- 2A: HashMapCustom с линейным пробированием, DELETED и удвоением при загрузке выше 0.75.
- 2B: квадратичное пробирование i+2i² при ёмкости 2^p; доказан полный обход,
  сравнено число проб на 50 000 get.
- 3A: Top-K с собственной min-heap, проверка сортировкой, замер на 1 000 000 элементов.
- 3B: частоты слов без учёта регистра, собственная таблица и Map-адаптер;
  обработан синтетический UTF-8-корпус 1 048 578 байт, выведены 10 самых частых слов.
- 3C: уникальные элементы в порядке первого появления; сравнение с LinkedHashSet по времени и памяти.

Готовые реализации коллекций используются только в тестах и бенчмарках.
Собственные результаты List/Map неизменяемые; исходные списки и массивы не изменяются.
Для abs(hashCode) сначала используется long, чтобы корректно обработать Integer.MIN_VALUE.
Очистка маркеров удаления выполняется при превышении 7/8 использованных ячеек;
живые пары по-прежнему ограничены порогом 3/4.

## Асимптотика

| Операции | Время | Память структуры / алгоритма |
|---|---|---|
| Очередь: add | O(log n) амортизированно, O(n) при расширении | O(H), H — максимальная ёмкость |
| Очередь: poll | O(log n) | O(H) |
| Очередь: peek, size, isEmpty | O(1) | O(H) |
| Построение кучи из массива | O(n) | O(n) |
| Таблица: put | Ожидаемо O(1) амортизированно; худшее O(C+n²) при перехешировании | O(C) |
| Таблица: get, containsKey, remove | Ожидаемо O(1), худшее O(C) | O(C) |
| Таблица: size, capacity, статистика проб | O(1) | O(1) сверх массивов |
| Top-K | O(n log(k+1)), k=0 — O(1) | O(k+1) |
| Частота слов | Ожидаемо O(L), L — длина текста | O(L+u) |
| Уникальные элементы | Ожидаемо O(n), худшее O(nu) | O(u+1) |

Предположения о хешах, стоимость строк и расчёты приведены в
[asymptotics.md](./asymptotics.md), идеи и ручные примеры — в [report.md](./report.md).

## Выводы

Время зависит от входных данных, JIT, сборки мусора и внутреннего устройства реализации; локальные результаты не доказывают превосходство на других нагрузках.
Массивы собственной таблицы не требуют объектов-узлов для каждой пары, но расширение и упаковка чисел также выделяют память.
Показатель памяти — суммарные выделения текущего потока за один прогон, а не размер удерживаемой кучи или пиковое потребление процесса.
При небольшом k Top-K хранит только k кандидатов, тогда как полная сортировка копирует весь вход.
