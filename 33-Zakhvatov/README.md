# Лабораторная работа №2 — структуры данных

ФИО: Захватов Антон. Группа: ИУ3-33Б.

Реализованы задачи **1A + 1B + 1D + 2A + 2B + 3A + 3B + 3C** — **18 баллов** при необходимых 7.
Основание: [условие ЛР2](../tasks/task-lab02.md), [стиль](../docs/style-guide.md),
[критерии оценки](../docs/grading.md) и [порядок сдачи](../docs/how-to-submit.md).

| Задача | Реализация | Баллы |
|---|---|---:|
| 1A | Собственная очередь на расширяемом массиве, siftUp/siftDown | 2 |
| 1B | Естественный порядок и Comparator: min-heap/max-heap | 2 |
| 1D | Копирующий конструктор с bottom-up heapify за O(n) | 2 |
| 2A | Собственная хеш-таблица с линейным пробированием | 3 |
| 2B | Квадратичное пробирование с полным обходом таблицы | 3 |
| 3A | k наибольших элементов через собственную min-heap | 2 |
| 3B | Частота слов через собственную таблицу, обработка корпуса около 1 МиБ | 2 |
| 3C | Уникальные элементы в порядке появления через собственную таблицу | 2 |

## Сборка и проверки

Из корня репозитория, Maven и JDK 21 или новее:

```sh
mvn -pl 33-Zakhvatov clean verify
```

Команда проверяет Checkstyle для основного и тестового кода, запускает JUnit 5,
строит отчёт JaCoCo и завершится ошибкой при покрытии строк основного кода ниже 80%.
HTML-отчёт находится в `target/site/jacoco/index.html` внутри модуля.
JUnit 5.11.4 задан локально: родительский проект использует другую версию JUnit.
Параметр `release=21` фиксирует минимальную версию байткода только этого модуля.
Для сборки **всех** модулей родительского проекта нужен JDK 25 или новее:

```sh
mvn clean verify
```

Бенчмарки запускаются отдельно, после обычных тестов:

```sh
mvn -pl 33-Zakhvatov -Pbenchmarks test
```

Этот профиль отключает агент JaCoCo только для измерений и перезаписывает
[benchmarks.md](./benchmarks.md) фактическими результатами. Он выводит 10 самых частых слов
в консоль и записывает их частоты в тот же отчёт. Случайные данные имеют фиксированные seed;
корпус текста генерируется самим бенчмарком, внешний файл не нужен.

## API и принятые соглашения

Исходники: [основной код](./src/main/java/ru/bmstu/lab2), [тесты](./src/test/java/ru/bmstu/lab2).

- `PriorityQueueCustom<T>`: `add`, `poll`, `peek`, `size`, `isEmpty`.
  Пустые `poll` и `peek` бросают `NoSuchElementException`; null запрещён.
  Компаратор null означает естественный порядок. Конструкторы принимают компаратор,
  массив или массив с компаратором. Массив копируется, порядок входа не меняется.
- `HashMapCustom<K,V>`: `put`, `get`, `containsKey`, `remove`, `size`, `capacity`.
  По умолчанию — линейное пробирование; `new HashMapCustom<>(HashMapCustom.Probing.QUADRATIC)`
  включает квадратичное. Null-ключи запрещены, null-значения разрешены;
  `containsKey` отличает отсутствующий ключ от ключа со значением null.
  Ключи должны иметь согласованные `equals/hashCode` и не меняться после вставки.
- `DataAlgorithms.topK(List<T>, int)`: возвращает **k наибольших по убыванию**,
  включая повторы. Разрешены `0 <= k <= n`, при k=0 вход не обходится.
  Иначе null-элементы запрещены. Вход не меняется, поддерживаются и связные списки.
- `DataAlgorithms.countWords(String)`: возвращает `Map<String,Integer>`.
  Регистр нормализуется с `Locale.ROOT`; слово состоит из Unicode-букв, комбинируемых
  знаков и цифр. Пунктуация, дефисы, апострофы и пробелы разделяют слова;
  например, `мир-мир!` даёт `мир=2`. Пустой текст даёт пустую карту; null запрещён.
- `DataAlgorithms.distinct(List<T>)`: сохраняет порядок первого вхождения,
  допускает один null в результате, не меняет вход. Null вместо списка запрещён.

Результаты прикладных методов неизменяемые. Для выполнения требуемых сигнатур `List` и `Map`
используются собственные `ResultList`, `ResultSet` и `WordCounts`: массивы, собственные
итераторы и адаптер над `HashMapCustom`. Готовые коллекции, включая `AbstractList/AbstractMap`,
в основном коде не используются. Разрешённые интерфейсы `List/Map/Set/Collection`,
`Comparator`, `Objects`, `Arrays` и регулярные выражения не реализуют хранение структур за нас.
Библиотечные `PriorityQueue`, `HashMap`, `LinkedHashSet`, `ArrayList` находятся только в тестах/замерах.

## Детали хеш-таблицы

Начальный индекс: `Math.abs((long) key.hashCode()) % capacity` — формула из условия
с устранением переполнения `Math.abs(Integer.MIN_VALUE)`. Ёмкость начинается с 16
и удваивается при превышении 0.75 живых элементов; после расширения все пары перехешируются.
Удаление помечает ключ маркером `DELETED` и освобождает ссылку на значение.
Вставка проходит за первым маркером, чтобы найти уже существующий ключ и не создать дубликат.

Для 2B выбраны `c1=1`, `c2=2`, ёмкость — степень двойки. Формула `base + i + 2*i*i`
обходит каждую ячейку; доказательство — в [расчёте асимптотики](./asymptotics.md).
Любой поиск ограничен числом `capacity` проб. Если живые элементы вместе с маркерами
при новой вставке превысят 7/8 ёмкости, выполняется очистка маркеров перехешированием
при той же ёмкости. Запас между 3/4 и 7/8 предотвращает очистку после каждого удаления/вставки.
`averageGetProbes` и `resetProbeStatistics` обеспечивают эксперимент 2B;
подсчитываются успешные и неуспешные `get`, но не `put/containsKey/remove`.
