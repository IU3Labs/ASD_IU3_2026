# Лабораторная работа №2

Захватов Антон, ИУ3-33Б.
Задачи: 1A, 1B, 1D, 2A, 2B, 3A, 3B, 3C — 18 баллов.

## Реализация

| Задачи | Пакет | Что реализовано |
|---|---|---|
| 1A, 1B, 1D | task_1a_1b_1d | PriorityQueueCustom: динамический массив, siftUp, siftDown, Comparator, heapify |
| 2A, 2B | task_2a_2b | HashMapCustom: линейное и квадратичное пробирование, DELETED, расширение |
| 3A | task_3a | TopK.topK: k наибольших через собственную min-heap |
| 3B | task_3b | WordCounter.countWords: частота слов через собственную таблицу |
| 3C | task_3c | DistinctElements.distinct: уникальные элементы в порядке появления |

1B и 1D расширяют очередь из 1A, поэтому код кучи не дублируется.
В 2A и 2B различается последовательность пробирования, остальной код таблицы общий.
Пакет result содержит только собственные результаты List/Set: готовые коллекции
в основном коде запрещены. WordCounts в пакете 3B возвращает результат через интерфейс Map.
Стандартные PriorityQueue, HashMap и LinkedHashSet используются только в тестах и бенчмарках.

Очередь хранится в массиве, который удваивается при заполнении. После добавления
элемент поднимается, после извлечения корня — опускается. Компаратор меняет порядок
кучи. Конструктор массива копирует вход и просеивает внутренние узлы снизу вверх.

В таблице удалённые ячейки помечаются DELETED, чтобы не прерывать цепочку поиска.
При вставке поиск продолжается за маркером, иначе можно создать дубликат ключа.
При загрузке выше 0.75 ёмкость удваивается. Для квадратичного пробирования выбраны
c1=1, c2=2 и ёмкости 2^p; каждый поиск ограничен C шагами. Формула abs(hashCode)
вычисляется через long, чтобы обработать Integer.MIN_VALUE.

Top-K хранит в куче не более k кандидатов и заменяет минимум на больший элемент.
Подсчёт слов использует Locale.ROOT; пунктуация разделяет слова, буквы и цифры
входят в слово. Distinct запоминает элементы в своей таблице и добавляет в результат
только первое вхождение. Входные данные не меняются.

## Примеры проверок

| Вход или действия | Ожидаемый результат | Что проверяем |
|---|---|---|
| Очередь: 3, -1, 3, затем poll до пустоты | -1, 3, 3 | Отрицательные числа и повторы |
| Та же очередь с reverseOrder | 3, 3, -1 | Max-heap |
| poll на пустой очереди | NoSuchElementException | Граница пустоты |
| Конструктор из [3,1,2] | poll: 1,2,3; исходный массив не меняется | Heapify и копирование |
| Два ключа с одним хешем, удалить первый | Второй находится | Поиск за DELETED |
| Обновить второй ключ после удаления первого | Размер не увеличивается | Нет дубликатов |
| 13-я пара при начальной ёмкости 16 | Ёмкость 32 | Порог 0.75 |
| topK([1,9,3,9,5], 3) | [9,9,5] | Повторы в Top-K |
| countWords("ЁЖ ёж — Мир!") | ёж=2, мир=1 | Регистр и пунктуация |
| distinct([3,1,3,2,1]) | [3,1,2] | Порядок первого вхождения |

## Сборка и результаты

Из корня репозитория: `mvn -pl 33-Zakhvatov clean verify` на JDK 21+.
Команда запускает JUnit 5 и Checkstyle, проверяет покрытие JaCoCo не ниже 80%.
Тесты находятся в src/test/java, в тех же пакетах, что проверяемый код.
Для сборки всего репозитория нужен JDK 25+ из-за настроек родительского проекта.

Замеры: `mvn -pl 33-Zakhvatov -Pbenchmarks test`.
Профиль запускает отдельный тест измерений без агента покрытия и записывает
[benchmarks.md](./benchmarks.md). Там приведены все размеры из условия,
сравнения со стандартной библиотекой и 10 самых частых слов корпуса около 1 МиБ.
Расчёт времени и памяти находится в [asymptotics.md](./asymptotics.md).
